# Edax・Egaroucid を土台にした設計

`deft_reversi_book` は、Edax と Egaroucid の Book 構造から長所を取り入れつつ、Deft の評価モデルと運用要件に合わせて設計している。

## 先行実装から取り入れた考え方

- **Edax**: 局面、その局面につながる登録済みの手、最良の未登録手を中心に構成する。登録済みの各手には主に着手位置と点数を持つ。（[参照した Edax の定義](https://github.com/abulmo/edax-reversi/blob/713a434f13b3d15fb69c61b9ba3641aed82c496c/src/book.c#L59-L117)）
- **Egaroucid**: 手を進めた先の局面を検索してその手の値を求め、登録済みの手の一覧を省略する。局面の評価・計算レベル・最良の未登録手などを持つ。（[公式の構造説明](https://www.egaroucid.nyanyan.dev/ja/usage/book/)）

Deft では、登録を外しても局面と探索結果を保持する必要があるため、登録状態（`Edge.registered`）を明示的に持つ。子の座標を繰り返し正規化しないための補助データも残す。一方、詳細な探索記録は各候補に複製せず、共有一覧に 1 件だけ置く。

## Deft で追加している情報

レベル番号だけで品質を表すのではなく、実際の中盤深さ・終盤方式・選択率、点と上下限、対象手集合、モデル等を識別する情報（`AnalysisIdentity`）を追加している。探索記録を共有することで、集合最大値・最良手・他の手の上限に同じ探索条件を重複して持たせない。

登録先の子の値を親へ戻す方式は一つに統一している。現在の品質は説明できるようにする一方、過去の計算入力の全経路は保存しない。完全読み切りで分かった最終石差の情報は、手動値や登録解除とは独立して保持する。

## 生成と資源配分

生成時は未登録手の集合から最良手を探し、損失条件内の手を登録する。登録後は有望な進行を一定数（`line_plies`）続けて伸ばし、別の候補にも計算を配分する。探索が返す読み筋（PV）は次の手を優先するヒントとして使い、探索済みの評価の代わりにはしない。

独立した複数局面の同時探索と、1 局面の内部並列は仕事量に応じて使い分ける。スレッド数と主な探索表（TT）の容量を分配し、登録と値の公開は順番に行う。探索中に局面状態が更新された場合、古い状態に対する探索結果は破棄してやり直す。

Edax の誤差条件や Egaroucid のレベル番号を、Deft の数値へそのまま対応させることはしない。Deft 独自の「1 手の損失」「累積損失」「未登録手追加の損失」という 3 つの条件を維持する。

## 理解の負担を抑える設計

正しさ・メモリ量・速度に加え、通常の編集や生成を理解するために覚えるべき独自の分類を減らすことを設計基準にしている。評価を `Evaluation` 一つから読み、値の採用規則（`MoveValues::choose`）と情報の取得を分け、旧形式の都合を通常の局面データから切り離している。具体的な整理内容と残る複雑さは [保守性の見直し](maintainability.md) にまとめている。
