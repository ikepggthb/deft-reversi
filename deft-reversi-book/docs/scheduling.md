# 探索の優先順位と並列化

限られた時間やノード予算の中でどこから探索するかは、スケジューラの方針（`SchedulePolicy`）で決める。

## 選択と既定値

Rust API の `GenerationConfig.schedule`、または CLI の `--schedule breadth|promising`（旧表記の `frontier` も受理）で選ぶ。

- **`Breadth`（既定）**: 開始局面からの距離と解析段階の順で探索する。
- **`Promising`**: 新規探索と深掘りの配分の中で、有力な進行や不確かな末端を優先する。

```sh
target/release/deft-reversi-cli book extend --model MODEL --work openings.dbook-work \
  --levels 4,8,12 --max-plies 24 --schedule promising --seconds 60
```

優先順位はあくまで探索順を決めるヒューリスティックであり、統計的な誤差確率や棋力の証明ではない。条件を満たす有限のジョブ集合をすべて処理し終えれば、最終的な探索目標と展開条件は `Breadth` と同じになる。ただし途中の予算で打ち切った場合は、出来上がるグラフが異なり得る。

## 優先順位の定義

新規探索（未調査の局面）と深掘り（段階を上げる探索）のどちらを選ぶかは、`new_job_weight` と `deepen_job_weight` の比率で先に決める。既定値は `3:1` で、片方に仕事がなければ他方へ回す。それぞれのクラス内では次の辞書順で優先度を決める。

1. 流入した手の局所損失と、局面内の最善未登録候補の損失の和が小さい。
2. 直接探索値と完成した子からの伝播値の最大差が大きい。
3. 未登録候補の最小深さが小さい。
4. 未登録候補の最小選択率が低い。
5. 同順位なら、深掘りは「段階・距離・正規化 `Context` 順」、新規は「距離・`Context` 順」。

未評価の末端を持つ局面の「末端損失・深さ・選択率」は優先上 0 として扱う。未登録候補がない局面の末端損失は 128 とする。流入損失は保存された登録親の文脈のうち最小のものを使う（開始局面と `leaves` モードでは 0、流入親の点評価がまだそろっていなければ優先上 0）。

流入損失は局所的な優先基準であり、経路全体の累積損失を置き換えるものではない。実行前には現在の到達資格を別途判定する。古い優先スコアだけを根拠に許容外の経路を解析したり、新しい分岐を登録したりはしない。

16 ジョブに 1 回は、そのクラスの通常の「距離・段階順」で仕事を取り出す。これにより低順位の仕事にも進行の機会を残す。途中停止したジョブを再試行すると `iteration` カウンタは再び進むため、中断を挟んだ実行と中断なしの実行で途中順序まで完全に一致する保証はない。

## 索引・保存・計算費用

通常キューを元の仕事一覧とし、`Context` 別の仕事索引と優先順位別の `BTreeSet` を派生キャッシュ（`PriorityIndex`）として持つ。通常の挿入・取り出しは `O(log Q)`、初回は `Q` 件から索引を構築する。評価が変更された後は、その `Context` と登録された子の優先順位を更新する。優先値の計算は局面内の候補と登録された親候補だけを調べ、仕事ごとに全キューを走査はしない。

索引の見積もり容量はメモリ制限に含める。ただし索引自体は `.dbook-work` に保存せず、読み込み後の最初の取り出し時に再構築する。未処理キュー、`iteration`、`schedule` 設定はファイルに保存する。なお、`resume` では `schedule` を変更できない（変更には `extend` / `reanalyze` / `leaves` を使う）。

## 最良進行の連続伸長としきい値探索

生成処理では、最良の未展開手と残り候補の上限を使う方式を採用している。最良手を新しく登録できたらその子局面の解析を優先し、読み筋（PV）の次の手を正規化座標へ変換して `Engine` の手順付けヒントへ渡す。ヒントはあくまで順序付け用であり、スコアの証拠には使わない。損失条件は各登録の直前に現在値で確認する。

`--line-plies 8`（既定）は連続して最良進行を伸ばす手数の予算で、`0` を指定すると無効になる。未開拓の中盤では損失 0 の最善手を先に登録し、残り候補の再評価より子局面を優先する。パスはこの連続伸長の手数予算を消費しない。中盤の主線が止まるか予算を使い切ったら、再評価を含む通常キューへ戻る。中断した主線の残量とヒントは `.dbook-work` へ保存する。

すでに点評価がある中盤局面では、全経路のうち最も余裕がある残り損失をもとに、未登録手が許容される最低評価を計算する。未評価の手集合をこのしきい値で調べ、下回ったら上限を保存し、通過したら通常どおり点評価を求める。親の値や到達条件が変わった場合は、保存した上限がまだ枝を除外できるかを確認する。適合する置換表（TT）エントリがあれば初期反復を省くが、要求された最後の反復は必ず実行する。

## 並列探索の配分

`--jobs 0`（既定）を指定すると、総スレッド数（`--threads`）と TT 設定の範囲で 1 ジョブあたり約 3 スレッドを目安に自動配分する（例: 18 スレッドなら最大 6 ジョブ）。`--jobs 1` なら外側は逐次実行し、1 局面の内部探索に全スレッドを使う。複数ジョブ間では総ノード予算を分配する。

短いバッチでは空いた `Engine` の補助スレッドを解放し、TT は保持する。共有する `BookEditor` への結果反映は順番に行い、古い状態に対する探索結果は破棄して再キューする。バッチ内の別局面の反映によって親へ値が伝播するため、予算途中で打ち切ったときのグラフやノード数はスレッド数や実行順で変わり得る。
