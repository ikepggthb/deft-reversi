# Book の検証

保守性を見直した構成（比較元のリビジョン `69051e8` からの改修後）で行った機能テストと実データでの測定結果をまとめる。

## 機能テストの結果

全ワークスペース・全 feature の release テストは 205 件成功した（既存の負荷試験 1 件は実行対象外）。`deft_reversi_book` 単体（CLI 連携含む）は 109 件成功し、Clippy（全 target・全 feature）、非公開項目を含む Rustdoc 生成（警告エラー化）、フォーマット検査もすべて通っている。

| 確認対象 | 確認内容と結果 |
|---|---|
| 評価の対象範囲 | 一部の手の最大値や特定の手の評価を子局面全体の値へ読み替えないことを、現行 `Evaluation` と旧形式検査の双方で確認 |
| 推定と確定の区別 | 中盤 Full や選択的終盤から最終石差の確定情報を作らないこと、手動指定とは独立した最終石差の情報を維持することを確認 |
| 編集・登録・解除 | 小終盤での独立した区間計算、96 段階の操作列、矛盾時のロールバック、子からの反映を確認 |
| 中断と再開 | 探索中の途中値を完了扱いにせず仕事を戻すこと、旧途中結果は読み込み中だけで取り込むことを確認 |
| 旧形式の読み込み | 固定の v6/v2・v7/v3 データを読み込み可能。手動値と旧探索を混ぜた v3 の品質は旧情報検査後に再集計 |
| 現行 v8/v4 の互換性 | 改修前バイナリで作った固定入力を読み込み、再保存した全バイトが一致することを確認 |
| 実 Book での全件照合 | 26,527 局面・289,881 候補・26,851 登録手を旧形式と既存 v8 の両方から全件照合。再保存後の全バイト一致と元ファイルの SHA-256 不変を確認 |
| 実モデルでの生成・対局 | `v3-pen`・18 スレッドで新規生成、保存再開、設定変更、既存 Book への追加、合法な対局手の選択を確認 |
| 固定探索の再現性 | 6 局面・67 候補の既知の値・品質・登録が 3 回とも改修前と一致 |
| 対局時のメモリ確保 | 通常の着手選択で問い合わせごとのヒープ確保 0 回を維持（[book_alloc.rs](../tests/book_alloc.rs)） |

## 同じ実 Book でのメモリ・速度測定

同じ v8/v4 形式の実 Book を使い、`69051e8` から再ビルドした測定用プログラムと改修後を交互に測定した（3 回の中央値）。

| 項目 | `69051e8` | 改修後 |
|---|---:|---:|
| 生成用データ見積もり（MiB） | 90.9 | 89.8 |
| 対局用データ見積もり（MiB） | 8.6 | 8.6 |
| play 読み込み（ms） | 41.5 | 44.0 |
| work 読み込み（ms） | 154.7 | 148.0 |
| play 保存（ms） | 17.5 | 17.8 |
| 局面参照＋候補の点数走査（ns） | 33.0 | 33.3 |

生成用の見積もりは局面・評価・仕事一覧などの保持分であり、`Engine`・モデル・置換表を含む総使用量ではない。参照速度は `moves()` の点数走査であり、詳しい記録の展開や手の選択全体の費用ではない。メモリ見積もりの増加はなく、読み込み・通常参照に 10% を超える悪化はなかった。

また、固定 6 局面・深さ 8 Full・18 スレッド・TT 128 MiB の完了探索では、生成処理の中央値が 0.049 秒だった（短い標本であるため長時間生成の倍率へ一般化はしない）。

## 再現と未検証の範囲

機能テストは `tests/` と各モジュール内にあり、既存形式の固定入力は `tests/fixtures/` に置いている。実 Book の監査・測定・コマンド・ハッシュは `local/work/book-maintainability-review/RESULTS.md` と同ディレクトリの JSON・ログに保存している（[以前の検証記録](https://github.com/ikepggthb/deft-reversi/blob/69051e880cbf5a8dc639d7bc8e3a8a74268bcc72/docs/book-v2/validation.md)）。

次の項目はこの測定では未検証である。

- 長時間・大規模な生成における計算量とメモリ推移
- 対局における棋力（Elo）の向上
- 外部入力の申告を再探索して真偽を確かめること
- スマートフォン実機での表示や動作

なお、`Engine` の再帰探索・レベル表・探索 revision は変更していない。将来の「中盤レベル＝同じ探索元での要求深さ」への切り替えは未実装である。
