# 子の値を親へ反映する

登録された子局面の値を親局面へ戻す方式は一つに統一されている。登録先の子局面に利用できる値があれば、それを親から見た値へ変換して採用する。以前その手を直接探索した深さが大きいことを理由に更新を止めることはない。

## どの値を使うか（採用の優先順）

候補手の値を選ぶ処理（`MoveValues::choose`）は、次の優先順で採用する値を決める。

1. **手動値**: 現在のモデル識別値に対応する手動値があれば、手動指定として採用する。ただし完全読み切りで得た別の確定情報は消さない。
2. **最終石差の確定情報**: 手動指定がなければ、保持している最終石差の確定情報を未確定の推定で置き換えない。
3. **登録された子の値**: 登録された手で、子局面に利用できる値があれば、子から変換した値を使う。
4. **直接探索の値**: 子が未評価なら、その手を直接調べた利用可能な結果を使う（あわせて子を解析対象にする）。
5. **未登録手の値・集合探索**: 未登録手では、個別に得た結果と、残り候補をまとめて調べた集合探索の結果を使う。最良手以外には上限だけを与える。

点確定や最終石差の上下限は、採用する推定とは別にも保持する。上限しか分からない手を、その点数が得られる手として選ぶことはない。矛盾する確定情報はエラーとして拒否する。

子からの値を採用した場合、探索条件（品質）の説明もその子の値のものへ更新する。以前の深い直接探索の条件を、現在使う値の品質として表示することはない。詳細は [評価の意味](value-model.md) を参照。

## 変更時の再計算手順

値の追加、手の登録、登録解除、手動値の設定・解除、探索結果の取り込みはすべて共通の更新手順を通る。変更した局面から影響するすべての親局面へ再計算を進めるため、複数の親が合流する局面も正しく更新される。

- 更新に成功したら、必要な仕事を探索待ちへ戻す。
- 確定情報の矛盾などで失敗したら、値・登録状態・更新世代と関連する計算結果を編集前へ戻す。
- 並列探索中に局面が更新された場合、古い世代に対する探索結果は公開せず、仕事をやり直す。

登録解除（`unregister_move`）は、その枝を進行として使わなくする操作である。過去の確定情報や、ほかの親から参照される局面を自動で消す操作ではない。

## 保存結果から作り直す

```sh
target/release/deft-reversi-cli book repair --work openings.dbook-work --book openings.dbook
```

`repair` コマンドは探索を行わず、現在保存されている登録状態と探索記録から値と補助データを再計算する。何度繰り返しても結果は変わらない。ただし、破損した入力を無条件に修復して通す機能ではない。

以前の `--propagation quality|book` オプションと Rust API の `set_propagation_policy` は廃止した。CLI で旧引数を指定すると、方式を統一したことを説明して拒否する。古いファイルは読み込んだうえで現在の方式で採用値を計算し直す。変更された件数は [互換性](compatibility.md) に記載の変換報告で確認できる。
