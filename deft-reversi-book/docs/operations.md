# 保存・運用・障害対応

## 予算の指定と使い分け

ここでいう「Book の保持メモリ」は、生成・更新・再開のために RAM 上に持つデータの見積もり量である。RSS はプロセスが実際に使用する物理メモリの測定値、TT は探索で得た局面結果を再利用する置換表を指す。これらはすべて別の量として管理する。

| 設定 | 制限するもの | 注意点 |
|---|---|---|
| `--seconds` | 1 回の `generate` で使う探索・処理時間 | モデル読み込みや最終保存を含むプロセス全体の期限ではない |
| `--nodes` | 集合探索の実ノード数の合計 | バッチ内要求へ残量を分配し、停止までの実績を加算する |
| `--memory-mib` | Book の局面・記録・仕事一覧などの保持メモリ見積もり | プログラム全体の最大使用量の上限ではない |
| `--tt-mib` | 探索中に使う置換表（TT）の公称容量 | `BookEditor` のメモリ制限とは別 |
| `--threads` | 内側・外側を合わせた総探索スレッド数 | 独立ジョブ数に合わせて自動分配される |

実行には時間またはノード予算など、少なくとも一つの停止条件を設定するのが基本である（`leaves` では時間またはノード予算が必須）。限られた機器ではノード・時間と管理メモリの双方を指定する。読み込み側の上限も生成側と合わせ、`Engine`、モデル、スナップショット、I/O バッファの分を別に確保する。

```sh
target/release/deft-reversi-cli book resume --model MODEL --work openings.dbook-work \
  --nodes 100000 --seconds 60 --tt-mib 128 --threads 2 \
  --read-mib 512 --read-positions 2000000 --read-candidates 32000000
```

`--read-mib` はファイル長と読み込み時の割り当て制限にも使う。`--memory-mib` を上げただけでは大きい `.dbook-work` を読めるようにならない。`resume` で管理メモリ設定を変更することはできないため、変更したいときは `extend` を使う。

## チェックポイントと停止

バッチ探索の終了境界と正常停止時にコールバックで保存する。`--checkpoint-seconds` の既定値は 60 秒である。1 回の候補探索自体が長ければ保存間隔を超えることがあるため、厳しい復旧時間が必要なら探索の時間・ノード予算も小さく分割し、`resume` を繰り返す。

Ctrl-C を押すと共有の `StopHandle` が立ち、実行中の探索が停止してから保存する。2 回目の強制終了や `kill -9` では最後の完了チェックポイントまで戻る。コールバックやファイル保存が失敗した場合は CLI の終了コードと標準エラーを確認し、エラーを無視して次の育成を上書き実行しない。

保存時は同じディレクトリに排他的な一時ファイルを作って書き込み、`flush`・`sync`・`rename` の順で置き換える（Unix では親ディレクトリも `sync` する）。`.dbook-work` と `.dbook` は別々に原子的更新を行うため、`.dbook` の更新に失敗したら保存済みの `.dbook-work` を `verify` して `export` し直す。2 ファイルを同時に更新するトランザクションではない。

## 単一ライター運用と配布

同じ `.dbook-work` を複数プロセスで同時に編集してはいけない。ファイルロックでジョブを調停する実装ではないため、それぞれが別の状態から最終保存すると後勝ちで上書きされる。ジョブスケジューラや運用ルールで単一ライターを守る。複数機器で育成する場合は別の出力先を使う（結合コマンドはこの版にはない）。

対局プロセスには `verify` 済みの `.dbook` だけを配布し、書き換え中のワークスペースを共有しない。対局側では `Arc<Book>` を複数対局で共有し、更新時は新しいスナップショットを読み込んで切り替える。作業用 `.dbook-work` とモデルのバックアップは対局用 `.dbook` とは別に残す。

## モデル・探索更新時の手順

評価モデルや校正、探索 feature を変更した場合は、元ファイルをコピーしたうえで `reanalyze` を実行する。

```sh
# 新しい名前へコピーし、元ファイルを残す。
cp openings.dbook-work next.dbook-work
target/release/deft-reversi-cli book verify --work next.dbook-work
# まず再目標化（retarget）だけを保存して構造を確認する。
target/release/deft-reversi-cli book reanalyze --model NEW_MODEL --work next.dbook-work --nodes 0
target/release/deft-reversi-cli book verify --work next.dbook-work
# 保存設定で再解析を続行する。
target/release/deft-reversi-cli book resume --model NEW_MODEL --work next.dbook-work --seconds 60
```

`reanalyze` は互換性のない推定と古い仕事を無効化し、局面、登録リンク、手動の原記録、ルールやモデルに依存しない確定済みの直接結果を保持する。古いモデルの手動値は有効値には使わない。`--nodes 0` の直後は推定が空になることがあるため、その段階の Book を品質確認なしに配布しない。

詳細は [互換性](compatibility.md) を参照。バイナリの `--version` と `inspect` のモデル識別値を運用記録へ残しておくと切り分けしやすい。

## エラーへの対応

| 症状 | 確認と対応 |
|---|---|
| モデル識別値（identity）不一致 | モデル・校正・feature・探索 revision を照合。`resume` で強行せず、コピーに `reanalyze` を使う |
| ProbCut 校正不足 | モデルを確認する。適切な校正を用意するか、目的に合う Full 探索を明示する |
| `resume` が設定変更を拒否 | 同じ仕事の続行なら余計な設定を外す。条件を変えるなら `extend` を使う |
| `MemoryLimit` | ワークスペースを保存し、`Engine`・`BookEditor`・読み込み制限を別々に見直す。RSS と見積もりを混同しない |
| `NodeLimit` / `TimeLimit` | 正常な中断。完成結果と未処理キューが残っているため、`resume` で続行できる |
| チェックサム・形式・合法性エラー | バックアップから復旧する。`repair` は破損を無条件で通す機能ではない |
| 対局で Book が使われない | 登録手の有無、モデル識別値、`UsePolicy` の深さ・選択率、未登録有力手との損失差を確認する |

エラーが繰り返される場合は、元の `.dbook-work` を残したまま、最小のコピーとモデルハッシュ、`--version`、`inspect` 出力、実行コマンドと標準エラーを保存する。`record_imported` 等で誤った確定情報を入力したデータは、`verify` だけでは再証明できない。

## 大規模化の判断と制約

大規模に育てる場合は、`inspect` の品質分布、末端数、管理メモリ見積もりとプロセス RSS、保存・読み込み時間、1 段階あたりのノード数を記録する。優先順位索引は増分更新するが、到達資格の判定には祖先グラフを調べる。転置が多い大きなグラフでの費用は別途測定する。

不要な枝の削減・部分抽出・複数 Book の結合は後続機能であり、この版には含まれない。外側の局面並列は `--jobs` で制御する。手動の `unregister_move` はリンクを外す API であり、到達しない局面を一括削除するものではない。
