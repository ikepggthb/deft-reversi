# 評価値と探索条件の意味

`.dbook-work` と `.dbook` で評価の意味は共通している。現在の評価は `Evaluation` 型（借用時は `EvaluationRef`）で読み取り、点数・探索条件・出所を区別して扱う。

## 点数と上下限

`result()` が返す `Score` には次の 2 種類がある。

| 種類 | 意味 |
|---|---|
| `Estimate { score, bound }` | 探索条件内の推定。`bound` は `Point`（点評価）、`Lower`（下限）、`Upper`（上限） |
| `Final(ScoreInterval)` | 完全読み切りや終局ルールで分かった、最終石差の範囲 |

たとえば「+4 の点評価（`Point`）」と「+4 以下という上限（`Upper`）」は意味が異なる。一点に決まった値だけを取り出したいときは `point_value()` を使う。`Final` も片側の上下限だけの場合があり、下限と上限が同じ値になったときだけ `is_solved()` が `true` になる。確定したかどうかの判定を別の編集可能なフラグとして保存はしない。

選択的な終盤探索（選択率 85%〜99% など）の結果はあくまで推定（`Estimate`）である。中盤 Full 探索の深さが空きマス数と同じだけでも、最終石差の確定（`Final`）へは変えない。また、選択率 95% を「Book 全体が 95% の確率で正しい」という意味では扱わない。

子局面から親局面へ値を戻すときは符号を反転し、区間 `[L, U]` は `[-U, -L]` になる。石を置く手では親からの深さに 1 を加え、パスでは深さを加えない。元の探索記録に残された実際に完了した深さは書き換えない。

## 実際の探索条件

`conditions()` を使うと、採用する値に含まれる中盤・終盤・方式不明の旧入力の条件を読める。子から計算した値に中盤と終盤の探索が混ざる場合も、それぞれの条件を残す。

- **中盤**: 最低の到達深さと最低の選択率。
- **終盤**: 終盤探索であることと最低の選択率。
- **旧入力**: 記録された深さと選択率（失われた探索方式は推測しない）。
- **手動値を含む場合**: 手動値を含むという事実（手動の表示深さで実際の探索条件を下げたりはしない）。

1 回の探索の詳細は `CompletedSearch` に保存する。ここには要求した条件、実行予定の条件、実際に完了した条件、探索元の盤面、対象手集合、最良手、結果、モデル識別値・実行との対応、ノード数と所要時間を持つ。

たとえば深さ 20 を要求して 16 までで停止したなら、完了結果は深さ 16 になる。レベル 19 が深さ 16・選択率 95% へ解決された場合も、要求した「レベル 19」と実際に完了した「深さ 16」を別々に残す。

## 値の出所と対象範囲

`source()` で値の出所を直接読める。直接探索なら探索記録（`CompletedSearch`）、子から求めた値なら子の盤面、局面や特定の手から計算した値ならその対象と探索条件が入っている。過去の入力記録を延々とたどる連鎖は持たない。

複数の手をまとめて探索した「集合探索」の最大値と、そこから得られる個々の手の値は区別する。候補 A・B・C だけを探索した結果を、ほかの合法手を含む局面全体の値にはしない。最良手には点評価を与え、ほかの対象手には上限だけを与える。

局面全体の点評価は、最良の点評価と、それを超えないほかの手の値または上限がすべてそろったときに求められる。その場合でも全候補に点評価があるとは限らない。未評価の手を 0 点として扱うことはない。

## 対局に使う条件

対局時の利用条件（`UsePolicy`）の既定値は、中盤が深さ 12・選択率 95% 以上、選択的終盤が選択率 85% 以上である。子から計算した値を使うときは、その元の探索条件を確認する。手動値と方式不明の旧推定は既定では使わない。

- `allow_calculated`: 子や候補から計算した値の使用を許可する（既定 `true`）。
- `allow_imported`: 方式不明の旧推定の使用を許可する（既定 `false`）。
- `allow_manual`: 手動値、または手動値を含めて計算した値の使用を許可する（既定 `false`）。

許可した場合も、それぞれの実際の探索条件を確認する。中盤と終盤を一つの最低深さだけでまとめて判定はしない。借用した評価には `UsePolicy::check_ref`、独立した `Evaluation` には `UsePolicy::check` を使って同じ条件を確認できる。上限しか分からない手を、その点数が得られる着手として選ぶことはない。

## 読み込み検査の限界

読み込み時には盤面・手・対象範囲・探索条件・上下限の整合性を検査し、保存された情報から現在値を再計算する。ただし、探索そのものを再実行して外部入力の申告の真偽まで確かめる機能ではない。
