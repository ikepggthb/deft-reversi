# 保存場所と API

`deft_reversi_book` は、用途に応じて次の 3 つの型に分かれている。

- **`BookEditor`**: Book の作成・編集・自動生成の途中状態を扱う作業用ワークスペース（`.dbook-work`）。
- **`Book`**: 対局時に高速に読み取るためのコンパクトなスナップショット（`.dbook`）。作成後に元の `BookEditor` を変更しても、すでに取り出した `Book` は変わらない。
- **`BookPlayer`**: `Book` を参照し、設定された品質条件を満たす登録手を選ぶプレイヤー。

## 評価は一つの型で読む

`Evaluation`（または借用版の `EvaluationRef`）が点数・探索条件・出所・モデル識別値を持つ。点数や確定フラグを簡易表示用の別構造へ重ねて保存はしない。

- `result()`: 推定の点・上下限（`Score::Estimate`）、または最終石差の範囲（`Score::Final`）。
- `conditions()`: 中盤の深さ・選択率、終盤の選択率など、採用する値の探索条件。
- `source()`: 直接探索した結果か、子から計算した値か、手動値かなどの出所。

1 回の探索の要求・予定・完了条件は `CompletedSearch` に残す。中盤と終盤、推定と確定を一つの深さ番号へ潰してはいけない。詳細は [評価の意味](value-model.md) を参照。

## 局面と手に持つ情報

| 保存場所 | 情報と用途 |
|---|---|
| 局面（Node） | 盤面、合法手と登録状態、現在の局面値、独立した最終石差の情報、集合探索の記録 |
| 手（Edge） | 着手先の局面、登録状態。個別の直接評価・手動値・最終石差の情報がある場合だけ追加領域を確保 |
| 共有する評価一覧（`ValueStore`） | 点数・出所・探索記録・モデル識別値を共有。各局面・手は 4 バイトの内部番号で参照 |
| 生成の状態（`GenerationState`） | 開始局面と色、設定、完了段階、未完の仕事 |
| モデル・実行の一覧 | モデル等の識別情報、1 回の生成の条件と停止理由 |

たとえば局面 P の候補手 A・B・C を探索して A が最良で +4 だった場合、元の探索記録は 1 件だけ保存する。そのうえで A には +4 の点評価を、B・C には「+4 以下」という上限を与える。B・C が +4 の点評価を持つわけではない。

共有する評価の内部番号は外部へ公開しない。記録の共有はメモリ配置の問題として `values.rs` へ分けている。内容を探す補助索引はメモリ見積もりへ含め、対局用スナップショットでは解放する。過去の計算入力の全経路は保持しない。

## 変更する主な API

| API | 用途 |
|---|---|
| `record_search` | 正規化した盤面で得た探索結果を、対象手集合ごと取り込む |
| `record_candidate` | 特定の手について得た検査済みの評価を追加する |
| `set_manual` / `record_manual` | 手動値を設定する |
| `record_imported` | 探索方法が残っていない旧入力を明示して取り込む（入力型は `legacy` モジュール内） |
| `register_move` / `unregister_move` | その親から進む手として登録・解除する（局面の存在とは別） |
| `move_values` | 直接評価・子の値・手動値・採用値を一度に確認する診断用の入口 |
| `repair` | 探索せず、登録関係と保存済み記録から現在値と補助データを再構築する |
| `retarget` | モデル等が変わった際、互換性のない推定を無効にする |

採用する値の判定は `MoveValues::choose`、親への更新は `refresh_from` で確認できる。手動値とは別に最終石差の情報を残し、矛盾する変更は巻き戻す。詳細は [子からの更新](propagation.md) を参照。

## 生成と対局

生成では `GenerationConfig.analysis` に `AnalysisSchedule::Levels(Vec<u8>)` または `AnalysisSchedule::Stages(Vec<Stage>)` の一方だけを設定する。`configure_generation_roots` で開始局面と色を渡し、`generate` へ `Engine` と時間・ノード・追加局面の予算を渡す。定期保存する場合は `generate_with_checkpoint` のコールバック内で保存する。

対局では `Book::probe` から `BookEntry::moves()` を呼び、入力盤面の座標へ戻した手と借用した評価（`EvaluationRef`）を得る。点数を読むだけで探索記録全体をコピーすることはない。詳細を独立して持ちたい場合は `to_owned()` を使う。`candidates()` は独立した評価を列挙する診断用の入口だが、評価の意味は同じである。

`BookEntry::value()` は採用する局面値、`final_score()` は手動指定とは独立した最終石差の情報を返す。使える登録手がなければ `BookPlayer` は理由（`BookMiss`）を返し、通常探索は呼び出し元で行う。`Engine` の再帰探索自体は内部で Book を読まない。

コードを追う順序とテストは [ソースの読み方](source-review.md)、API の移行は [互換性](compatibility.md) にまとめている。
