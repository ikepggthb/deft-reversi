# 展開の損失制御

Book を際限なく広げると局面数が爆発するため、最善手との評価差（損失）によって登録・展開する分岐を絞り込む。

## 3 つの独立した制限

点評価と残り候補の上限から局面値 `best` を再構成し、各候補の局所損失を `max(0, best - candidate)` として計算する。符号はその局面の手番視点でそろえる。

| 制限 | Rust API | 対象 | 既定値 |
|---|---|---|---|
| 1 手の損失 | `expansion_loss`, `black_loss`, `white_loss` | 新規リンクと既存経路の双方 | 共通 `2`、色別指定なし |
| 累積損失 | `cumulative_loss: Option<u16>` | 開始局面からの局所損失の和（黒白双方を含む） | `None`（制限なし） |
| 末端追加の損失 | `leaf_loss: Option<u8>` | 未登録候補を新しくリンクとして追加するとき | `None`（制限なし） |

CLI では `--loss`、`--black-loss`、`--white-loss`、`--cumulative-loss`、`--leaf-loss` で指定する。後ろ 2 つは `none` を渡すと制限を解除できる。たとえば `--loss 3 --cumulative-loss 5 --leaf-loss 2` とした場合、すでに登録済みの 3 石差のリンクはそのまま通れるが、新しく追加するリンクは 2 石差までになる。制限を厳しくしても既存のリンクを自動で消すことはしない。

現在の生成処理では、最良の未展開手の点評価を末端評価として使い、ほかの候補を上限で覆う。上限しか分からない手は登録せず、許容範囲内であれば次の最良手を探索して点評価を得る。未登録候補だけを独立して再計算したい場合は [leaves モード](diagnostics.md)、探索順序を変えたい場合は [探索の優先順](scheduling.md) を使う。

## 経路と転置

異なる手順から同じ局面へ合流（転置）することがある。このため、盤面と絶対手番色の組（`Context`）ごとに「`(開始局面からの着手数, 累積損失)` の組」のうち、ほかより劣っていないもの（パレート最適な組）だけを保持する。

たとえば、同じ局面に「距離 2・損失 3」の経路と「距離 4・損失 0」の経路で到達した場合、どちらも別の強みがあるため両方残す。距離の上限と損失の上限をそれぞれ別の経路で満たしても、それらを合成して架空の「距離 2・損失 0」を作ることはない。同じ距離では最小の損失だけを残すため、各 `Context` で保持する組は最大 61 個（距離 0〜60）に収まる。

開始局面（root）に到達したときは距離 0・累積損失 0 にリセットする。複数の開始局面のどれかから条件を満たせば処理できる。パスは手番色を反転させるが、着手距離（`max_plies` の対象）は加算しない。強制パスは唯一の合法手なので局所損失は 0 になる。

保存されているキューの距離はヒントであり、実行時には逆リンクから現在の評価で経路を再判定する。評価の変化で条件から外れた枝は削除せずそのまま残し、自動強化の対象から外す。のちに再び条件を満たすようになれば、既存の完了値を使って処理を再開する。展開済みのキャッシュには経路の組と候補の損失を含め、候補集合が同じでも残りの損失予算が増えた場合は子を再スケジュールする。

## メモリ見積もりとテスト

到達判定は祖先をメモ化しながら逐次処理する。同じ更新世代・到達集合であればメモを再利用し、登録や評価が変われば無効化する。`BookEditor` のメモリ見積もりには一時メモ（各 `Context` 最大 61 組）と展開キャッシュの容量も含めている。ただしこれはプロセス全体の RSS 上限ではなく、`Engine` や I/O バッファは別管理になる。

テストでは、「3 + 3 の累積損失を上限 5 で拒否し、3 + 2 への改善で再活性化する」「`leaf_loss` と既存リンクの独立性」「保存と再開の往復」「転置で短い高損失経路と長い低損失経路を両方保持する」「パスの距離 0 と色反転」を確認している。なお、制限を変更して続行したいときは `extend` を使う（`resume` は設定変更を拒否する）。
