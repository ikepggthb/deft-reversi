保存する情報とAPI

BookEditorが生成・編集する元データ、Bookがその時点の対局用データである。editorを変更しても、以前に取り出したBookは変わらない。BookPlayerはBookから利用できる手を選ぶ。

評価は一つの型で読む

Evaluationが点数・出所・モデル識別値を持つ。点数や確定フラグを簡易表示用の別構造へ重ねて保存しない。

  • result()：推定の点・上下限、または最終石差の範囲。
  • conditions()：中盤の深さ・選択率、終盤の選択率など、採用する値の探索条件。
  • source()：直接探索した結果か、子から計算した値か、手動値かなどの出所。

一回の探索の要求・予定・完了条件はCompletedSearchに残す。中盤と終盤、推定と確定を一つの深さ番号へ潰さない。評価の意味を参照。

局面と手に持つ情報

保存場所 情報と用途
局面 盤面、合法手と登録状態、現在値、独立した最終石差の情報、集合探索の記録
手 着手先の局面、登録状態。個別の直接評価・手動値・最終石差の情報がある場合だけ追加領域を確保
共有する評価一覧 点数・出所・探索記録・モデル識別値を共有。各局面・手は内部の番号で参照
生成の状態 開始局面と色、設定、完了段階、未完の仕事
モデル・実行の一覧 モデル等の説明、一回の生成の条件と停止理由

局面PのA・B・Cを探索してAが最良で+4なら、元の探索記録は一件。Aには点評価、B・Cには+4以下という上限を与える。B・Cが+4の点評価を持つわけではない。

内部番号は4バイトで、外部へ公開しない。記録の共有はメモリ配置の問題としてvalues.rsへ分けている。内容を探す補助索引はメモリ見積もりへ含め、対局用では解放する。過去の計算入力の全経路は保持しない。

変更する入口

API 用途
record_search 正規化した盤面で得た探索結果を、対象手集合ごと取り込む
record_candidate 特定の手について得た検査済みの評価を追加する
set_manual / record_manual 手動値を設定する
record_imported 探索方法が残っていない旧入力を明示して取り込む。入力型はlegacy内
register_move / unregister_move その親から進む手として登録・解除する。局面の存在とは別
move_values 直接評価・子の値・手動値・採用値を一度に確認する診断用の入口
repair 探索せず、登録関係から現在値と補助データを再構築する
retarget モデル等が変わった際、互換性のない推定を無効にする

採用する値はMoveValues::choose、親への更新はrefresh_fromで確認できる。手動値とは別に最終石差の情報を残し、矛盾する変更は巻き戻す。子からの更新を参照。

生成と対局

GenerationConfig.analysisは、Levels(Vec<u8>)かStages(Vec<Stage>)の一方だけを持つ。configure_generation_rootsで開始局面と色を渡し、generateへEngineと時間・ノード・追加局面の予算を渡す。定期保存する場合はgenerate_with_checkpointのコールバックでsaveする。

Book::probe→BookEntry::moves()は、入力盤面の座標へ戻した手と、借用した評価を返す。点数を読むだけで探索記録全体をコピーしない。詳細を独立して持つ場合はto_owned()を使う。candidates()は独立した評価を列挙する診断用の入口で、評価の意味は同じである。

BookEntry::value()は採用する局面値、final_score()は手動指定とは別の最終石差の情報。使える登録手がなければBookPlayerは理由を返し、通常探索は呼出し元で行う。Engineの再帰探索はbookを読まない。

コードを追う順序と試験はソースの読み方、APIの変更は互換性にまとめている。
