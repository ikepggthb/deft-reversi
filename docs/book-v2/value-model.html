評価値と探索条件の意味

生成再開用はwork v8、対局用はplay v4。評価の意味は共通である。古い計算経路の保存は廃止したが、現在値の種類・対象範囲・探索条件を区別する。

一件の探索記録

情報 必要な理由
評価値と、点・上限・下限の区別 「+4と評価」と「+4以下と分かった」を混同しない
探索開始局面と対象手集合、最良手 部分的に調べた結果を対象外の手へ流用しない
要求した条件 利用者が何を指定したか分かるようにする
実行予定の条件 既存の完全読み情報を守るため強化した場合などを表す
実際に完了した条件 中断した目標を達成済みとしない
モデル等の番号と実行番号 異なる推定を混ぜず、いつの設定で得た結果か調べる
探索量と所要時間 診断用。値の正しさを保証する指標にはしない

中盤は実際の深さと選択率、終盤は終盤探索であることと選択率を保存する。深さ20を要求して16まで完了した場合、実際の結果は16。現行のレベル19が深さ16・95%に解決された場合も、19と16を別に残す。将来のレベル＝深さになっても中断時の区別は残る。

元の探索記録は共有する。値を使う場所には内部番号と使い方を置く。内部番号は保存し直すと変わる可能性があり、外部APIへ公開しない。

推定と最終石差

ValueClaim::Estimateは推定で、点評価または探索上の上限・下限を持つ。選択的終盤もこの種類である。選択率95%を、book全体が95%の確率で正しいという意味へ読み替えない。

ValueClaim::Certifiedは、完全読み切りや終局ルールで分かった最終石差の上下限である。上下限が同じときだけ点確定となる。中盤Fullの深さが空き升数と等しいだけでは、この種類へ変えない。

親視点へ移すと、値は符号を反転し、区間[L,U]は[-U,-L]となる。着手では到達範囲に1を加え、パスでは加えない。元の探索で完了した深さは書き換えない。

対象の範囲

集合の最大値、最良手の点評価、その他の対象手の上限を区別する。A・B・Cだけを調べた値を、ほかの合法手を含む局面全体の値にしない。子から親へ値を渡す場合も、子の全体について分かっている値を使う。

局面全体の点評価は、最良の点評価と、それを超えない他の手の評価・上限で範囲を覆える場合に求める。未評価の手を0点や排除済みとして扱わない。

直接探索した値と、子から計算した値

ValueAnalysis::Searchには実際の探索記録がある。Derivedは子や候補の値から計算した結果であり、単一の直接探索を行ったように表示しない。

CalculationSubjectは値の対象を表す。Positionは局面全体、FromChildは子の値を親視点へ変換したもの、Candidateは特定の候補手である。以前の入力記録への参照は持たない。

中盤・終盤が混ざる計算結果は、QualitySummaryという種類別の品質要約を持つ。中盤の到達深さ・選択率と、終盤の選択率を別に判定する。要約の到達深さを、その局面で直接探索した深さとして説明しない。

手動値は手動として記録し、探索済みとはしない。新しいset_manualは架空の探索深さを要求しない。旧取込値の既知の深さ等は記録として保つ。不明な方式はLegacyUnknownとして明示する。

対局で使う条件

既定では中盤12手・95%以上、選択的終盤85%以上を要求する。手動値と方式不明の旧推定は既定で使わない。例えば中盤16以上を要求するならUsePolicy { min_depth: 16, ..Default::default() }を指定する。残り8手の終盤探索を、中盤16手に足りないという理由で落とさない。

借用した値はUsePolicy::check_ref、展開した記録はcheckで同じ条件を確認する。上限だけの手を点評価の着手候補にはしない。手動値を明示許可しても、同時に使う実際の探索の品質条件は維持する。

検査の限界

現在値は保存した元データから再計算し、手・対象範囲・品質を検査する。過去に得た最終石差の情報は独立した保存結果として残す。以前の計算経路は辿れない。読込検査は探索そのものを再実行するものではなく、外部入力の申告が真実かは取込元を信頼する。
