bookのソースを読む

最初から内部の型を全部覚える必要はない。まず、確認したい操作から読む。現在の評価はEvaluation一つで扱い、点数・探索条件・出所を直接読む。旧形式の検査は別の場所へ分けている。

評価を読む

Book::probeで局面を探し、entry.moves()で手を列挙する。それぞれのvalueが評価である。

知りたいこと 読む箇所
点数と、点・下限・上限の区別 value.result()。Score::Estimateは推定、Score::Finalは最終石差の範囲
中盤の深さ、終盤の選択率、混在する条件 value.conditions()
直接探索したのか、子から計算したのか、手動なのか value.source()
実際に完了した一回の探索の詳細 出所がSearchまたはSearchMoveなら、そのCompletedSearch

例えば「この手は+4以下」という情報は+4の点評価ではない。着手に使える一点の値を読むならvalue.result().point_value()を確認する。完全読み切りで石差が一点に確定したかはis_solved()で確認する。

通常の対局参照は借用した評価を返す。to_owned()で独立したEvaluationにできるが、点数・探索条件・出所の読み方は同じである。共有するための番号を呼出し側で扱う必要はない。

評価を表す型、点数と上下限、探索条件を参照する。実際に探索した条件の記録はsearch_record.rsにある。

評価を追加する・登録した子の値を反映する

editor.rsの次の入口から読む。

操作 入口
一回の探索結果を取り込む record_search
一つの手の評価を取り込む record_candidate
手動値を設定する set_manual
その手をbookの進行として登録する register_move
登録を外す unregister_move

変更後はrefresh_fromが子から親の順に再計算する。ある局面へ複数の進行が合流する場合も、影響する親を更新する。

値の候補を集めるのがmove_values_at、その中から採用する値を選ぶのがMoveValues::choose。採用規則だけを確認する場合は、共有番号や盤面の検索処理を飛ばしてchooseを読める。

  1. 現在のモデルに対応する手動値があれば、それを使う。
  2. 最終石差について確定した情報があれば、それを推定で置き換えない。
  3. 登録した子に値があれば、その値を親の手番へ変換して使う。
  4. 子の値がなければ、その手を直接調べた値を使う。
  5. 手をまとめて調べた結果も確認する。最良手以外には上限だけを与える。子から戻した推定を、以前の深い直接推定へ戻さない。

手動値とは独立して、完全読み切りで得た最終石差の情報を保持する。確定情報の共通範囲が空になる変更は拒否し、編集前へ戻す。最終石差の統合はmerge_final_scores、局面全体の最大値はlib.rsのcombine_valuesが担当する。

例として、子の手番から見て-4なら親の手の値は+4。子の最終石差の範囲が[-6,-2]なら親では[+2,+6]。パスでも符号は変えるが、石を置いていないので深さは増やさない。変換はEvaluation::try_child_to_parentにある。

bookを生成する

設定と登録範囲はgenerate.rs、探索を一巡する処理はgrow.rsを読む。

  1. configure_generation_rootsで開始局面・手番の色・設定を決める。
  2. generateが次の仕事を取り出し、prepareが調べる手を決める。
  3. BatchPool::runが探索を実行し、publishが完了結果を反映する。
  4. expandが現在の損失・手数・予算を確認して手を登録する。
  5. 次の段階や子の仕事を追加する。停止時は未完の仕事を探索待ちへ戻す。

「局面が存在する」と「その親から進む手として登録されている」は別である。Edge.registeredが後者を表す。

一回の集合探索はMoveSearchに保持する。最良手の点評価と、それ以外の手の上限を同じ探索から読む。探索範囲に含まない手を評価済みにしたり、一部の手の最大値を局面全体の値にしたりしない。

candidate_planはレベル・深さ指定をEngineの条件へ変換する。現在の子基準のレベル解釈は維持しており、将来の「同じ探索元で中盤レベル＝深さ」へは変更していない。

開始局面から到達できるかはactive_pathsで判定する。同じ局面へ短いが損失の大きい進行と、長いが損失の小さい進行が合流し得るため、最短距離だけでは新規登録を許可しない。analysis_distanceは既存の不明値を調べ直すための判定であり、新規登録の根拠には使わない。

優先順位は探索の順序だけを変える。並列探索では全体のスレッド数・置換表・残りノードを仕事へ分配する。

保存して再開する

format.rsのsave_editor/load_editorが生成再開用、save_book/load_bookが対局用。書き込む形式はwork v8 / play v4で変更していない。

生成再開用に保存するもの 読み込んだ後で作るもの
盤面、登録した手、直接評価、手動値、最終石差の情報、集合探索 子の盤面、親の逆引き、現在の局面値と親へ戻す値
開始局面、色、設定、完了段階、未完の仕事 探索の優先順位の索引、到達条件のキャッシュ
モデル等の説明、実行条件と停止理由 保存に必要のない補助索引

定期保存はgrow::saveが仕事一覧をeditorへ戻してからコールバックを呼ぶ。atomic_saveは一時ファイルへ書いて同期後に置換する。読み込むだけでは元ファイルを更新しない。

旧形式の「導出」「投影」「旧採用方式」といった表現はlegacy内で検査・変換する。現行の局面データには旧方式の途中状態を保持せず、読込中に完了した候補だけを取り込む。旧形式を変更しないレビューでは、この内部表現を追う必要はない。

共有する保存方法を変更する場合

ここまでの値の意味とは別に、values.rsがメモリ上の共有配置を担当する。局面や手は4バイトの参照番号を持つ。記録一覧は点数・出所・探索記録・モデル識別値を共有する。

番号は外部へ公開しない。compact_evidenceで使わない記録を除くときに全参照を付け替える。新しい参照の保持欄を追加した場合は、この走査も修正する。

対局用への変換はsnapshot.rs、使用条件と着手の選択はplayer.rs。統計のための全走査はstats.rsに分けている。
