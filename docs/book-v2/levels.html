レベル、深さ、選択率

指定方法

CLIは--levels 4,8,12、または--stages 12,16,20 --selectivity 95。同時指定は拒否する。RustではGenerationConfig.analysisのAnalysisSchedule::LevelsまたはStagesを使う。使わない側の設定は存在せず、検査もしない。

レベルは1〜60の厳密な昇順。深さ系列は2〜60で深さを増やし、選択率を下げない。

target/release/book build --model MODEL --work trial.dbook-work \
  --levels 2,4 --max-plies 2 --seconds 10 --tt-mib 64
target/release/book extend --model MODEL --work trial.dbook-work \
  --levels 4,8,12 --max-plies 12 --seconds 60
target/release/book resume --model MODEL --work trial.dbook-work --seconds 60

現在の解釈

レベルから実行条件への変換は、Engineの表を使う一か所の処理へ集約する。現在は候補手を打った子局面でレベルを解決し、着手分を加えた親基準の探索条件で残り候補を調べる。パスでは加算しない。例えば子の深さ2なら親からは3。序盤のレベル19が親基準の深さ16・95%になる場合がある。

Engine::search_planは探索を実行せず予定条件を返す。実際に完了した方式・深さ・選択率はSearchResultから保存する。選択探索に必要な校正がなければ、黙ってFullへ変えずにエラーとする。ただし保持結果を再利用する場合や、既存の確定情報を守るためFullへ強化する場合はその実条件を使う。

深さと選択率の一方だけが強い結果を、単純な順位で上書きしない。未登録側を調べ直す場合は、残す必要のある条件を満たす探索予定を作る。登録先の子の値を使うかどうかは、これとは別で常に子から反映する。

将来の中盤レベル＝要求深さ

将来は、同じ探索開始局面で「中盤レベルN＝要求深さN」とする。今回その挙動へ変更したわけではない。

移行時にはEngineとbookの基準局面を揃える。現在の子基準の換算だけを残すとN+1へずれるため、両方を一緒に変更する。選択率、終盤への移行、選択的終盤と完全読み切りの条件は別に定義する。旧ChildLevelの記録を、新しい深さへ読み替えない。

要求・予定・実際に完了した探索の区別は、将来も維持する。要求16でも12までで停止したなら、完了した結果は12。中盤Fullを、深さが空き升数と同じという理由で最終石差の確定情報にしない。

続行と再設定

resumeは保存した条件を引き継ぐ。レベルや範囲を変更する場合はextend、同じ結果の再利用を無効にする場合はreanalyzeを使う。旧形式に保存された完了結果は、条件変更の前に取り込む。
