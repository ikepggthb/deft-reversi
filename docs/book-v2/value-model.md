# 評価値と探索条件の意味

work v8とplay v4で、評価の意味は共通である。現在の評価は`Evaluation`で読み、点数・探索条件・出所を区別する。

## 点数と上下限

`result()`が返す`Score`には次の二つがある。

|種類|意味|
|---|---|
|`Estimate { score, bound }`|探索条件内の推定。boundは`Point`（点評価）、`Lower`（下限）、`Upper`（上限）|
|`Final(ScoreInterval)`|完全読み切りや終局ルールで分かった、最終石差の範囲|

例えば+4の点評価と、+4以下という上限は異なる。`point_value()`は一点の値がある場合だけ返す。`Final`も片側の上下限だけの場合があり、両端が同じときだけ`is_solved()`がtrueになる。判定結果を別の編集可能なフラグとして保存しない。

選択的な終盤探索は推定である。中盤Fullの深さが空きマス数と同じだけでも、最終石差の確定へ変えない。選択率95%をbook全体が95%正しい確率とは扱わない。

子から親へは符号を反転し、区間[L,U]は[-U,-L]となる。石を置く手では親からの深さへ1を加え、パスでは加えない。元の探索記録で実際に完了した深さは書き換えない。

## 実際の探索条件

`conditions()`で、採用する値に含まれる中盤・終盤・方式不明の旧入力の条件を読む。子から計算した値に中盤と終盤が混ざる場合も、それぞれを残す。

- 中盤は、最低の到達深さと選択率。
- 終盤は、終盤探索であることと最低の選択率。
- 旧入力は、記録された深さと選択率。失われた方法は推測しない。
- 手動値を含む場合は、その事実。手動の表示深さで実際の探索条件を下げない。

一回の探索の詳細は`CompletedSearch`に保存する。要求した条件、実行予定の条件、実際に完了した条件、探索元の盤面、対象手集合、最良手、結果、モデル・実行との対応、ノード数と時間を持つ。

深さ20を要求して16までで停止したなら、完了結果は16。現在のレベル19が深さ16・95%へ解決された場合も19と16を別に残す。[将来のレベル＝深さ](levels.md)へ変えた後も、この区別は必要となる。

## 値の出所と対象範囲

`source()`で出所を直接読む。直接探索なら探索記録、子から求めた値なら子の盤面、局面や特定の手から計算した値ならその対象と探索条件がある。過去の入力記録をたどる連鎖は持たない。

集合探索の最大値と、そこから得る手の値を区別する。A・B・Cだけを探索した結果を、ほかの合法手を含む局面全体の値にしない。最良手には点評価、ほかの対象手には上限だけを与える。この操作のために別の「投影」分類を公開APIで指定する必要はない。

局面全体の点評価は、最良の点評価と、それを超えないほかの手の値・上限がそろえば求められる。その場合でも全候補に点評価があるとは限らない。未評価の手を0点として扱わない。

## 対局に使う条件

既定では中盤12手・95%以上、選択的終盤85%以上を要求する。子から計算した値は、その元の探索条件を確認する。手動値と方式不明の旧推定は既定で使わない。

`UsePolicy.allow_manual`は手動値、`allow_imported`は方式不明の旧推定、`allow_calculated`は子や候補から計算した値の使用許可。許可した場合も、それぞれの実際の探索条件を確認する。中盤と終盤を一つの最低深さだけで判定しない。

借用した値は`UsePolicy::check_ref`、独立した評価は`check`で同じ条件を確認する。上限だけの手を、その点数が得られる着手として選ばない。

## 検査の限界

読込では盤面・手・対象範囲・探索条件・上下限を検査し、保存した情報から現在値を再計算する。探索そのものを再実行して外部入力の申告の真偽を確かめる機能ではない。
