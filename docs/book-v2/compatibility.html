保存形式と旧bookの引継ぎ

現在の形式

ファイル 読込可能 新しく保存する版 用途
.dbook-work v1〜v8 v8 生成・更新の元データと再開状態
.dbook v1〜v4 v4 対局用の読み取りデータ。生成再開には使わない

二つの用途で、点数・探索方式・品質の意味は共通である。workから直接export()して対局に使えるため、playファイルの出力は任意。

新形式は、モデル等、完了した探索、値の説明、評価値をそれぞれの一覧へ保存し、番号で対応付ける。一回の探索を、最良手の値と他の手の上限に使っても、元の探索記録は一件だけとなる。過去の計算に使った入力記録の連鎖は保存しない。

ヘッダーは識別文字8バイト、形式版u32、ルール版u32、本文長u64、本文のSHA-256の32バイト。合計56バイトで、数値はlittle-endian。Rustの構造体配置をそのままファイルへ書かない。

生成設定は、レベル系列か深さ・選択率系列かを表すタグと、選んだ系列だけを保存する。旧版の二つの設定欄は読込時だけ解釈する。

変換で残すもの

局面、登録した手、直接探索の既知の値・条件、手動値、最終石差について分かっている上下限、生成設定を残す。旧形式に残った完了済みの結果も更新手順を通して取り込み、未完了の仕事は続行対象にする。

失われた方式は不明のまま。深さが空き升数と同じという理由で終盤探索や完全読み切りへ変更しない。旧v7/v3の計算元参照は読込時に検査し、新しい保存へは引き継がない。計算した値は現在の情報から作り直す。

旧play v3で手動値と旧探索の評価を合成した場合、旧版では手動値の表示深さも探索の最低深さへ含めていた。旧入力関係を当時の規則で検査してから、入力に残る探索条件を現在の方法で集計し直す。点数と各手の情報は保ち、探索品質を変更した場合は、旧品質を前提にしているか判断できない任意拡張を破棄する。

旧workは子の値を親へ反映する方式へ移行する。以前の直接探索結果は残すが、採用値やその品質が変わる場合がある。CLIは変換元の版、局面数、登録手数、採用する局面値・候補値が変わった件数を標準エラーへ報告する。評価採用方式が変わる場合は、完了した探索結果を保ったまま、開始局面から必要な仕事を組み直す。古い方式の待ち行列や拡張キャッシュはそのまま使わず、意味の変化を解釈できない任意拡張も破棄する。jobs_rebuiltで組み直しの有無を表示する。Rustではmigration_report()で取得できる。変換報告自体は再開データの意味に影響しない。

元ファイルはコピーで保護する。

cp openings.dbook-work next.dbook-work
target/release/book verify --work next.dbook-work
target/release/book repair --work next.dbook-work --book next.dbook
target/release/book verify --work next.dbook-work
target/release/book verify --book next.dbook

verifyは入力を書き換えない。repairは指定先を新形式で保存する。旧バイナリは新形式を読めないので、元ファイルを保持する。保存途中の失敗で既存ファイルを壊さない方式を維持する。

ファイル互換性と探索の互換性

ファイルが読めることと、その推定を現在のモデルと混ぜてよいことは別である。analysis_identityはモデル重み、校正、sigma、探索feature、探索仕様のrevisionから作る識別情報。

今回、再帰探索とレベル表を変更していないため探索revisionは2のまま。レベルの意味・枝刈り・点数の意味が変わる場合は、別途revisionの更新を判断する。

モデル等が変わる場合はコピーにreanalyzeを使う。互換性のない推定は無効にし、登録・手動の原記録・ルールが一致する最終石差の確定情報は残す。古いモデルの手動値は黙って現在の値として使わない。探索自体の不具合で過去の確定情報が誤っていた場合は、別途監査・再構築が必要。

読込時は、長さ、件数、割当上限、盤面、合法手・パス、参照番号、探索対象、品質、上下限、登録先を検査する。不明な必須拡張は拒否する。未知の任意拡張は無編集の往復で保持し、意味の変わる更新では破棄する。

旧APIからの変更

GenerationConfig.levels / stagesはanalysisへ統合した。汎用のrecordは、record_search、record_candidate、record_imported、set_manual / record_manualへ分けた。評価のフィールドを旧表示へ自動で読み替える仕組みは廃止し、score()、claim()、analysis()などで明示的に読む。

旧入力用のLegacyAssessmentはImportedValueへ変更した。外部入力をAssessment::importで明示的に扱う。evidence_inputs / evidence_by_idによる過去の計算経路の参照は廃止した。

保存場所とAPI、値の更新、試験・実測も参照。
