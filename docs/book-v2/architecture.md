# 保存する情報とAPI

この版は、局面の値と最良の未登録手を中心にする。探索結果を一か所へ置き、必要な場所から番号で参照する。生成・更新の元データを持つ型が`BookEditor`、対局で読む型が`Book`である。

コードを確認する場合は、[ソースの読み方](source-review.md)に読む順序、関数間の流れ、保存する情報と作り直す情報、対応する試験をまとめた。

## 何を、どこへ保存するか

|保存場所|情報と用途|
|---|---|
|局面|盤面、登録した手、現在の値、最終石差の上下限、最良の未登録手を探した記録への番号|
|探索記録の一覧|実際に行った一回の探索について、対象盤面・手集合・最良手・結果・要求・予定・完了条件・実行番号を一件だけ保存|
|モデル等の一覧|モデルと校正・探索仕様の識別情報を共有。各評価は一覧内の番号で対応付ける|
|個別の手の追加情報|独立した探索結果、手動値、残すべき最終石差の上下限がある場合だけ追加の領域を確保|
|生成状態|開始局面と色、設定、次の仕事、停止再開に必要な状態|

例えば局面Pの候補A・B・Cを探索し、Aが最良、評価+4だった場合、元の探索記録は一件。集合全体の最大値、Aの点評価、B・Cの上限は、この記録をどの意味で使うかだけを変える。探索条件や盤面を三件分複製しない。

候補や局面が持つ記録番号は4バイト。番号は内部用で、呼出し側へ公開しない。使わなくなった記録を解放する際は、参照する番号もまとめて更新する。探索中の仕事は盤面・更新世代・予定条件を持ち、この番号を保持しない。

更新中は、内容から記録番号を検索するための補助索引も持つ。この索引のメモリも見積もりへ含め、対局用データでは索引を解放する。

局面の値、親を逆引きする一覧、座標変換済みの子局面、探索の優先順位は、保存した情報から作り直せる補助データである。子局面の座標計算を繰り返さないための補助データは残す。過去の評価を計算した入力記録の全経路は保存しない。

## 生成と更新の入口

`GenerationConfig.analysis`は次のどちらか一方である。

```rust
use deft_reversi_book::{AnalysisSchedule, GenerationConfig, Stage};
use deft_reversi_engine::Selectivity;
let levels = GenerationConfig {
    analysis: AnalysisSchedule::Levels(vec![4, 8, 12]),
    ..Default::default()
};
let depths = GenerationConfig {
    analysis: AnalysisSchedule::Stages(vec![Stage {
        depth: 16, selectivity: Selectivity::Percent95,
    }]),
    ..Default::default()
};
```

`configure_generation_roots`で開始局面と黒白の色を渡す。`generate`または`generate_with_checkpoint`へ、Engineと明示的な時間・ノード・追加局面予算を渡す。後者のコールバックで`save`すれば定期保存できる。

|API|用途|
|---|---|
|record_search|現在のモデル等で行った探索の結果を、対象手集合ごと取り込む。盤面と着手は正規化した座標で渡す|
|record_candidate|特定の手について得た、検査済みの探索・取込結果を追加する|
|record_imported / Assessment::import|外部から申告された値を明示的に取り込む。失われた探索方法は不明のまま|
|set_manual / record_manual|手動値を設定する。探索結果の追加とは入口を分ける|
|register_move / unregister_move|手をbookの進行として登録・解除する。局面の存在だけでは登録扱いにしない|
|repair|保存結果から現在の値と補助データを作り直す。探索は行わない|
|retarget|モデル等の変更に伴い、互換性のない推定を無効にする|

これらの変更は、対象の更新、影響する親の再計算、必要な仕事の追加を共通の手順で行う。矛盾などで失敗した場合は値・登録状態・更新世代を戻す。

## 対局で読む

`Book::probe`は入力盤面に対応する参照を返す。通常の手の走査には`BookEntry::moves()`を使う。返す`BookMove`の値は借用した`EvaluationRef`で、点数や品質の確認時に探索記録一式をコピーしない。詳しい探索条件は`analysis()`、独立した読取結果が必要なら`to_owned()`で取得する。

`BookEntry::candidates()`は、詳しい評価記録を展開して返す診断用の便利な入口として残す。`value()`と`proof()`は局面の現在値と最終石差の情報を返す。`positions()`で保存局面を列挙できる。

`BookPlayer`は通常の手の参照を使い、品質・モデル・登録・損失条件を確認する。使える手がなければ理由付きで通常探索へ戻す。問い合わせごとのメモリ確保はしない。Engineの再帰探索にはbook参照を追加しない。

## 実装の配置

`values.rs`が共有する記録、`editor.rs`が局面と更新、`generate.rs / grow.rs`が仕事の選択と探索実行、`format.rs`が新旧形式の読書き、`snapshot.rs / player.rs`が対局用の配置と手の選択を担当する。古い形式の評価採用方式は、読込時の比較・変換だけで使う。

[評価の意味](value-model.md)、[値の更新](propagation.md)、[保存形式と移行](compatibility.md)、[測定と試験](validation.md)も参照。
