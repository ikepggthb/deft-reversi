展開の損失制御

三つの独立した制限

点評価と残り候補の上限から局面値bestを再構成し、候補の局所損失をmax(0, best−candidate)とする。符号はその局面の手番視点でそろえる。

設定 API 対象 既定
1手の損失 expansion_loss、black_loss、white_loss 新規リンクと既存経路の双方 共通2、色別指定なし
累積損失 cumulative_loss: Option<u16> rootからの局所損失の和、黒白双方を含む 制限なし
leaf誤差 leaf_loss: Option<u8> 未登録候補を新しくリンクにする時 制限なし

CLIは--loss、--black-loss、--white-loss、--cumulative-loss、--leaf-loss。後二つはnoneで制限を解除できる。例えば--loss 3 --cumulative-loss 5 --leaf-loss 2では、既存の3石差リンクは通れるが、新しいリンクは2石差まで。既存リンクを消す操作ではない。

現在のDeftは最良の未展開手の点評価をleaf評価として使い、他の候補を上限で覆う。上限だけの手は登録せず、許容範囲内なら次の最良手を探索して点評価を得る。leafの独立再計算はleavesモードで実装した。優先スケジューリングも選択できる。

経路と転置

盤面と絶対手番色のContextに対し、(rootからの着手数、累積損失)の非劣な組を持つ。距離2・損失3と、距離4・損失0なら両方必要。距離上限と損失上限をそれぞれ別の経路で満たしても、その二つを合成して架空の距離2・損失0にはしない。同じ距離では最小損失だけを残す。各Contextで最大61組となる。

root到達時は距離0・損失0にリセットする。複数rootのどれかから条件を満たせば処理できる。パスは手番色を反転し、着手距離は加算しない。強制パスは唯一の合法Actionなので局所損失0。

保存キューの距離はヒントであり、実行時には逆リンクから現在の評価で経路を再判定する。評価変更で外れた枝は保存し、自動強化から外す。再び条件を満たすと既存の完了値を使って処理を再開する。展開済みのキャッシュには経路の組と候補の損失を含め、候補集合が同じでも残り損失予算が変わった場合は子を再スケジュールする。

メモリと検証

到達判定は祖先をメモ化する逐次処理。同じrevision・到達集合ならメモを再利用し、登録や評価が変われば無効化する。Editorの見積もりには一時メモの各Context最大61組と展開キャッシュの容量を含める。プロセスRSSのハード上限ではなく、EngineやI/Oバッファは別管理。大規模育成時の計算量・メモリは引き続き計測が必要。

試験は3+3を上限5で拒否、3+2への改善で再活性化、leaf制限と既存リンクの独立性、保存往復、転置で短い高損失経路と長い低損失経路を保持、パスの距離0と色反転を確認している。制限変更にはextendを使う。resumeは設定変更を拒否する。
