# 持ち時間制（一局全体の持ち時間）での時間配分

GTP の `--game-ms` / `time_left` と FlipSight の `remaining_ms` のように、一局全体の持ち時間で指すときの時間配分の設計。2026-11-18 版はエンジン側（`GameClock`、`SearchRequest::target_time`）で時間を管理していたが、2026-11-20 に `feature/cli-v2` の `game_clock.rs` に統合した。この文書は統合後の設計を書いている。

実装：`deft-reversi-cli/src/game_clock.rs`（`Budget`、`Forecast`）。エンジン側は `SearchRequest::timed_levels` と `Progress`（`next` を含む）だけを使う。

今の方式の動作を一手の流れから順に説明した文書：`2026-11-20-game-clock-explained.md`。

## 1. 変更前の問題（2026-11-18 時点）

| 箇所 | 変更前の配分 |
|---|---|
| FlipSight | `min(budget_ms, remaining / (空き/2 + 1))` を**ハードな上限**にして `timed_levels` |
| GTP | `remaining / ((空き − 20)/2 + 1)` を上限にして `Level(60)`。21空き以下では分母が1になり、残り時間全部が1手の上限になる |

1. **均等割り＋上限だけ**：反復深化は上限が来た時点で途中の反復を捨てるので、最後の反復に使った時間はまるごと無駄になる。
2. **余りを使い切れない**：完全読みが終わった後の手番はほぼ時間を使わないのに、それを見込まずに割っている。
3. **完全読みの時期を考えていない**。
4. **最善手が揺れていても時間を延ばさない**。

## 2. 参考にした実装

### Edax（`search.c` の `search_time_set` など）

- `solvable_depth(残り時間の10%)` で完全読みできる空き数 `sd` を見積もる（NPS と分岐数の定数から）。
- `moves_to_do = max((空き − sd)/2, 2)`、1手の時間 `t = 残り / moves_to_do × 0.9`。
- 3段階の時間：`mini = 0.3t`（これを過ぎたら次の反復を始めない）、`maxi = 0.9t`、`extra = t`（探索を止める）。
- `extra` に達した時点で評価値が前の反復より下がっていれば、残りの半分まで延ばす（1回だけ）。

### Egaroucid（`time_management.hpp`、`ai.hpp` の `ai_time_limit`）

- 残り時間から 400ms×残り手数 ＋ 5秒を安全分として除く。
- `Nodes = a·exp(b·空き)` と NPS から、残り時間の90%で完全読みできる空き数と、15%で終盤 MPC できる空き数を出し、今の空き数がそれ以下ならその時間を上限にする。
- それ以外は、30空き以上の手数に重み（×1.4、40空き以上は＋0.2）を付けて割る。
- 38空き以上では、浅い全手探索で評価値の近い候補が2手以上あれば時間を足す。

## 3. 設計

### 3.1 手番の予算：`Budget::new(空き, 残り, 上限)`

1. 将来の自分の手番を、終局に近い方から順に見る。その手番の完全読みの見積もり `solve = 2ms + 3 × 6ms × 2^(空き−17)` が、今の均等額（`pool / 残り手数`）より安ければ、その分を予約して `pool` から引き、手数から外す。高い手番に当たったところで止める。
   - `6ms × 2^(空き−17)` はレベル表の測定での1スレッドの完全読み時間。3倍は、遅いマシン・冷えた置換表・局面のばらつきの分。2ms は整数ミリ秒の時計での往復の分。
   - スレッド数では割らない。4スレッドでは20〜30空きの完全読みが約3.3倍速い（probe・45局面）が、`threads^0.85` で割って予約を減らした版は、FlipSight 6秒・4スレッドで −0.33石 [−0.63, −0.03] だった（`deft-reversi-notes/benchmarks/2026-11-20-time-control-forecast/`）。
   - 今の手番は予約の対象にしない。今の局面は平均より重いことがある。
2. `soft = pool / 残り手数`（均等額）。
3. `hard = soft + min(soft, (pool − soft)/2)`。均等額1つ分まで、ただし将来の高い手番の予算の半分までしか借りない。予約済みの安い手番からは借りない。プロトコルの上限（FlipSight の `budget_ms`）も超えない。

残り時間は毎手の実測値から計算し直すので、使い残しは後の手番に回る。

### 3.2 探索：`Budget::search`

`SearchRequest::timed_levels(60, hard).reuse_pv().skip_pv_recovery()` で探索する。`hard` に達すると、エンジンが途中の反復を捨てて最後に完了した反復の結果を返す。

反復が完了するたびに `Forecast::stop` が呼ばれる。そこで次の反復の完了時刻を予測し、目標を超えるならストップハンドルで止める（止めた理由は `StopReason::TimeLimit` として返す）。

### 3.3 次の反復の予測：`Forecast`（`Progress::next` で場合分け）

`Progress::next` は、エンジンが次に実行する予定の反復の種類（最後の反復のあとは `None`）。予測時間は、直前の反復の時間に倍率を掛けたもの。

| 今の反復 → 次の反復 | 倍率 |
|---|---|
| どれでも → なし | 予測しない（止めない） |
| 中盤 d → 中盤 d′ | 直近2つの中盤反復の比を2手あたりに直し（1.5〜6 に収める）、`(d′−d)/2` 乗する。比が分からないときは2手あたり3 |
| 中盤 → 最初の終盤ステージ | `max(2, 5 × 1.06^(空き−24))`。20空きで約4、28空きで約6.3 |
| 中盤 → 完全読み（選択的ステージなし） | 上の倍率 × 下の倍率 |
| 選択的ステージ → 完全読み | `max(1, 3 × 1.15^(空き−22))`。20空きで約2.3、26空きで約5.2 |
| 選択的ステージ → 次のステージ | 1.25 |

止める条件は `経過 + 予測 > min(soft × (1 + 不安定度), hard)`。不安定度は、最善手が変わったとき1、変わらない反復ごとに半分になる（最大で soft の2倍まで延びる）。

倍率は中央値に合わせている。soft と hard のあいだに余裕があるので、予測より重かった場合の多くは hard の内側に収まる。少なく見積もると、終わらない反復に hard まで時間を捨てる。多く見積もると、そのステージを次の手番に回すだけで、時間は後に残る。

### 3.4 時間がないとき

`hard` がゼロ（残り時間がほぼない）のときは、合法手の先頭ではなく2手読み（`Goal::Depth(2)`）で指す。数マイクロ秒で終わる。

## 4. 測定

### 4.1 遷移の倍率（2026-11-20、`deft-reversi-notes/benchmarks/2026-11-20-time-control-forecast/`）

`tools/time-control/probe`（置換表を空にして `timed_levels(60, 30s)`、20〜34空き）と、対局中の `DEFT_GTP_LOG` から集計した中央値（`tools/time-control/ratios.py`）。

| 遷移 | probe 1スレッド | probe 4スレッド | 対局中（1・4スレッド、2秒・20秒） |
|---|---|---|---|
| 中盤 → 終盤 | 5〜6（20〜36空き） | 4〜8 | 15〜19空き 約2、20〜27空き 2〜5、28〜31空き 5〜13 |
| 選択的 → 完全読み | 20〜23空き 3.4、24〜27空き 4.8、28〜31空き 6以上 | 2.6、4.5、4以上 | 15〜19空き 0.4〜0.9、20〜23空き 1〜2.6、24〜27空き 2〜4.5 |
| ステージ → ステージ | 0.9〜1.25 | 0.9〜1.5 | 0.8〜1.4 |

スレッド数で中央値はあまり変わらない。2026-11-18 版の「完全読みは×20」「ステージ間は×2」は、どちらも大きすぎた。

### 4.2 対局

`deft-reversi-notes/benchmarks/2026-11-20-time-control-forecast/README.md` を参照。`a21b8c9` と、調整に使っていない開局（1000番以降）で対局させた。

| 条件 | 1スレッド | 4スレッド |
|---|---|---|
| GTP 2秒 | +0.10 [+0.01, +0.18]（400局） | −0.11 [−0.39, +0.17]（200局） |
| FlipSight 2秒 | +0.13 [−0.04, +0.29]（400局） | +0.01 [−0.35, +0.38]（200局） |
| FlipSight 6秒 | −0.02 [−0.07, +0.03]（400局） | −0.01 [−0.18, +0.15]（200局） |
| GTP 20秒 | +0.04 [−0.08, +0.16]（200局） | +0.04 [−0.09, +0.17]（100局） |
| GTP 60秒 | +0.05 [−0.11, +0.20]（128局） | — |

石差は新から見た平均で、括弧は開局ペアごとの95%信頼区間。時間切れはどの条件でも0件。GTP 2秒・1スレッド以外は区間が0をまたいでいる。GTP 2秒・1スレッドも、9条件のうちの1つで下限が0にほぼ接しているので、改善とは判断しない。悪化した条件もない。

終わらない反復に捨てた時間（次が終盤の最初のステージか完全読みなのに hard まで使った手の、最後の反復が終わってからの時間）は、総使用時間に対して GTP 2秒で1.9%→0.4%、20秒で5.0%→0.5%、60秒で7.8%→0.7%（1スレッド）に減った。

## 5. 今後

- **余った時間の使い方**：予測を正確にしたことで、終局時に時間が余るようになった（GTP 20秒で約0.6秒）。倍率を対局中の値に下げる案（第2案）は、時間を使い切るが終わらない反復も増え、強さは変わらなかった。手番ごとの重み w(e) で余りを中盤に回す方が筋がよい。
- **損失の表による配分の調整**：`deft-reversi-notes/benchmarks/2026-11-20-time-allocation-loss-table/` で、20〜48空き各64局面の表から最適配分を計算した。交差検証では今の配分との差が見えず、配分を変える根拠にはならなかった。確かなのは、24〜28空きでは85%〜95%のステージに届くと1手あたり0.2〜0.35石の損失が減り、完全読みまで進めても減らないこと。完全読みの予約を95%/98%のステージの時間に置き換える案は、対局で確かめる必要がある（予約を減らした `5339c14` は負けた）。
- **終盤の時間見積もりのオンライン補正**：完全読みの実際の時間から `solve(e)` を対局中に直す。
- **候補手の拮抗による延長**（Egaroucid）。
