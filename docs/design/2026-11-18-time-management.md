# 持ち時間制（一局全体の持ち時間）での時間配分（2026-11-18）

GTP の `--game-ms` / `time_left` と FlipSight の `remaining_ms` のように、一局全体の持ち時間で指すときの時間配分を見直した。

## 1. 変更前の問題

| 箇所 | 変更前の配分 |
|---|---|
| FlipSight | `min(budget_ms, remaining / (空き/2 + 1))` を**ハードな上限**にして `timed_levels` |
| GTP | `remaining / ((空き − 20)/2 + 1)` を上限にして `Level(60)` |

1. **均等割り＋上限だけ**。反復深化は上限が来た時点で途中の反復を捨てるので、最後の反復に使った時間はまるごと無駄になる。反復の時間は2手深くするごとに約2〜2.5倍になるので、平均すると割り当ての半分ほどが捨てられる。
2. **余りを使い切れない**。FlipSight では完全読みが終わった後の手番はほぼ時間を使わないが、それを見込まずに「残りの手数全部」で割っている。20秒の持ち時間で 9秒前後を残して終局していた（4章）。
3. **完全読みの時期を考えていない**。何空きで完全読みに入れるかを見積もらず、そのための時間も残していない。
4. **最善手が揺れていても時間を延ばさない**。

## 2. 参考にした実装

### Edax（`search.c` の `search_time_set` など）

- `solvable_depth(残り時間の10%)` で完全読みできる空き数 `sd` を見積もる（NPS と分岐数 `BRANCHING_FACTOR` の定数から）。
- `moves_to_do = max((空き − sd)/2, 2)`、1手の時間 `t = 残り / moves_to_do × 0.9`。
- 3段階の時間：`mini = 0.3t`（これを過ぎたら次の反復を始めない）、`maxi = 0.9t`、`extra = t`（探索を止める）。
- `extra` に達した時点で最善手の評価値が前の反復より下がっていれば、残りの半分まで `extra` を延ばす（1回だけ）。

### Egaroucid（`time_management.hpp`、`ai.hpp` の `ai_time_limit`）

- 毎手、残り時間から 400ms×残り手数 ＋ 5秒を安全分として除く。
- `Nodes = a·exp(b·空き)` のモデルと NPS から、残り時間の90%で完全読みできる空き数と、15%で終盤読み（MPC 付き）できる空き数を出す。今の空き数がそれ以下なら、その時間を上限にする。
- それ以外は、30空き以上の手数に重み（×1.4、40空き以上はさらに＋0.2）を付けて割る。30空き未満の手は分母に入らず、その分が終盤用に残る。
- 38空き以上では、先に全合法手を浅く読み、評価値の近い候補が2手以上残れば `request_more_time` で時間を足す。
- 深い中盤探索で最善手が2回続けて変わらず、次善手が閾値以上悪いと分かれば早めに打ち切る。

## 3. 設計

Edax の「完全読みの地点を見積もり、そこまでの手数で割る」と「目標時間と上限の2段階」を土台にした。時間を延ばす条件は、Edax の「評価値が下がったとき」と Egaroucid の「最善手が決まらないとき」を合わせた。

### 3.1 手番の時間：`GameClock::move_time`（エンジン、`search/clock.rs`）

入力は残り時間・空き数・スレッド数で、任意で1手ごとのオーバーヘッドと上限（FlipSight の `budget_ms`）も渡せる。出力は `MoveTime { target, limit }`。

1. `usable = 残り − overhead × (自分の残り手数 + 1)`
2. 完全読みの時間の見積もり：`solve(e) = 0.2s × 2.2^(e−20) / threads^0.8`。4スレッドでの実測（4章）に合わせた、計画用の大まかな値。
3. **今すぐ解ける**（`solve(空き) ≤ 0.4·usable`）なら、`target = 0.4·usable`、`limit = 0.6·usable`。解き終われば、それ以降の手番はほぼ時間を使わない。
4. それ以外は、完全読みに入る空き数 `e_s` を、`solve(e_s)/0.4 ≤ 0.4·usable` を満たす最大の値にする。`reserve = solve(e_s)/0.4` を残し、`(usable − reserve)` を `e_s` までの自分の手数で均等に割って `target` にする。`limit = min(3·target, 残りの半分)`。
5. 上限（`move_cap`）があれば、`target` と `limit` をそれ以下にする。

残り時間は毎手の実測値から計算し直すので、使い残しは自然に後の手番へ回る（均等割りでもうまく働く理由）。

### 3.2 反復ごとの判断：`SearchRequest::target_time`（エンジン、`Pacer`）

反復が1つ終わるたびに、次の反復にかかる時間 `T̂` を予測する。

| 次の反復 | 予測 |
|---|---|
| 中盤 d → d+2 | 直前の反復時間 × 実測の伸び率（前回との幾何平均、1.5〜5 に収める。分からないときは2.5） |
| 中盤 → 最初の終盤ステージ | 直前の反復時間 × `4·1.35^(空き−28)`（4以上）。28空きで約4倍、32空きで約13倍（実測） |
| 終盤ステージ → 次のステージ | ×2 |
| 99% → 完全読み | ×20。実測では10〜45倍とばらつく。多めに見積もっても、完全読みが次の手番に回るだけで済む |

`経過 + 0.5·T̂ ≤ target` かつ `経過 + T̂ ≤ limit` のときだけ次の反復を始める。止めたときは `StopReason::TimeLimit` で、最後に完了した反復の結果を返す。

最善手が変わったとき、または評価値が3石以上下がったとき（同じ種類の反復どうしで比べる）は `target` を1.4倍する。最大で元の2倍までで、`limit` は超えない。

### 3.3 接続

- FlipSight：`GameClock::new(remaining − 受信からの経過).threads(n).overhead(50ms).move_cap(budget − 経過 − 50ms)` で、`timed_levels(60, limit).target_time(target)` を探索する。
- GTP（`--game-ms`）：`GameClock` から求めた `move_time` を `Level(60)` の探索に渡す。

## 5. 今後

- **終盤の時間見積もりのオンライン補正**：完全読みの実際の時間から `solve(e)` の係数を対局中に直す。マシンやスレッド数が変わっても合うようにする。
- **候補手の拮抗による延長**：Egaroucid のように、浅い全手探索で評価値の近い候補が複数あれば時間を足す。今は最善手の変化だけを見ている。
- **早めの打ち切り**：最善手が安定していて、次善手との差が null window 探索で確かめられたら打ち切り、残った時間を後に回す。
- **重み付け**：今は完全読みまでの手を均等に扱っている。序盤の手（Book を抜けた直後）や 30〜40空きの手を重くするのがよいかどうかは、もっと長い持ち時間の対局で確かめる。
- **先読み（ponder）**：相手の手番中に探索する。
