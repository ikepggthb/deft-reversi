# 持ち時間制の時間管理：予測の高精度化の作業計画（2026-11-20）

今の方式の説明は `2026-11-20-game-clock-explained.md`、設計の経緯は `2026-11-18-time-management.md`、議論と途中結果のメモは `2026-11-20-time-control-notes.md` にある。作業ブランチは `research/time-predict`。この文書は、これから行う作業の一覧と進み具合を管理する。

## 目的

時間管理で使っているすべての予測（時間、価値、残り時間の価値）を、根拠のある特徴量で、より正確に計算できるようにする。最終的な評価は対局での石差で行う。

## 守ること

- エンジンの探索本体と公開 API の互換性は保つ。追加はよい。
- 統計の扱い
  - 石差の平均と95%信頼区間（開局ペアごと）を付ける。信頼区間が0をまたぐものは「改善」と書かない。
  - 調整に使う開局と、評価に使う開局を分ける。
- 時間切れは、1件でも重大な問題として扱う。
- 実験は research/* ブランチで行う。変更ごとにテストを通し、意味のある単位でコミットする。
- 記録は `docs/benchmarks/` の日付フォルダに置く（README と結果だけ、索引に1行）。

## 付録C：今の計算式で使っていない特徴量

根拠の「実測あり」は今回までの測定で分かっていること、「仮説」はまだ確かめていないこと。

| 計算 | 使っている特徴量 | 使っていない特徴量 | 根拠 |
|---|---|---|---|
| 残りの手番数 | 空き数 | パスの起こりやすさ | 仮説（影響は小さそう） |
| 完全読みの予約 | 将来の空き数 | すでに完全読みに届いたか、この局・この環境での実測、スレッド数、置換表の再利用、安全係数3倍の根拠 | 実測あり：予約は実際の約4倍。4スレッドは完全読みが約3.3倍速い。ただしスレッド数で割った版は対局で負けた |
| soft | 残り時間、空き数 | 手番ごとの時間の価値の違い | 実測あり（損失の表）。ただし配分を変えて得になるとは示せていない |
| hard | soft、将来の分の合計 | 今の局面の重さ（予測の幅）、プロトコルの違い | 仮説 |
| マージン | 固定 | 実際の返答の遅れ、スレッド数 | 仮説（時間切れ0件なので、余裕が大きすぎる可能性） |
| 中盤 → 中盤 | 直近2反復の比、深さの差 | 比の逆戻り、空き数、深さ、ノード数、置換表の再利用、合法手の数 | 実測あり：前の比への傾きは −0.39（今の式は +1 にあたる）。条件を付けても対数の標準偏差 0.62 |
| ENTRY | 空き数 | 最後の中盤の深さ、ノード数、置換表の状態、評価値、合法手の数・偶奇、スレッド数 | 一部実測あり（空きが少ない・置換表が温まっていると小さい）。ほかは仮説 |
| EXACT | 空き数 | 直前のステージ、評価値、スレッド数 | 仮説（空き数の効果に、直前のステージの違いが混ざっている可能性） |
| ステージ → ステージ | 定数 | どのステージ間か、空き数 | 実測の中央値 1.0〜1.25。分け方は未確認 |
| 予測の幅 | なし（中央値だけ） | σ | 実測あり：中盤→中盤で約0.62 |
| 不安定度 | 最善手が変わったか | 評価値の変化の大きさ、変わった回数、どの反復で変わったか、ルート上位2手の差 | 実測あり：次の反復で減る損失は、安定のとき0.01石、変化したとき0.27石。ほかは仮説 |
| 止める条件 | 予測時間、soft、hard、不安定度 | 次の反復の価値の種類、予測の幅 | 実測あり：終盤の最初のステージは0.18〜0.57石、中盤の1段は0.01石。ただし価値を使う規則でも今と差は見えなかった（`2026-11-20-time-stopping-oracle`） |
