# 持ち時間制の時間管理：今の方式の全体説明（2026-11-20、`717a5c4` 時点）

一局全体の持ち時間（GTP の `time_settings` / `time_left`、FlipSight の `remaining_ms`）で対局するとき、Deft が各手番で何秒使い、どこで探索を打ち切るかを、コードの順にすべて説明する。設計の経緯と参考にした実装は `2026-11-18-time-management.md` にある。

コード：

| 役割 | 場所 |
|---|---|
| 予算と打ち切り | `deft-reversi-cli/src/game_clock.rs`（`Budget`、`Forecast`、`reflex`） |
| GTP の時計 | `deft-reversi-cli/src/gtp.rs`（`Mode::Time`） |
| FlipSight の時計 | `deft-reversi-cli/src/flipsight.rs`（`choose`） |
| 反復の並び | `deft-reversi-engine/src/search.rs`（`timed_level_iterations`）、`deft-reversi-engine/src/search/level.rs`（`endgame_limits`） |

## 1. 一手の流れ

```
手番が来る
 ├ パスしかない → パス
 ├ 合法手が1つ → すぐ打つ
 ├ 定石にある（FlipSight）→ 定石の手
 └ それ以外
     1. 残り時間を読む（安全マージンを引く）            … 2章
     2. Budget::new で soft と hard を決める             … 3章
        hard = 0 なら 2手読み（reflex）で打って終わり
     3. 反復深化で探索する（浅い反復から順に）            … 4章
        反復が1つ終わるたびに Forecast が
        「次の反復は目標までに終わるか」を予測           … 5章
          終わらない → ここで打ち切る（最後に終わった反復の手）
          終わる     → 次の反復へ
        hard に達したら、途中の反復を捨てて打ち切る      … 6章
     4. 最後に終わった反復の最善手を打つ
次の手番では、実際に減った残り時間から計算し直す
```

一局の計画表は持たない。毎手「今の残り時間」と「今の空き数」だけから予算を決め直す。使い残しは自然に後の手番へ回り、使いすぎは後の手番の予算を減らす。

## 2. 残り時間とマージン

| | 残り時間 `remaining` | その手の上限 `cap` |
|---|---|---|
| GTP | `--game-ms` / `time_left` による自分の残り − 10ms | `remaining` と同じ |
| FlipSight | `remaining_ms` − （受信からの経過 + 50ms） | `min(budget_ms, remaining_ms)` − （受信からの経過 + 50ms） |

マージンは、返答の通信と時計の丸めのためのもの。FlipSight では、初手でモデルを読み込む時間もこの上限の中に入る。

## 3. 手番の予算：`Budget::new(空き, remaining, cap)`

その手番の **soft**（目標）と **hard**（絶対の上限）を決める。

### 3.1 残りの手番数

自分の残りの手番数は `turns = ceil(空き / 2)`（パスは考えない）。

### 3.2 将来の完全読みの予約

終局に近い手番は、完全読みが安く終わる。その分を先に取り分けて、残りを中盤以降の手番で分ける。

1. 将来の自分の手番を、終局に近い方（空き2, 4, …）から順に見る。
2. その手番の完全読みの見積もり

   `solve(e) = 2ms + 3 × 6ms × 2^(e − 17)`

   が、今の均等額（`pool / 残り手番数`）より安ければ予約する。`pool` から引き、その手番を手番数から外す。
3. 均等額より高い手番に当たったら止める。

- `6ms × 2^(e−17)` は、レベル表の測定での1スレッドの完全読みの時間（17空きで約6ms、1空きごとに2倍）。
- 3倍は、遅いマシン・冷えた置換表・局面のばらつきの分。2ms は整数ミリ秒の時計での往復の分。
- 今の手番は予約しない（今の局面は平均より重いことがある）。
- スレッド数では割らない。割った版は FlipSight 6秒・4スレッドで −0.33石 [−0.63, −0.03] だった（`docs/benchmarks/2026-11-20-time-control-forecast/`）。

### 3.3 soft と hard

```
soft = pool / 残り手番数                       （予約しなかった手番での均等額）
hard = soft + min(soft, (pool − soft) / 2)     （均等額1つ分まで借りる。将来の分の半分まで）
hard = min(hard, cap)
soft = min(soft, hard)
```

予約済みの安い手番からは借りない。

### 3.4 数値例（XOT 開局直後、52空き、1スレッド）

| 持ち時間 | 予約する手番 | 予約の合計 | soft | hard |
|---|---|---|---|---|
| 2秒 | 18空き以下 | 0.07秒 | 0.11秒 | 0.23秒 |
| 20秒 | 22空き以下 | 0.79秒 | 1.28秒 | 2.56秒 |
| 60秒 | 24空き以下 | 3.10秒 | 4.06秒 | 8.13秒 |

20秒の場合、24空き（完全読みの見積もり 2.3秒）は均等額 1.28秒より高いので予約されない。52〜24空きの15手番で、残りの19.2秒を分ける。

## 4. 探索の計画：反復の並び

探索は `SearchRequest::timed_levels(60, hard).reuse_pv().skip_pv_recovery()` で行う。エンジンは、レベル1〜60がその空き数で行う探索を並べて重複を除き、浅い順に1つずつ実行する。

- **中盤**：レベル表が終盤探索に切り替わる手前の深さまで、2手ずつ深くする（偶奇を合わせて d5/d6 から始める）。選択性（MPC）は 83%。
- **終盤**：最後まで読む探索を、確からしさを上げながら繰り返す。85% → 95% → 98% → 99% → 100%（完全読み）。どのステージがあるかはレベル表（`endgame_limits`）で決まる。

空き数ごとの並び（1スレッドで実際に出るもの）：

| 空き | 反復の並び |
|---|---|
| 34 | d5 d7 … d25 d27 → e85 e95 e98 e99 e100 |
| 30 | d5 d7 … d21 d23 → e85 e95 e98 e99 e100 |
| 28 | d5 d7 … d19 d21 → e85 e95 e98 e99 e100 |
| 26 | d6 d8 … d18 d20 → e85 e95 e98 e99 e100 |
| 24 | d6 d8 … d16 d18 → e85 e98 e99 e100 |
| 22 | d5 d7 d9 d11 d13 → e85 e95 e98 e99 e100 |
| 20 | d5 d7 d9 d11 → e85 e95 e98 e100 |

`reuse_pv` は前の手番の読み筋と置換表を使い回す設定。対局中の反復は、置換表が空のときの約0.7倍の時間で終わる。

## 5. 反復ごとの打ち切り：`Forecast`

反復が1つ終わるたびに、エンジンが `Progress`（経過時間 `elapsed`、終わった反復の種類 `kind`、次に行う予定の反復 `next`、最善手）を渡す。`Forecast::stop` はそこで次の反復の完了時刻を予測する。

### 5.1 次の反復の時間の予測

予測完了時刻 = 経過時間 + 直前の反復にかかった時間 × 倍率

| 今の反復 → 次の反復 | 倍率 |
|---|---|
| どれでも → なし（最後の反復） | 予測しない（止めない） |
| 中盤 d → 中盤 d′ | 直近2つの中盤反復の時間の比を2手あたりに直し、1.5〜6に収めて `(d′−d)/2` 乗する。比が分からないとき（最初の反復など）は2手あたり3 |
| 中盤 → 最初の終盤ステージ（ENTRY） | `max(2, 5 × 1.06^(空き−24))`。20空きで約4、28空きで約6.3 |
| 選択的ステージ → 完全読み（EXACT） | `max(1, 3 × 1.15^(空き−22))`。20空きで約2.3、26空きで約5.2 |
| 中盤 → 完全読み（選択的ステージなし） | ENTRY × EXACT |
| 選択的ステージ → 次のステージ | 1.25 |
| 終盤 → 中盤（起きないはず） | ENTRY |

ENTRY と EXACT は、置換表が空のとき（probe、1・4スレッド）と対局中（GTP ログ）に測った比の中央値に合わせてある（`docs/benchmarks/2026-11-20-time-control-forecast/ratios.txt`）。

### 5.2 止める条件

```
不安定度 = 最善手が変わった反復のあとは 1、変わらなかった反復ごとに半分
目標     = min(soft × (1 + 不安定度), hard)
予測完了時刻 > 目標 なら、ここで止める
```

- 最善手が変わった直後は、目標が最大で soft の2倍（ただし hard まで）に延びる。その後は確認の反復ごとに延長が半分になる（2倍 → 1.5倍 → 1.25倍 …）。
- 止めたときは、ストップハンドル（Ctrl-C と同じ仕組み）で止め、理由を `StopReason::TimeLimit` として返す。
- 倍率は中央値なので、半分ほどの反復は予測より重い。soft と hard のあいだの余裕が、その上振れを受け止める。

### 5.3 例（26空き、20秒対局の中盤、soft 1.2秒・hard 2.4秒）

| 終わった反復 | 経過 | かかった時間 | 次 | 予測完了 | 目標 | 判断 |
|---|---|---|---|---|---|---|
| d16 | 0.10秒 | 0.06秒 | d18 | — | 1.2秒 | 続ける |
| d18 | 0.25秒 | 0.15秒 | d20 | 0.25 + 0.15 × 2.5 = 0.63秒 | 1.2秒 | 続ける |
| d20 | 0.60秒 | 0.35秒 | e85 | 0.60 + 0.35 × 5.6 = 2.57秒 | 1.2秒（最善手が変わっていれば 2.4秒） | 止める（d20 の手を打つ） |

中盤から終盤の最初のステージへは時間が約5倍に跳ねるので、届くかどうかはここで決まる。届かなかった e85 は、次の自分の手番（24空き）で使える。

## 6. hard での打ち切り

`hard` はエンジンに渡す時間制限でもある。予測が外れて反復が `hard` までに終わらないと、エンジンは途中の反復を捨てて、最後に終わった反復の結果を返す。捨てた反復の時間は無駄になる（20秒・1スレッドの対局で、持ち時間の約0.5%）。

## 7. 特別な場合

- **hard = 0**（残り時間がマージン以下）：`reflex` で2手読み（`Goal::Depth(2)`）をして打つ。数マイクロ秒で終わる。合法手の先頭を打つより悪手が減る。
- **合法手が1つ**：探索せずに打つ（GTP・FlipSight とも）。
- **定石**（FlipSight）：定石にある局面では探索しない。
- **時間切れ**：評価対局（9条件・2,628局）では0件。

## 8. 一局の中で実際に起きること

評価対局の GTP ログ（1スレッド、`0c53a14`）から集計した。

### 8.1 時間をかけている場所（一局の持ち時間に占める割合）

| 空き | GTP 2秒 | GTP 20秒 | GTP 60秒 |
|---|---|---|---|
| 60〜45 | 21% | 24% | 24% |
| 44〜37 | 25% | 27% | 30% |
| 36〜31 | 18% | 20% | 24% |
| 30〜27 | 12% | 19% | 16% |
| 26〜23 | 14% | 10% | 6% |
| 22〜19 | 10% | 1% | 0.5% |
| 18以下 | 1% | 0.1% | 0% |

中盤（44〜27空き）に約6割をかける。1手あたりの時間は 45〜27空きでほぼ一定（20秒対局で1.1〜1.7秒）。26空き以下では、すでに完全読みに届くので短くなる。

### 8.2 どこまで読めているか（その手番の最後の反復で多いもの）

| 空き | GTP 2秒 | GTP 20秒 | GTP 60秒 |
|---|---|---|---|
| 30 | 中盤 d15〜d17 | d23 / e85 | e95 / e85 |
| 28 | d15〜d17 | e95 / e85 | e99 |
| 26 | d16〜d20 | e99 / e98 | 完全読み 69% |
| 24 | d18 / e85 | 完全読み 64% | 完全読み 91% |
| 22 | 完全読み・e99・e85 が半々 | 完全読み 91% | 完全読み |
| 20 | 完全読み 86% | 完全読み | 完全読み |

### 8.3 時計の監査（`tools/time-control/audit.py`）

- 終局時に残る時間：1スレッドで持ち時間の8〜10%、4スレッドで16〜17%。ほぼすべてが、最初の完全読みが終わった時点でもう残っている。
- 予約（3.2）は、実際に完全読み以降で使った時間の約4倍。
- 中盤の手番の使用時間 / soft の中央値は 0.67。中盤の手番の98%は `Forecast` で止まっている（hard まで行くのは2%）。

## 9. この方式の評価

### 9.1 対局（`docs/benchmarks/2026-11-20-time-control-forecast/`）

`Forecast` を入れる前の `a21b8c9` との比較では、9条件のうち GTP 2秒・1スレッドだけが +0.10石 [+0.01, +0.18] で、ほかは信頼区間が0をまたぐ。捨てた時間（6章）は 5.0% → 0.5% に減った。

### 9.2 打ち切り方は最適に近いか（`docs/benchmarks/2026-11-20-time-stopping-oracle/`）

各反復の完了時刻が分かっている（予測が正確な）シミュレーションで、理論上最適な形の規則と比べた。

- 比べた規則は「この先のどこかまで読むと、1秒あたりの期待される損失の減りが、一局共通のしきい値以上になるなら続ける」もの。
- 結果、差は見分けられなかった（10局面あたり −0.09〜+0.03石、どれも信頼区間が0をまたぐ）。
- 最善手が変わったときの延長をなくすと、悪くなる傾向があった。

予測が正確なら、今の打ち切り方（均等額 + 最善手の変化での延長）は、ほぼ最適と区別できない。

### 9.3 損失の表（`docs/benchmarks/2026-11-20-time-allocation-loss-table/`）

24〜28空きで終盤の最初のステージ（85%〜95%）に届くと、1手あたり0.2〜0.35石の得がある。完全読みまで届いても、それ以上の得はほぼない。表から計算した配分は、交差検証で今の配分との差が見えなかった。

### 9.4 分かっている弱点

- **予約が多すぎる**：約4倍。終局時に時間が余る主な原因。ただし、予約を減らした版（`5339c14`）や、スレッド数で割った版は対局で負けたことがあるので、変えるなら対局で確かめる。
- **中盤の時間の予測は誤差が大きい**：空き数と深さで条件を付けても、対数の標準偏差は0.62。さらに、直前の比が大きいと次の比は小さくなる傾向がある（傾き −0.39）。今の「直前の比をそのまま使う」予測は、この傾向を考えていない。
- **短い持ち時間では終盤の最初のステージに届かない**：2秒対局の24〜28空きでは、中盤の探索で終わることが多い。
- **スレッド数を見ていない**：倍率も予約も1スレッドの値。4スレッドでは終局時の残りが多い（16〜17%）。
