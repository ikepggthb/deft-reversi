shrink を入れた理由と、v3 評価関数の 3 つの問題・修正解説

旧学習器（8cc381a / v3 モデル）で起きていた重みの壊れ方と、現行学習器（e17e889 / v4 対応）での解消方法を図解でまとめます。

目次
  1. なぜ shrink をつけたのか？
  2. 対策①：線形と PEN の ±25 石綱引き → 中心化（recenter）
  3. 対策②：鏡像非対称 → 学習時からの重み・埋め込み共有
  4. 対策③：合法手数差の両端 0 落ち → 隣接アンカー補間・外挿
  5. まとめ比較（Before / After）と奇数-偶数差への効果

基礎 1. なぜ shrink をつけたのか？

パターン評価には、1 フェーズあたり 298,161 個 のパターン状態（10 マスのパターンは 3¹⁰ = 59,049 通り）があります。全データで学習しても、その中には 1〜数回しか出てこない珍しい形 が大量に含まれます。

もし珍しい形がたまたま「+40 石の大勝ち局」に 1 回だけ出た場合、重みはその 1 回の結果（ノイズ）をそのまま覚えてしまい、未知の局面で極端な点数を出してしまいます（過学習）。

書き出し時の重み = 縮小先 + (学習した重み − 縮小先) × n / (n + k)   （n = 出現回数, k = shrink 既定 32）
図1：shrink は「見た回数が少ない重みほど、安全な基準値（縮小先）へ寄せる」仕組み。
ここが落とし穴だった！ shrink 自体は「希少パターンの過学習を防ぐ」ための正しい仕組みです。
しかし旧学習器では 「どこに向かって縮めるか（縮小先）」がズレていた ため、次の対策①と対策③のバグを引き起こしました。

対策① 2. 線形と PEN の ±25 石綱引き → 中心化（recenter）

評価値は バイアス + 線形パターン(44個) + 合法手数差 + PEN出力 の合計です。すべての局面で同じ個数の重みを足すため、線形テーブル全体に +25 石、PEN 全体に −25 石を足しても合計の予測値は変わりません。AdaGrad と Adam を同時に回すうち、実際に石数 41〜56 で ±25〜31 石もの綱引き が起きていました。

図2：予測値を一切変えずに各テーブルの平均を bias（定数項）へ移すことで、shrink 先が常に「平均的な状態」になる。

旧学習器の問題

  • 線形表の平均が 0 から大きくズレたまま 0 へ縮小していた。
  • PEN の平均出力が ±25〜31 石までドリフトしていた。
  • PEN 埋め込みを誰も残っていない初期値 0.125 へ縮小していた。

新学習器の修正内容

  • PhaseWeights::recenter()：各表の使用回数重み付き平均を bias へ移動（4 回転分なので 4×平均 を足す）。
  • PenWeights::train()：PEN のエポック平均出力を B2 から linear.bias へ移動（bias 自体は shrink しない）。
  • PenWeights::mean_embeddings()：希少な埋め込みを各表の平均埋め込みへ縮小。
実装箇所：deft-reversi-train/src/phase.rs（recenter）、deft-reversi-train/src/pen.rs（train, mean_embeddings, export）

対策② 3. 鏡像非対称 → 学習時からの重み・埋め込み共有

リバーシの盤面は「4 方向の回転（0° / 90° / 180° / 270°）」と「左右反転（鏡像）」を組み合わせた 8 通りがまったく同じ価値 を持ちます。エンジンは 4 回転で同じ表を引くため回転対称は保たれていましたが、旧学習器は 左右反転を別々の重みとして学習 していたため、同じ局面でも反転するだけで平均 1 石・最大 5 石ズレていました。

図3：学習中は min(i, mirror[i]) に統合して更新し、書き出し時に両方へ同じ値を展開する（エンジン側は変更不要）。
  • 完全対称化：8 通りの対称形すべてで評価値が完全に一致します（鏡像差：平均 1.03 石 → 0.00 石）。
  • 実質データ量が約 2 倍：同じ重みを左右反転の両方から学習するため、出現回数 n も約 2 倍になり、shrink による減衰も減って精度が上がります。
  • 二重更新の防止：1 つの局面内で同じ共有スロットが複数回読まれた場合は、勾配を合計してから 1 回だけ AdaGrad 更新します（PEN 埋め込みも同様に対応）。
実装箇所：deft-reversi-engine/src/evaluation/mod.rs（mirror_weights）、deft-reversi-train/src/phase.rs（shared_weights, export）、deft-reversi-train/src/pen.rs（backward, export）

対策③ 4. 合法手数差の両端 0 落ち → 隣接アンカー補間・外挿

合法手数差（自分の合法手数 − 相手の合法手数）は、差が大きいほど自分の有利（または不利）を表す単調なテーブルです。ところが旧学習器では、出現回数の少ない両端（差 ±15〜±20 以上）も一律 0 へ shrink していたため、大有利なはずの局面で突然 0 点に落ちる「崖」 ができていました。

図4：mobility_targets() により、出現回数の少ない端のビンは「0」ではなく「最も外側の信頼できるアンカーの値」に向かって縮小する。
  • アンカーの選定：出現回数が shrink（既定 32 回）以上のビンを「信頼できるアンカー」とする。
  • 外側の領域：最も外側のアンカーの値をそのまま縮小先にする（崖が消える）。
  • アンカー間の希少ビン：両隣のアンカーを結ぶ直線（線形補間）を縮小先にする。
実装箇所：deft-reversi-train/src/phase.rs（mobility_targets, export）

まとめ 5. Before / After 比較と奇数-偶数差への効果

項目 Before（旧学習器 8cc381a / v3） After（新学習器 e17e889 / v4 対応）

鏡像（左右反転） 別々に学習。左右反転だけで平均 1.03 石・最大 5.04 石ブレる。 代表スロット min(i, mirror[i]) を学習時から共有。8 対称すべてで差 0.00 石。
合法手数差の両端 出現回数の少ない端が 0 に急落（10 石以上の不連続な崖）。 信頼できる隣接アンカーから線形補間・水平外挿した値へ shrink し、崖を解消。
