# 小型 NNUE バリアント実験(2026-07-13〜14)

web(WASM)配布用の軽量 NNUE 選定のため、回転重み共有・accumulator 幅・パターン集合・
残差学習の4軸を1変数ずつ切り分けて 9 構成を比較した記録。
図: `size_vs_mae.{svg,pdf}`(サイズ vs 精度)、`mae_by_empties.{svg,pdf}`(空きマス数別、
NNUE代表4構成+パターン評価2種。パターン評価の曲線は別実験の eval-mae 計測で、
評価局面の分母が近いが厳密には別サンプルである点に注意)、
生データ: `results.csv`、各 run: `runs/small-*/`。

## 共通条件

- データ: `egaroucid_rd_data_set`(残差 run は `egaroucid_rd_residual_data_set`)
- 予算: 100M サンプル(フェーズ均等)× 8 epochs、batch 8196、cosine LR(lr 4)、GPU
- 指標: 学習スクリプトの valid MAE(200,000 局面)。v2 の 4.517 と同一の物差し
- S 系は対称性拡張8変換、R 系(残差)は回転4変換のみ(旧 eval.json が鏡映非厳密不変のため)
- 残差 run の MAE は「旧パターン評価 + NNUE」合成系の最終 MAE

|---|---|---|---|---|
| v2 | 非共有 / フル / acc256(基準) | 499MB | 4.517 | 4.116 |
| S1 | 共有 / フル / acc256 | 127MB | 4.482 | 4.078 |
| **S2** | **共有 / フル / acc128** | **65MB** | **4.479** | **4.069** |
| S3 | 共有 / フル / acc64 | 35MB | 4.602 | 4.201 |
| S4 | 共有 / corner2×5削除 / acc128 | 33MB | 4.574 | 4.186 |
| S5 | 共有 / 3^10全削除 / acc128 | 17MB | 4.630 | 4.254 |
| S6 | 共有 / 3^10全削除 / acc64 | 9MB | 4.740 | 4.379 |
| R1 | 残差 + フル / acc256 | 127MB(+土台36MB) | 4.820 | 4.482 |
| R2 | 残差 + 3^10全削除 / acc64 | 9MB(+土台36MB) | 5.048 | 4.736 |

`2026-07-nnue-v2-vs-pattern` 参照。指標の分母は近いが厳密には別サンプル)。

## 主要な結論

1. **回転重み共有は「タダより良い」**: S1(127MB)= 4.482 < v2(499MB)= 4.517。
   テーブル 1/4 で精度が +0.035 改善。パラメータ共有により各パターン状態の実効
   出現数が4倍になるサンプル効率の利得が、表現力の理論的損失を上回った
2. **acc 256→128 はコストゼロ**(4.482→4.479)。**崖は 128→64**(−0.12)。
   PSQT 直行ルートが線形成分を担うため accumulator 幅には余裕がある
3. **パターン削減のコスト**: corner2×5 で −0.095、edge+2X でさらに −0.056。
   同サイズ比較(S3 35MB vs S4 33MB)では「パターンを削って acc を残す」方が僅かに得
4. **残差学習(既存パターン評価+NNUE)は全面的に不採用**: 同一 NNUE サイズの直接学習に
   全域で大敗(R1 4.820 vs S1 4.482)。土台が得意な石数24+ に絞っても差はむしろ拡大
   (4.482 vs 4.078)。土台の情報は NNUE が自前で表現できる一方、残差ラベルは土台の癖
   (鏡映非対称・手番バイアス)を含みフィットしにくい。鏡映拡張を失う点も不利
5. **パレート前線**: S6(9MB)→ S5(17MB)→ S4(33MB)→ S2(65MB)。
   9MB でもパターン評価単体を約0.9石上回る

## 推奨

- **ネイティブ / デスクトップ**: S2(共有・フル・acc128、65MB)。v2 より小さく速く強い。
  現行採用中の v2(514MB bin)からの置き換え候補
- **web**: サイズ予算次第で S4(gzip 推定 ~13MB)か S5(~7MB)。最安なら S6(~4MB)
- 残差方式・acc64(フルパターン)は非推奨

## 再現

- 学習基盤: `train_nnue_torch.py` の `--acc-size / --pattern-set / --share-rotations /
  --augment-rotations-only`(デフォルトは v2 完全互換)
- 残差データ生成: `cargo run -p deft-reversi-train --release -- annotate-residual
  --eval data/eval/eval.json --data egaroucid_rd_data_set --out egaroucid_rd_residual_data_set`
- キュー: `tools/small_variants_status.sh`(進捗)、実行スクリプトは各 run の
  `logs/stdout.log` にコマンドライン記録あり
- 図の再生成: `python3 docs/experiments/2026-07-nnue-small-variants/make_graph.py`

## 推論速度ベンチ(2026-07-14、エンジン S2 対応+AVX2 SIMD 後)

同一 260,000 局面(phase 12..63 × 5,000)を `evaluate_board_slow` で評価。
ロード時間は分離済み。SIMD は accumulator 構築のみ(pairwise/dense はスカラーのまま)。

| 構成 | µs/eval | evals/sec | 対パターン比 |
|---|---|---|---|
| パターン評価 | ~0.12 | ~8.7M | 1x |
| v2(scalar) | 13.0 | 77k | ~110x遅 |
| v2(SIMD) | 9.8 | 102k | ~80x遅 |
| S2(scalar) | 5.3 | 189k | ~44x遅 |
| **S2(SIMD)** | **4.4** | **227k** | **~37x遅** |

- S2+SIMD で現行 v2 比 **2.2倍高速**(9.8→4.4µs)。精度も上(eval-mae 4.495 vs 4.540)
- パターン評価の計測値はレコードパース込みのため実際はさらに速い(計測ノイズ域)
- 残りの主要高速化は**差分更新**(触る重み行数を 1/10〜1/20 に)。実装すれば
  サブµs域=パターン比 5〜10 倍が見込み
