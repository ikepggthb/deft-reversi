# FFO 40〜59：PEN と Edax・Egaroucid（2026-11-06）

[PEN](../2026-11-06-pen/README.md) のモデルで、完全読みの速さが変わるかを確かめた。

## 条件

```sh
python3 run.py 2 ../2026-11-01-ffo-engines/ffo40-59-answers.obf .
```

[前回](../2026-11-03-ffo-engines/README.md)と同じ。

- 1スレッドで、CPU 2 に固定した。1問ごとに新しいプロセスで解いた。
- エンジンの順番は、問題と回ごとに回した。2回測り、中央値をとった。
- 機械は i3-14100（このマシン）である。
- 答えは、すべて FFO の正解と一致した。
- Deft のエンジンは 3222ab6 で、`-Ctarget-cpu=native` を付けてビルドした。モデルだけを替えた。
  - **deft-pen**：PEN のモデル。MPC は1空き数あたり250局面で校正した。
  - **deft-linear**：PEN と同じデータで学習し直した線形のモデル。MPC は同じく250局面。
  - **deft-release**：今の Release のモデル（線形、1,000局面で校正）。
- Edax 4.5.5・Egaroucid 7.8.1 は、前回と同じ設定である。
- 結果は [results.tsv](results.tsv)（全部の解）、[summary.txt](summary.txt)（問題ごとの中央値とノード数）にある。

## わかったこと

- **3つの Deft は、合計でほぼ同じ速さ（276〜278 s）だった。** Edax（310.9 s）より約11%、Egaroucid（288.3 s）より約4%速い。
- **PEN は、ノード数が約10%少ない**（124億、線形は138億）。評価1回が遅い分と打ち消し合い、時間はほぼ同じになった。
  - 完全読みでは、空き13以下の大部分のノードで評価を使わない。評価を使うのは、手の並べ替えと MPC の判定だけである。そのため、中盤のような1.9倍の差は出ない。
- **問題によって、速くなるものと遅くなるものがある。**
  - 速くなった問題：49（3.1 → 2.4 s）、54（39.7 → 36.5 s）、57（25.0 → 24.6 s）、58（19.7 → 17.6 s）。
  - 遅くなった問題：48（1.4 → 2.0 s）、50（9.9 → 12.1 s）、52（3.1 → 3.8 s）、53（24.4 → 26.2 s）。
  - 空き28〜30の重い問題（53〜58）では、合計が 250.6 → 247.5 s と少し速く、Egaroucid（254.9 s）を下回った。
- **前回の Deft の弱点だった問題57・58は縮まった。**
  - 前回は 31.3 s・25.4 s で、Edax・Egaroucid の1.3〜1.6倍だった。
  - 今回の PEN では 24.6 s・17.6 s になった。58 は Egaroucid とほぼ同じである。57 は、まだ Egaroucid・Edax の約1.24倍かかる。
- **deft-release は、前回の Deft（300.7 s）から 277.8 s に速くなった。** これはエンジンの変更による（中盤の切り替えの深さと、ProbCut の事前判定 c40fbb0、ゼロ窓だけで MPC を試す変更 7dd1aad）。
- MPC の局面数（250 と 1,000）の違いは、合計の時間にはほとんど出なかった（deft-linear 276.4 s、deft-release 277.8 s）。
