# 中盤MPC 79・81・83・85・87%の総当たり

100 ms／手、5候補の全10組。同じ100開局を全組で共有し、各開局を先後入替で2局、各組200局、合計2,000局。各候補は800局。

> 2026-11-15 追記：ここで使った `tools/bench/mpc_match.py`・`mpc_report.py`・`mpc_detailed_report.py`・`mpc_sigmas.py` と実験用GTPのオプション（`--mid-sigma` など）は 2026-11-14 に削除した。当時のコードは各測定フォルダの `source.diff` にある。任意の確率は「85%段の中盤の倍率を置き換える」方法で実現していた。今のエンジンの段は 83/85/95/98/99/100% で、83%はモデルの校正が持つ倍率（ここで採用した 1.2691755）を使う。68%・77%は選べない。各手のログ（`logs/`、`pilot/logs/`、`pilot-final/logs/`）は git で管理せず、手元の `local/bench-runs/docs-raw/2026-11-09-midgame-mpc-79-87/` に置いた。

## 探索条件

- XOTの8手後（空き52）から開始。単一スレッド、TT 64 MiB、CPU 2で逐次対局。
- 各着手で深さ1から1ずつ反復深化。深さが空き数に達する反復は、中盤探索の代わりに終盤99%、続いて100%を実行する。
- 中盤反復と終盤の両段階が、同じ100 msの締切とTTを共有する。反復間・着手間・終盤への移行時にTTを消去しない。各対局ではエンジンを新規起動する。
- 完了した最後の反復を採用する。99%が未完了なら直前の中盤結果、100%が未完了なら99%の結果。100%完了だけを完全読み完了と数える。
- 旧実験の「空き18以下で別リクエスト・25 ms・移行時TTクリア」は使用しない。各着手で同じ反復予定を使い、移行を別の着手へ永続する設定はない。
- 終盤99%は完全読みより前の選択的探索。本比較では、中盤で終局深さを読むより精度が高いと仮定する。終盤の校正値は候補間で共通とし、中盤用の値を適用しない。
- 候補の中盤校正値は、現行モデルと一致する校正局面の実測誤差分布から算出。85%はモデルに収録された値と一致する。他の中盤ステージ・終盤の校正値は変更しない。

時間制限は探索内の定期チェックで検出するため実時間に超過がある。探索時間と外側時間の両方を記録する。進捗通知のテレメトリ生成も予算内で、全候補で共通。

## 開局・集計

開局は、XOT大リスト（`tools/bench/positions/xot-openingslarge.txt`）を seed 5 で並べ替え、先頭から順に、[2026-11-08-midgame-mpc](../2026-11-08-midgame-mpc/README.md) の各測定で使った開局（254局面）と MPC 校正に使った空き52の局面（合わせて695局面）に当たらず、それまでに選んだものとも重ならないものを100個取った。局面の比較は盤面の対称形（回転・鏡映）を同一視する。選んだ開局は [xot-100.txt](xot-100.txt)、件数は [opening-selection.json](opening-selection.json)。選定に使ったスクリプトは手元（`local/bench-runs/mpc-79-87-20261109/`）にある。候補の順序と先に実行する色を開局ごとに回す。pilotは動作確認のみで、順位の集計に加えない。

得点率（勝1・分0.5）、対戦相手別成績、開局単位の95%ブートストラップ区間を集計する。時間・完了深さの最小・最大・平均・中央値、終盤99%／100%の完了件数も記録する。中盤結果と終盤結果の着手の構成比が候補ごとに異なるため、全着手の統計も併記する。

この結果は100 msという条件での比較であり、長時間や各レベルにおける最適性の証明にはしない。
