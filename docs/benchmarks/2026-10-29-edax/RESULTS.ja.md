# 最新DeftとEdaxのFFO40–49比較

## 比較対象

- **Deftリモート版**: `527c906`をそのままビルド。同じ公開API計測adapterだけ追加。
- **Deft統合版**: `eb76a8f`。手元のSIMD盤面等を残した現在の作業ブランチ。実験featureは既定OFF。
- **Edax 4.5.5**: 配布`lEdax-x86-64-v3`。従来の比較対象を同時期に再測定する。
- **Edax 4.6 native**: ローカルのtracked source `713a434f13b3d15fb69c61b9ba3641aed82c496c`を`git archive`で一時ディレクトリへ展開してビルド。既存の`native`名のsymlinkからコンパイル条件を推測しない。元checkoutの未追跡ファイルは使用・変更しない。

4.6はClang 23.1.4、`make CC=clang BUILD=optimize build ARCH=native`で生成した。主要フラグは`-O3 -flto -ffast-math -fomit-frame-pointer -DNDEBUG -march=native`。DeftはRust 1.99.1、release、fat LTO、`-C target-cpu=native`。異なる言語・コンパイラの通常エンジン比較である。

## 条件

FFO40–49、CPU1（Core Ultra 7 265KのPコア）固定、1スレッド、時間・ノード制限なし、各局面新規プロセス・空のTT、各条件3回。4条件×10局面×3回＝120run。実行順は4通りのローテーションを使用し、各条件の位置は7/8回となる。完全に均等な配置とは称さない。

Deftは同じeval-v4.binとそのMPC設定を直接読み込み、通常`Engine.solve(board,60)`を実行する。主TT256MiB、PV表16MiB。Edaxは付属eval.datを読み、`-l 60 -n 1 -h 23 -book-usage off`を使用する。`-h 23`はMiBではなく項目数の指数であり、Deftと同じ総メモリ量とは主張しない。評価関数とMPC・手順付けはエンジン間で異なる。同一評価関数の探索カーネルだけの比較ではない。

主指標は各局面3回の探索時間の中央値の合計。Deftは`SearchResult.elapsed`、Edaxは結果行の内部探索時間（ms精度）を使う。起動・モデル読込・外側の検証時間は含めず、探索内の初期化と準備探索は含める。プロセス全体の経過時間は別項目で保存する。計測中にビルドやテストを行わない。

全結果を公式スコアと照合する。DeftはExact/Completed/nonselectiveと合法なPV・終局値を検証する。Edaxは最終深さが空き数と一致し、選択率の省略された完全読みの結果であることを確認する。Edaxの表示PVは部分手順の場合があるため、完全な終局PVを検証したとは扱わない。

同じ測定群で4条件を取り直し、過去の時間や別CPU・別モデルの時間との引き算で改善率を作らない。検証・ビルド・計測はLunaが担当する。詳細なbinary/source/model/input hash、ビルドコマンド、全実行ログはこのディレクトリに保存する。

## 結果

| 条件 | 局面別中央値合計 |
|---|---:|
| Deftリモート版 (`527c906`) | 10.251324秒 |
| Deft統合版 (`eb76a8f`) | 10.194934秒 |
| Edax 4.5.5 配布x86-64-v3 | 10.465000秒 |
| Edax 4.6 native (Clang 23.1.4) | 13.669000秒 |

手元の試作を含まないリモート版で、Edax 4.5.5より合計約2.04%短かった。局面別では6局面で短く、4局面で長かった。ただし各3回の小差であり、全局面・全環境での明確な優位とは断定しない。Edax 4.6 nativeはこの版・ビルド・評価データの組合せで4.5.5配布版より長かった。新しい版やnative指定なら必ず速い、あるいは4.6全般が遅いとは扱わない。コンパイラ差・実装差を一つずつ切り分けた比較でもない。

統合版とリモート版の差も約0.55%に留まり、手元機能を残す性能上の決め手とはしない。今回の主比較のDeftはリモート版として読む。
