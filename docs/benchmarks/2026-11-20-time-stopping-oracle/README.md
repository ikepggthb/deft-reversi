# 打ち切り規則のシミュレーション（予測が正確な場合、2026-11-20）

> develop/v2 には `tools/time-control/` を入れていない。ここに出てくるツールは `research/time-predict`（commit 9238780）または `ccr-a29b8244-tag4vo` にある。

各反復がいつ終わるかを前もって知っているとする（時間の予測が正確な場合）。その条件で、今の `game_clock`（1手ごとの目標時間と、最善手が変わったときの延長）が、損失（最善手より何石損か）の合計を最小にする打ち切り方になっているかを調べた。比べる相手は、理論上の最適な形である「価値÷時間」の規則である。

## 結論

- **今の方式より良い打ち切り方は見つからなかった。**
  - 価値÷時間の規則と今の方式の差は、10局面あたり −0.09〜+0.03石だった。
  - どの持ち時間でも95%信頼区間が0をまたぐ（下の表）。
  - 1手あたりに直すと、あっても0.01石程度。
  - 64局のときは −0.22/−0.25石に見えたが、264局にすると半分以下になった。
- **最善手が変わったときの延長（instability）には効果がある。**
  - 延長をなくすと、1.5〜10秒で +0.06〜+0.12石悪くなった。
  - 価値の規則から最善手の変化の履歴を除くと、4秒で +0.13（SE 0.06）悪くなった。
  - 価値の予測に効いている情報（最善手が変わった直後は、次の反復で損失が大きく減る）を、今の方式は延長として取り込めている。
- したがって時間管理の改善は、打ち切り規則ではなく予測の精度（`2026-11-20-time-control-forecast` の監査で見えた予約の過大さなど）の側で考えるのがよい。

## 方法

| 項目 | 内容 |
|---|---|
| 局面 | 264局 × 10局面（空き 48, 44, 40, 36, 32, 28, 26, 24, 22, 20）。64局は `2026-11-20-time-allocation-loss-table` のデータ（seed 12）。200局をこの記録で追加した（`deft-reversi-cli self-play -l 8 --random 8 --seed 13`、`games.txt`） |
| 反復の時間と手 | `tools/time-control/probe`：置換表を空にして `timed_levels(60, 6s)`、1スレッド（`probe.txt`） |
| 参照 | `refer`：28空き以下は完全読み、それより多い局面は深さ26・MPC 85%（`reference.txt`）。中盤は深さ22より深い反復を使わない |
| 規則 | `tools/time-control/oracle.py`。反復の完了時刻は既知なので、どの規則も終わらない反復は始めない。違いは打ち切る位置だけ |
| 持ち時間の合わせ方 | 各規則のパラメータ（目標時間の倍率 c、または λ）を、学習側の局で1局あたりの平均時間が指定の秒数（probe の秒数）になるよう二分探索で決める。偶数番の局で決めて奇数番の局で評価し、逆も行う。差は評価側の局の対応のある差で、SE は局ごとのばらつきから出した |

比べた規則：

| 規則 | 内容 |
|---|---|
| current | 今の方式。目標 = c × soft(空き)。soft の空き数ごとの形は、`2026-11-20-time-control-forecast` の GTP 20秒対局（新）のログの中央値から取った。次の反復が min(目標 × (1 + instability), 2 × 目標) までに終わるなら始める。instability は最善手が変わると1、変わらなければ半分 |
| flat | current から instability を除いたもの |
| value | 価値÷時間。ある先の反復までの「期待される損失の減り ÷ そこまでの時間」が λ 以上なら続ける。期待される減りは学習側の局での平均で、反復の種類（中盤の1段、終盤の最初のステージ、終盤の次のステージ）で分ける。次の1段だけは、直近2反復で最善手が変わったかどうかでも分ける |
| kind | value から最善手の履歴を除いたもの |

```sh
B=tools/time-control/probe/target/release
deft-reversi-cli self-play -l 8 --random 8 --seed 13 -o games.txt 200
$B/probe games.txt 6 48,44,40,36,32,28,26,24,22,20 25 1 SKIP > probe.txt   # 8プロセス、SKIP=0,25,..,175
DEFT_MODEL=... $B/refer games.txt probe.txt 26 1 > reference.txt            # 分割して並列に
# 64局のデータと合わせ、こちらの局番号に1000を足してから
python3 tools/time-control/oracle.py probe.txt reference.txt GTP20_LOG_DIR/new-*.log -- 1.5 4 10 20
```

## 結果（`oracle.txt`）

10局面あたりの損失の合計（石）。評価側の局での平均。「差」は current との差（負が良い）と標準誤差。

| 持ち時間（probe 秒/局） | current | flat | kind | value |
|---|---|---|---|---|
| 1.5 | 2.49 | 2.62（+0.12, SE 0.10） | 2.51（+0.02, SE 0.10） | 2.41（−0.09, SE 0.10） |
| 4 | 1.85 | 1.91（+0.06, SE 0.06） | 1.98（+0.13, SE 0.06） | 1.77（−0.08, SE 0.07） |
| 10 | 1.20 | 1.28（+0.08, SE 0.05） | 1.29（+0.09, SE 0.06） | 1.12（−0.08, SE 0.05） |
| 20 | 0.78 | 0.77（−0.01, SE 0.01） | 0.81（+0.03, SE 0.01） | 0.81（+0.03, SE 0.02） |

## 限界

- 価値の予測に使った情報は、反復の種類と最善手の変化の有無だけ。評価値の変化量や合法手の数などを使えば、価値の規則はもっと良くなる可能性がある。
- 中盤は深さ22で打ち切っている（参照が深さ26のため）。深い中盤の価値は測れていない。
- probe の時間は置換表が空の状態の値で、対局中（約0.7倍）とは比が少し違う。
- 1局は10局面だけで、実際の対局の約30手番ではない。持ち時間の秒数は対局の秒数と直接は対応しない。
