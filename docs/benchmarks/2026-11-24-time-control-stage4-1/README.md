# 持ち時間制：段階4-1 の一局を通したシミュレーション（その1：時間の予測と、使われない時間／その2：最初の反復の扱い／その3：予約・価値・配分）

時間管理の予測を精度よくする作業（[ロードマップ](../../design/2026-11-20-time-control-roadmap.md)）の段階4-1。今の時計（`game_clock/legacy.rs`）の止める規則はそのままにして、時間の予測を「正解」（その反復に実際にかかる時間）に差し替えたとき、1局で指した手の損失がどれだけ減るかを見た。正解にノイズを足して、どの程度の精度が必要かも見た。あわせて、時計が観測できない最初の反復で使われる時間を調べた。

**これはシミュレーションの結果で、対局での石差ではない。** 改善かどうかは段階4-3と段階5の対局で確かめる。

## 結論

- **時間の予測を全部正解にしても、1局・片方あたりの損失の減りは 0.2 石以下。** 中盤の予測が効く分がほとんどで、ENTRY と終盤のステージ・EXACT の予測は ±0.03 石以内（区間はほぼ0をまたぐ）。中盤の予測の効果の大きさは、ログより先の反復をどう補うかで 0〜0.2 石と変わるので、ここでは決められない。
- **予測の誤差が倍率で 1.3 倍（ln の標準偏差 0.25）くらいまでなら、正解とほぼ同じ。** 誤差が2.7倍（ln の標準偏差 1.0）になると効果は消える。今の予測の誤差は中盤で ln の標準偏差 0.5〜0.9（段階3-1）。
- **最も効きそうなのは、時計の外で使われている時間。** 最初の反復が置換表から深い所で始まって hard までに終わらない手番が、各条件で時間の 10〜15% を使っている。このときエンジンは置換表の手を返すので、その手番の手は時間を使わなくても同じ。この時間を使わずに後の手番に回すと、損失は 0.04〜0.14 石減る。補い方を変えた4通りのどれでも、5条件のうち4〜5条件で区間が0をまたがない（`nowaste`）。ただし、これは「どの手番で最初の反復が終わらないかを前もって知っている」場合の上限。
- **時間切れはどの変種でも0件。**

## 方法（`tools/time-control/sim.py`）

| 項目 | 内容 |
|---|---|
| データ | 段階3-1 の v4 の通常の対局（開局 200〜299、5条件・各200局、両方の色）。各局の片方ずつを、その時計だけで再生する（各条件400）。損失は段階3-2の参照（[記録](../2026-11-24-time-control-stage3-2/README.md)）。どちらも調整用の開局 |
| 再生 | 棋譜は固定。各手番で、時計が反復ごとに次を始めるかを決め、使った時間を残り時間から引いて次の手番に渡す。止めた理由・hard・手番の間のずれ（ログの残り時間の差）はログのとおり |
| 確かめ | 今の時計（Python に写した `legacy.rs`）でログを再生すると、5条件・50,121手番の全部で、使った時間と指した手がログと一致した（`sim.py check`） |
| ログより先 | 時計が止めた反復や、hard で打ち切られた反復の先は、ログにない。完全読みまでの反復の列を、ログの分布から引いて補う：次の反復の種類（ログでは空き数と種類で決まる）、時間（同じ遷移・スレッド数・空き数の、終わった反復の倍率から引く。打ち切られた反復は打ち切りより長いものから）、手の損失（同じ遷移・深さの、ログの (前の損失, 後の損失) の組から）。28空き以下の EXACT は損失0。補い方を変えた4通りを流した（下の表） |
| 最初の反復が終わらない手番 | 時間はどの hard でも打ち切られるとし、手はログの手（損失もログのとおり） |
| 変種 | 時間の予測のうち、中盤・ENTRY・選択的ステージと EXACT・全部を、正解 × exp(σ z) に差し替える（σ = 0, 0.25, 0.5, 1.0。z は反復ごとに固定）。`nowaste`：最初の反復が終わらない手番は、すぐ置換表の手を指す |

### 4. 最初の反復が終わらない手番（`nowaste` の元）

`timed_levels` の `reuse_pv` は、置換表に今の局面の結果があると、その深さまでの反復を飛ばして次の反復から始める。この最初の反復は `Progress` を出す前なので、時計は何も観測できない。hard までに終わらないと、エンジンは置換表の手を返す（`search.rs`：「If time expires in the first uncached iteration, the compatible cached move is a better fallback」）。

| 条件 | 1局・片方あたりの手番 | 1手番の時間 | 全体の時間に占める割合 |
|---|---|---|---|
| GTP 2秒 | 0.85 | 0.22 s | 10.4% |
| FlipSight 6秒 | 0.93 | 0.67 s | 11.8% |
| GTP 20秒 | 0.99 | 2.46 s | 13.2% |
| GTP 60秒 | 1.18 | 7.14 s | 15.3% |
| GTP 20秒・4スレッド | 0.92 | 2.51 s | 13.5% |

この手番の手は時間を使わなくても同じなので、その時間はその手番の手を良くしていない。置換表を温める効果はある（シミュレーションには入っていない）。`nowaste` はこの時間をすべて後の手番に回した場合で、実際の時計は「最初の反復が hard までに終わるか」を予測しなければならない。そのための材料（置換表にあった深さ、前の手番の同じ深さの時間）は今の時計には渡っていない。

## 考察

- 段階2のオラクルの結論（[記録](../2026-11-20-time-stopping-oracle/README.md)）「予測が正確でも、止める規則を変えて得になるとは示せない」と同じ向き。時間の予測をいくら良くしても、今の規則のままでは 1局・片方あたり 0.2 石が上限で、対局で確かめるには、おそらく数千局が要る大きさ。
- ENTRY の予測は、1回の価値が大きい（段階3-2：1.0〜1.4 石）のに、予測を正解にしても 0.03 石しか減らない。ENTRY を始めるかどうかは、予測より soft と hard（配分）で決まっているため。
- 一方、最初の反復が終わらない手番の時間は、予測の精度とは別の問題で、時計が観測できない所で使われている。全体の時間の 10〜15% にあたり、取り戻せれば、どの条件でも予測を正解にするのと同じかそれ以上の効果がある。

## 残った課題

1. **最初の反復の扱い（新しい項目）。** → その2（下）で (b) と (c) を調べた。 時計が最初の反復を予測し止められるようにする案：(a) エンジンが置換表から飛ばした反復を `Progress` で知らせる（公開 API への追加）、(b) 時計が前の手番の記録から最初の反復の時間を予測し、間に合わないなら最初から置換表の手を指す、(c) 最初の反復だけ soft で打ち切る。どれも、実際の対局で確かめる必要がある（段階4-3・段階5）。
2. 4-1 の残り：将来の完全読みの予約（A6）を正解にした場合、価値の予測（B1）、soft と hard の配分（C3）。価値を使う止め方は今の時計にないので、比べるための規則を足す必要がある。
3. 中盤の予測の効果の大きさは、深い中盤の反復の値の実測が足りないので決まらない。延長モードの中盤の判断の後の反復（各条件 122〜385回）を増やすか、参照探索を深くすれば狭まる。
4. 4スレッドの探索時間はばらつきが大きい（同じ局面でも毎回違う）が、シミュレーションはログの1回の値を正解としている。

# その2：最初の反復の扱い（2026-11-24）

その1で見つけた「最初の反復が hard までに終わらない手番」の時間（全体の 10〜15%）を、実際の時計で取り戻せるかを調べた。その1の残った課題の案 (b)（前の手番から予測して、間に合わないなら読まずに置換表の手を指す）と (c)（最初の反復を soft で打ち切る）をシミュレーターに入れて比べた。(a)（飛ばした反復を知らせる）は、飛ばした反復の時間はほぼ0なので、それだけでは予測の材料にならず、ここでは扱わない。

**これもシミュレーションの結果で、対局での石差ではない。**

## 結論（その2）

- **前の手番の記録からは、最初の反復が終わらない手番をよく当てられない。** 前の手番が予測した「次の反復の時間」と今の手番の hard の比で分けると、AUC は 0.73〜0.79。その比が最も大きい区間（予測が hard の 1.6 倍超）でも、終わらない手番は 14〜22%。
- **置換表の手は、最初の反復の手とほとんど同じ。** 前の手番の読み筋から置換表の手が分かる手番で比べると、手が違うのは 1.6〜4.2%（最初の反復が soft の後に終わる手番では 4〜13%）。損失の差は1手番あたり +0.01〜+0.06 石（置換表の手の方が悪い）。
- **案 (c) 最初の反復を soft で打ち切る（`firstsoft 1.0`）は、条件によって割れる。** 時間をそろえて、2秒 −0.10、20秒 −0.09〜−0.11 で、区間は0をまたがない（補い方2通りのうち、2秒は1通りだけ）。FlipSight 6秒、60秒、4スレッドは区間が0をまたぐ。理想の場合（`nowaste`：前もって分かっている）の −0.03〜−0.15 に対して、どの条件でも同じか小さい。
- **案 (b) 前の手番から予測して読まない（`skip`）は、ほぼ効かない。** 区間が0をまたがないのは、5条件×4閾値×2通りの補い方×時間をそろえる／そろえないの80通りのうち7通り（どれも −0.02〜−0.13 石）で、補い方や時間のそろえ方を変えると0をまたぐ。
- **時間切れはどの変種でも0件。**
- **改善とは言えない。** (c) は2条件で区間が0をまたがないが、ほかの3条件ではまたぎ、2秒の結果は補い方による。採用するなら段階4-3の対局で確かめる必要があるが、差は 0.1 石程度で、対局で区別するには数千局が要る。

## 方法（その2）

| 項目 | 内容 |
|---|---|
| 最初の反復が warm | 最初の反復が d7 以上か終盤のステージから始まる手番（d6 以下から始まるのは置換表を使っていない）。終わらない手番は全部 warm |
| 置換表の手 | 最初の反復が打ち切られたときエンジンが指す手。前の手番で相手が読み筋どおりに応じた（`reply_matched`）なら、前の手番の読み筋の3手目。最初の反復が終わらなかった手番で確かめると、読み筋どおりに応じた750手番のうち747で指した手と一致した。読み筋の3手目のうち参照の値がなかった 529局面を追加で参照探索した（`refer-v4/extra-pv`、20プロセスで9分） |
| 置換表の手が分からない手番 | 読み筋が短い（置換表で切れた）か、相手が読み筋から外れた手番。1局・片方あたり 6〜9手番。損失を2通りで補う：`known`（読み筋から分かる手番の (最初の反復の損失, 置換表の手の損失) の組を、同じ深さ・soft の後に終わったかどうかで分けて引く）、`back`（同じ遷移・深さのログの1段の組を逆向きに引く。分かる手番で試すと、置換表の手の損失を1手番あたり 0.01〜0.04 石多めに見積もる。`known` は −0.009〜+0.025 石のずれ。[predict.txt](predict.txt) の最後） |
| `firstsoft K` | warm の手番で、最初の反復を min(K × soft, hard) で打ち切り、置換表の手を指す（打ち切りの遅れは 2 ms とした。ログの hard での打ち切りの遅れは 0.4 ms 以下）。K = 1.0, 1.5 |
| `skip T` | warm の手番で、前の手番の最後の反復が予測した次の反復の時間が T × hard を超えたら、読まずに置換表の手を指す（2 ms）。T = 2, 3, 5, 8。前の手番の予測はログの値（シミュレーションの中の前の手番ではない） |

## 結論（その3）

- **価値（B1）が、ここまでで一番効く。** 今の止め方の「不安定度」を「次の反復で手が良くなるか」の正解に差し替えると、時間をそろえて 1局・片方あたり −0.11（4スレッド）〜−0.47（2秒）石。補い方4通りのすべてで区間は0をまたがない。時間の予測を全部正解にしたとき（その1、0.2 石以下）より大きい。
- **ただし、今の不安定度はこの正解からかなり遠い。** 次の反復で手が良くなるのは反復の 6.7〜8.2%。そのとき今の不安定度が 0.5 以上なのは 29〜37%、良くならないときにも 15〜17% が 0.5 以上になる。同じくらいの精度（当たる率 0.3、外れる率 0.15）の信号に差し替えると、効果は 2秒の −0.07 を除いて消える。当たる率 0.5・外れる率 0.15 で −0.04〜−0.16 石（2秒は補い方4通りすべて、FlipSight・20秒・60秒は3通りで区間が0をまたがない。4スレッドはまたぐ）。
- **予約（A6）は効かない。** 予約の式は、実際の完全読みの時間を多めに見積もっている（中央値で、1スレッドで約1.1〜8倍、4スレッドで約8〜20倍）。予約を正解（その局の実際の時間）にしても、4分の1・半分・2倍にしても、時間をそろえると多くは ±0.1 石以内で区間が0をまたぐ。2秒で半分にすると −0.11 石（補い方4通りすべてで区間が0をまたがない）だが、FlipSight・60秒では悪くなる向きで、条件をまたいでそろった向きはない。
- **配分（C3）は、今より hard を大きくすると悪くなる。** hard の借りる分を 1.5倍・2倍にすると、多くの条件で +0.04〜+0.31 石悪くなる（区間は0をまたがない）。半分にすると 20秒で −0.07 石（補い方4通りのうち1通りだけで区間が0をまたがない）、ほかは0をまたぐ。空き数で重みを付けると、中盤に寄せる（a = +0.5）と 60秒・4スレッドで +0.04〜+0.06 石悪くなり、終盤に寄せる（a = −0.5）と2秒・20秒で −0.07〜−0.11 石だが区間は0をまたぐ。
- **時間切れはどの変種でも0件。**
- **改善と書けるのは「価値の正解・高い精度の価値の信号」だけで、どれもまだ作れていない予測。** 今の時計を直接変えて得になる、と言えるものは、予約・配分の中にはなかった。

| `reserve truth` | 将来の手番の完全読みの予約を、その局の世界での実際の時間（その手番で EXACT を終えるまでの時間）にする。その空き数の手番がない・EXACT に届かないときは式のまま |

## 考察（その3）

- 段階2のオラクルと段階4-1その1は「時間の予測を良くしても伸びない」だった。その3で、伸びしろは「次の反復が手を良くするか」の判断の方にあると分かった。今の止め方は、時間の予測より価値の判断で損をしている。
- ただし、効果は信号の精度に強く依存する。今の不安定度と同じ程度の精度の信号では、ほぼ何も変わらない（0.3/0.15 が今の時計とほぼ同じ損失になるのは、シミュレーターの組み立てが今の時計と矛盾していないことの確かめにもなる）。当たる率を 0.5 に上げ、外れる率を 0.15 以下に保てれば、0.04〜0.16 石。
- 価値の正解は、時計が止めた先の反復では補った値（その1の方法）。4通りの補い方で同じ結果だが、どれも「ログの (前の損失, 後の損失) の組」から引く点は同じ。延長モードで測った止めた先の反復の値（段階3-2）とは合っている。
- 予約の式は実際より大きいが、効かない。`budget` が予約するのは1手番の取り分より安い完全読みだけで、大きさを変えても配分の変わり方は小さいと考えられる（予約の量そのものは測っていない）。
- 配分は今の hard がほぼ上限で、これより借りると悪くなる。今の時計は持ち時間を 85〜92% しか使っていないが、配分や予約を変えて使い切っても、時間をそろえた比較では得にならない（使った時間の分だけ石差が伸びる、とは言えない）。

## 残った課題（その3）

1. **段階4-2：作る予測を決める。** 価値（B1）が最優先。「次の反復で手が良くなるか」を、当たる率 0.5 以上・外れる率 0.15 以下で予測できるかを、ログの特徴量（ロードマップの B1 の欄：最善手の変化、評価値の変化量、反復の種類、空き数、合法手の数、上位2手の差など）で調べる。時間の予測（A1〜A4）と予約（A6）は後回しでよい。
2. 価値の止め方を実際に組むときは、「良くなる確率 × 良くなる量」と「時間」を比べる形にする（今の `soft × (1 + 不安定度)` に差し込むのは、ここでの比較のための仮の形）。
3. 価値の正解の多くは補った値なので、4-3（対局での確かめ）は価値の止め方ができてから。
