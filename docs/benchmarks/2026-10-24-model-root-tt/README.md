## 戻した仕様と実装

### モデルとMPCの読込

`Engine::from_file` / `from_bytes` で、元のv3/v4パターンモデル（JSON / bincode）から評価重み・メタデータ・MPC設定を一緒に読む。モデル変換とsidecar設定は通常利用で不要になった。NNUEは今回の対象外。

元の旧JSONパターンラッパーとDPR2重み形式も互換用途で残す。これらに統合MPC情報がない場合は、元の既定MPC設定を使う。DPR2のsidecarを自動で読む仕様ではない。

対応先: 参照元 `src/file.rs`、新版 `src/model.rs`。新しいファイル形式を増やす変更ではない。

### MPC設定と適用

参照元 `src/search/mpc/config.rs` の深さ表・回帰式・既定係数を移植。`mpc_config()` と `set_mpc_config()` で取得・変更できる。回帰値は事前展開して直接参照するが、元の係数や符号付き偏差を勝手に置き換えない。正でない傾きや非有限な値にはルールを作らない。

選択率は元の68/77/85/95/98/99/100%の7段階（`Selectivity`）。通常窓・ゼロ窓ともMPCを適用し、浅い確認探索ではTTと再帰的なMPCを使わない。`result.selectivity` / `probcut_sigma` で最後に完了した段階を確認できる。

`Engine::solve(board, level)` と `SearchRequest::for_level` は元のレベル1〜60へのクランプ、深さ・選択率・終盤への移行、序盤補正、準備探索のレベル上限を戻した。中盤の各反復は指定された選択率、終盤前の準備は85%。終盤の段階移行は元と同じ閾値。

### ルート探索

参照元 `src/search/solver.rs` の `search_root_eval_window` / `search_root_final_window` / `RootBound` / アスピレーションの安定化を `src/search/root.rs` へ移植した。

- 前段階の最善手を先頭にして次の反復へ引き継ぐ。
- 先頭は通常窓、残りはゼロ窓で調べ、alphaを超える手を読み直す。
- 完全読みでは候補ごとの上下限を保持し、窓を変更した再探索でカット・絞り込みに使う。
- 選択的探索の値は厳密な候補境界として再利用しない。
- 浅い探索では全窓。深い探索では予測値が安定するまで最大10回の安定化反復。
- 強制パスをドライバ開始前に処理。中断時は最後に完了した結果と最善手を保持する。
- 並列時もルートのYBWCを維持し、完了した候補の境界を共有する。

### 置換表の利用

参照元 `src/search/tt_cut.rs` と通常窓PVSを基準に復元した。

- 通常窓でも上限・下限・確定値による即時カットを行う。
- カットしない場合はalpha・betaの両方を絞り込む。
- ETCは通常窓にも適用し、子の表からbetaカット、alpha更新、候補スキップを行う。
- スキップ判定は元のalphaで行い、スキップした手の最大上限も保持する。全手スキップ時に不正な上限を返さない。
- 深さ・探索方式・選択率が一致した境界だけを使用。モデルやMPC設定変更で全表を無効化する。
- 主表とは別に、元と同じ主表の1/16（最低1 MiB）のPV表を復元。通常窓の終盤探索で、条件が一致する表のうち範囲の狭い方を優先する。

## 維持した設計と残る差

検証付き盤面API、型付きの着手・パス・中断結果、差分評価、Context所有の局所表、停止・時刻・ノード上限、常駐ワーカーは維持した。TTのハッシュ・置換方針や共通PVS/NWSの構造まで元と同一にしたものではない。通常窓の確定石判定など、今回の4項目以外にも元と異なる経路が残る。

PV表は戻したが、読み筋は元のように表をたどるだけではなく、必要に応じて候補手が確定値に到達することを検証する。これは既存の完全な合法PVを返す動作を維持するため。復元の探索も時間とノード予算に含める。スコア確定後、PV復元で予算に達した場合は確定スコアを保持し、停止理由と取得済みPVを返す。

設定と制御を復元したもので、選択的探索について全局面の着手・スコアまで元と同一と保証するものではない。今回のFFOは最終段階を100%で完了させて比較している。

## 検証

native releaseでストレスを含む50テスト成功。通常/nativeの全ターゲットClippy、比較ツールのClippy成功。参照元の既存の未使用関数・命名の警告は残す。ログは `tests.log`。

追加した検証: v3/v4バイナリ・JSONから重みとMPC設定を同時に読むこと、レベル境界と序盤補正、中盤の中断結果の選択率、通常窓TTカットの深さ・方式・選択率の分離、両境界の絞り込み、ETCで全手スキップしたときの上限、ルート境界の再探索・反復間リセット。既存の総当たり・PV・予算・選択的探索と完全読みの分離・並列ストレスも通した。

## 測定条件と再現

Intel Core Ultra 7 265K、CPU 1固定、1スレッド、native release、fat LTO、codegen-units=1、panic=unwind。主表256 MiB、PV表16 MiB。両者とも局所表も使う。5周、新旧の実行順を周ごとに逆転。各局面で元のSolverとスレッドを作り直して主表・PV表・TLS表を初期化し、新版もすべての表を消去する。

両方とも同じ `eval-v4.bin` を直接読み、同じ `solve(board,60)` を使う。モデル読込・エンジン生成・表の消去は計時外。準備探索、選択性の段階移行、PVの復元は計時内。係数照合と返却後のPV検証は計時外。測定中にビルドやテストを実行していない。
