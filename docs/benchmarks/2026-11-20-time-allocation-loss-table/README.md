# 持ち時間の配分：損失の表とシミュレーション（2026-11-20）

引き継ぎメモ（`2026-11-20-time-control-handoff`）4章の方法を試した。各手番で探索の反復ごとに「選んだ手が最善手より何石損か」を測り、空き数ごとに「時間 → 期待損失」の表を作る。その表から、一局の総損失が最小になる時間配分を計算する。

## 結論

- **配分を変える根拠は得られなかった。** 表から計算した「最適配分」は、表を作った局面の上では今の配分より1手番あたり合計0.7〜1.8石よい。しかし、半分の局面で配分を決めて残り半分で確かめると、差は −0.00〜+0.47石（正の値は最適配分の方が悪い、標準誤差 0.31〜0.85）だった。差の大部分は表のノイズへの当てはまりで、空き数あたり64局面ではこの程度の差を見分けられない。数十分の1石の差を見分けるには、空き数あたり数千局面が必要になる。
- **はっきりしたこと**（20〜28空き、各64局面）：
  - 最後の中盤反復の平均損失は 0.34〜0.51石。終盤の最初のステージ（85%）で 0.06〜0.19石、95% で 0〜0.03石に下がる。
  - 98%/99% → 完全読みで、損失はそれ以上減らない（20〜28空き、完全読みまで終わった局面で0）。
  - 中盤（32〜48空き、深さ26の探索を参照にした）では、d14 から d22 まで読み進めても1手あたりの損失は 0.1〜0.15石ほどしか下がらず、反復ごとの差は誤差の範囲だった。
- したがって、24〜28空きで終盤の最初のステージ（85%〜95%）に届くことには価値がある。完全読みに届くかどうかは、指し手の質にはほぼ影響しない。統合版の `Forecast` が完全読みを次の手番に回し、終局時に時間が余ることの実害は小さい。

## 方法

| 項目 | 内容 |
|---|---|
| 局面 | `deft-reversi-cli self-play -l 8 --random 8 --seed 12` の96局のうち先頭64局（`games.txt`）。各局から、空き 48, 44, 40, 36, 32, 28, 26, 24, 22, 20 で手番側に合法手がある最初の局面。評価用の XOT 開局とは無関係 |
| 探索 | `tools/time-control/probe`：置換表を空にして `timed_levels(60, 6s)`、1スレッド、P コア1つずつ（`probe.txt`） |
| 参照 | `tools/time-control/probe/src/bin/refer.rs`：28空き以下は完全読み、それより多い局面は深さ26・MPC 85% の探索。制限なしで探索して最善手と値を出し、どれかの反復が選んだ他の手は `root_moves` で1手ずつ同じ探索をした（`reference.txt`）。中盤の参照は真の値ではないので、深さ22より深い反復は表に入れていない |
| 損失の表 | `tools/time-control/losses.py reference.txt -- probe.txt`（`losses.txt`） |
| 配分 | `tools/time-control/allocate.py`（`allocate.txt`）。局面ごとの「時間 t までに終わった最後の反復の損失」を平均して L_e(t) を作り、時間に対して増えない関数に当てはめる。52〜20空きの自分の手番17回に総時間を分け、損失の合計が最小になる配分を動的計画法で求める |
| 時間の換算 | 対局中（置換表が温まっている、`reuse_pv`）は同じ反復が probe の約0.7倍の時間で終わる（GTP ログとの比較：中盤 0.71〜0.80、終盤 0.49〜0.60）。probe の時間に0.7を掛けた |
| 今の配分 | `2026-11-20-time-control-forecast` の評価対局の GTP ログ（新）から、空き数ごとの平均使用時間の比 |

```sh
cd tools/time-control/probe && cargo build --release && cd -
B=tools/time-control/probe/target/release
$B/probe games.txt 6 48,44,40,36,32,28,26,24,22,20 8 1 SKIP > probe.txt   # 8プロセス、SKIP=0,8,..,56
$B/refer games.txt probe.txt 26 1 > reference.txt                           # 分割して並列に
python3 tools/time-control/losses.py reference.txt -- probe.txt
python3 tools/time-control/allocate.py --scale 0.7 18 -- reference.txt -- probe.txt -- LOG_DIR/new-*.log
```

### 配分（`allocate.txt`）

自分の手番 52〜20空きの合計損失（石）。「表の上」は表を作った局面での値、「交差検証」は偶数番の局で配分を決めて奇数番の局で比べた値と、その逆。

| 総時間 | 表の上：最適 / 今 / 均等 | 交差検証：最適 − 今 |
|---|---|---|
| 1.8秒（GTP 2秒相当） | 3.79 / 4.56 / 4.42 | +0.47（SE 0.49）、+0.09（SE 0.85） |
| 18秒（GTP 20秒相当） | 1.99 / 2.69 / 2.58 | −0.00（SE 0.31）、+0.00（SE 0.35） |
| 55秒（GTP 60秒相当） | 1.59 / 3.41 / 1.77 | −0.00（SE 0.44）、+0.44（SE 0.37） |

表の上では55秒の「今」が18秒より悪く出るなど、局面数に対して曲線のばらつきが大きい。55秒では中盤が深さ22を超えるので、中盤の曲線は平らになり、使えない。

## 今後に向けて

- 配分を計算で決めるには、空き数あたり数千局面と、中盤のより深い参照が必要。参照は1局面あたり約30秒（E コア1スレッド）なので、10段階×2,000局面で約170コア時間かかる。
- 確かな方向は、24〜28空きで85%〜95%のステージに届くよう時間を回すこと。完全読みのための予約（`Budget` の `3 × 6ms × 2^(空き−17)`）を、95%/98% のステージの時間に置き換える案が考えられる。ただし、予約を減らした `5339c14` は対局で負けた（`2026-11-20-time-control-forecast`）。この案も、対局で確かめてから入れること。
