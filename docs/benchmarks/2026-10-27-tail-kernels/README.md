再起動後の環境で双方をnative releaseでビルドし直した。Rust 1.99.1、AMD EPYC 9V74仮想環境、CPU 0固定、1スレッド、主TT 256 MiB、旧main評価をDPR2に変換したモデル（SHA-256: 3a07488cc364975eed03fe01c1806a6ff2737e99f5879f70f21dc023d64a6069）、旧main MPC。モデルは再変換して前回と同一のハッシュを確認した。比較前バイナリもSHA-256が前回の最終既定版（e5fa52375574872a9091746f27e1f8fdb71b588897f731739d2c677cb06f28c1）と一致した。モデル読込・TT初期化は計時外。各局面を新プロセス・空のTTで実行し、測定中はビルド・テストを並行実行していない。

**段階的に実装した内容**

1. `reuse`: 7マス側で計算済みの子の合法手を6マス側でも使う。従来は保存して渡していたが、6マス側の末端関数が再計算していた。
2. `direct`: 5マスから専用4マスカーネルへ直接接続する。6→5も空きマス数を判定する汎用入口を経由しない。ゼロ窓なのでbetaをalpha+1から導き、窓の下限を各候補で更新する処理も省く。6マスのパスは引き続き局所TT入口を通す。
3. `parity`: 6→5→4の四分割parityを着手した領域のビットでXOR更新する。5マスのパスではそのまま引き継ぐ。7〜13マスのparity計算や、広い窓のPV探索は変更しない。
4. `lazy`: Edaxの浅い終盤を参考に、5マスでは空きマスをparity・升番号順に調べ、近傍の相手石とflipで合法性を判定して即探索する。早い手でカットすれば、残りの空きマスの合法性を確認しない。6マスでは既知の合法手を使う構成を維持する。
5. `lean`: parityの受け渡しをOptionからu8一つにまとめ、未取得は16で表す。さらに「合法手があった」フラグを廃し、未探索の番兵値-65で判定する。カーネルのスコア・上下限は-64..=64なので区別できる。4マスの安定石カットはparity再計算より先に実行し、カット時の不要な計算を増やさない。

探索値・手順付け規則・選択率タグは維持する。6マス局所TTの有無、MPC係数、評価モデル、ノード上限、中断確認の頻度は変更しない。5マスで非法手のflipを調べても探索ノードには数えず、合法な子に進むときに従来どおりenterを呼ぶ。4マス以下のLeafSearchの中断伝播も維持する。
