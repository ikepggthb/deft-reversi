2026-10-27 終盤探索の実装と比較

対象は refactor/engine-layout の作業ツリー（基点 8ab1682）。比較前は、既存の局所TT候補手保存・唯一手の評価省略を含む、この作業開始時点。旧mainのJSON評価をDPR2へ変換したモデル、旧main MPC、native release、Rust 1.99.1、1スレッド、主TT 256 MiB、CPU 0固定、AMD EPYC 9V74仮想環境で実行した。各局面は新プロセス・空のTT。モデル読込・初期化は計時外。測定中にビルド・テストを並行実行していない。

**既定の変更**

- 汎用探索は候補生成と子TTのETCを先に済ませ、TT候補を他候補の高価な評価より先に探索する。TT候補でカットした場合も通常どおり主TT/PV TTへ保存する。
- 局所NWSの7〜13マスも、合法な保存済み候補を他候補のmobility計算前に探索する。
- 子の局所TT照会結果を6バイトのEndProbeとして子へ渡す。子は同じhash計算と局面照合を繰り返さず、保存にも照会済みindexを使う。着手をu64のマスクからu8の位置へ変え、EndMoveは32バイトを維持した。
- 子TTでのカット・wipeoutでも、実際にカットを証明した手をbestへ記録する。以前の候補を残すと、先行探索が次回に不適切な手を優先し得る。
- qualityの一致条件を維持し、再帰からErrが返った場合は親の未完成な上下限を保存しない。

EndProbeは照会時点のスナップショット。候補評価と探索の間に同じキャッシュのスロットが置換されても、局面・qualityが検証済みの上下限は有効である。qualityは探索ステージ中に変わらず、ステージ切替前にワーカーをjoinする。一方、候補列挙後に新しく入ったTT情報を再照会で拾う機会は減るため、再利用が常に有利とは限らない。

**11〜13マスの評価経路**

Cargo feature `endgame-pattern-ordering` で有効になる。既定では無効。11〜13マスは既存44パターンの評価とweighted mobility、7〜10マスは従来のweighted mobilityとparityで手順付けする。評価を本探索の値やMPCの判定に混ぜない。

単純な初回実装をそのまま残さず、次の順に実装費用を下げた。

1. 初回は局面からEvalStateを再構築し、候補ごとに両視点を更新した。
2. 11〜13マス各層に局面タグ付きの作業状態を持ち、探索する子へ差分更新した特徴量を引き継ぐようにした。13マス入口では汎用探索の既存状態も使う。パス等でタグが合わない場合は再構築する。
3. 候補の評価だけなら子の片側の44個のインデックスで足りるため、反対側の更新を省いた。実際に探索する子にだけ両視点を用意する。全候補へ176バイトを追加して保存する方式は使っていない。
4. 16パターンの小型状態も別実装したが、既存main重みの部分流用では順位付けの効果が弱まったため、本体の実験経路には44パターン版を残した。

この44パターン版は終盤手順付け専用に学習した評価ではない。Egaroucidの専用16特徴・専用重みを再現した実装とも異なる。現モデルによる試行結果から、専用モデルを使うアイデアそのものを否定しない。

`tt-first-ffo.*` は最初の先行版、`probe-ffo.*` はETC先行版に対する照会再利用の比較。`*-diagnostic.tsv` は1周のみの診断。`trial-binaries.json` に試作バイナリのSHA-256、各累積patchに作業開始時点からの試作差分を保存した。パッチを相互に重ねて適用するものではない。試作patchには最終版のfeature分離やカット候補保存の追加修正を含まない。

5周比較には `tools/bench_rewrite_versions.py` を使う。診断に使った `diagnose.py` は当時のモデルパス `/tmp/deft-eval-main.dpr2` を参照する。CPU・モデル・MPC・TT条件を変える場合は別の結果として扱う。

最終版の既定機能と実験機能は、後続の最終比較データを参照。Edax/Egaroucidとの再測定はこの作業では行っておらず、それらを超えたという主張はしない。

**最終版の実験機能の確認**

FFO 40〜44、5周の中央値で、既定版 3.604738秒に対し、実験機能有効版 3.852223秒（約6.87%増）。ノード数は 116,865,873→103,721,522（約11.25%減）。全5周で有効版の時間が増え、全スコアは一致した。周内のafter/before比の中央値では約7.42%増だった。初回実装のまま判断せず再利用・片側更新まで行ったが、現在のモデルと実装では費用に見合わないため既定にはしない。`final-pattern-ffo.*` に生データとハッシュを保存。

既定版・実験機能有効版の両方で、releaseの全56テスト（ignoredのストレステストを含む）が成功した。ETCをTT候補の探索前に行うこと、高価な候補評価前のTTカット、局所TTのquality不一致と置換後のスナップショット、カットを証明した候補の保存を追加検証した。実験用の片側インデックスは独立した盤面からの再構築と照合した。既存のfetch_update非推奨警告は残る。

**最終版の既定機能の比較**

FFO 40〜49を5周した全100実行がCompleted、全50組の前後スコアが一致した。各周で既定版が短縮し、周内のafter/before比は 0.9481, 0.9503, 0.9293, 0.9092, 0.9668、その中央値で約5.19%短縮した。ノード数は全周で一定で、816,408,001→815,860,308（約0.067%減）。ノード削減量に比べて時間差が大きく、処理の省略による改善と整合する。ただしどの変更が何割を占めるかは分離していない。

各周の合計時間の中央値は27.311269→25.001866秒（約-8.46%の時間変化）。仮想環境で実行時間のドリフトがあるため、中央値同士の比だけで約8.46%の一般的な短縮を主張せず、上記の周内前後比の中央値約5.19%を主な報告値とする。測定ツールにもpaired_time_ratio_medianを追加し、最終3組のJSONにも同じ式で追記した。

中盤24局面・深さ8の5周比較は周内比中央値で約14.04%短縮、合計時間中央値0.217404→0.195513秒。ノード719,338→692,128。5周中4周で短縮、1周では悪化しており、短時間測定の変動に注意する。全240実行Completed、前後スコアは一致。

`final-ffo40-49.*` と `final-midgame.*` に生データ・各周の時間・モデル/局面/バイナリのSHA-256を保存。`final.patch` は作業開始時点に対する最終実装の累積差分で、適用検査も成功した。実験機能はノード削減の効果を持つが現状では時間が増えるため、featureで明示的に有効化する。専用モデルの学習や追加のSIMD最適化の結果までは、この比較から判断しない。
