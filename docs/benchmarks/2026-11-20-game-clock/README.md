# 持ち時間制対局の時間管理最適化（2026-11-20）

1局全体に持ち時間が設定された FlipSight / GTP 対局において、同一総持ち時間での期待最終石差（自分の石数 − 相手の石数）を最大化するための時間管理を設計・実装し、現行版と直接対局で比較した。

## 測定環境・前提

- **基準コミット**: `2df7a40`（`develop/v2` 最新）
- **CPU**: Intel Core Ultra 7 265K
- **ビルド**: `cargo build --release -p deft-reversi-cli`
- **評価モデル**: 校正済み `model.dpr2`（SHA-256 `1a6e6b81aa4de564ab47674bc2911c42e1c0c33df2a74bb9e2dc3694f384eab5`）、TT 64 MiB、ブックなし
- **開局**: XOT 8手開局（seed `42139`）。調整・旧候補評価に使った 206 開局と最終評価の 186 開局は盤面対称性を含め非重複に分離。各開局で先後を入替。
- **主指標**: 新実装側から見た終局盤の実石数差（空きマスは加算しない）。95% 信頼区間は開局ごとの 2 局平均に対する両側 Student t 区間。
- **FlipSight 条件**: 毎局プロセス新規起動（初回モデルロードを計時に含む）、各手の `budget_ms = min(1000, remaining_ms)`。

## 変更内容と採用理由

共通の時間配分・反復継続判断を `deft-reversi-cli/src/game_clock.rs` に実装し、`flipsight.rs` と `gtp.rs` から利用する構成とした（`deft-reversi-engine` の公開 API・探索本体は未変更）。

1. **将来の安価な完全読み手の予約保護**:
   - 終局に近い将来の自手番から順に、完全読み推定時間 `2ms + 3 * 6ms * 2^(future - 17)` が均等額より安ければその分を予約して差し引き、残りを高価な手番で割って `soft` 予算とする。
   - `hard` は最大 2 手分、かつ高価な将来手の予約から借りられるのは半分までとし、安価な予約済み将来手からは借りない。
   - 固定の目標深度や空きマス境界はハードコードしない。
2. **反復完了時の次段コスト予測とソフト打ち切り**:
   - `Progress` コールバックで直前反復の実測時間から次段の完了時刻を予測（中盤 2 手深化は直近 2 段の比を `1.5..=6.0` にクランプ・初回 `3.0`、終盤 MPC は `1.6`）。
   - 予測が予算を超えるなら打ち切って次手へ持ち越す。直前の反復から最善手が変わった場合のみ `soft` を最大 `1.4` 倍（`hard` 上限内）へ広げる。
3. **プロトコル統一・即応**:
   - GTP の時間制対局も FlipSight と同じ `SearchRequest::timed_levels(60, hard).skip_pv_recovery()` に統一し、一本手・残時間枯渇時は探索せず即応。

## 補足診断

- **終盤（空き 16 以下）の完全読み検算**:
  - FlipSight 6秒全 144 局：新 1,158手・旧 1,143手ともに**全手 0 石損**。
  - GTP 0.5秒全 128 局：新 **0.031石損/局**（最大 2石） vs 旧 **4.188石損/局**（最大 34石）。
- **無駄打ち時間とフェーズ配分**（GTP 2秒・別6開局 12局）:
  - 最後の反復完了〜応答までの壁時計比率：旧 **46.2%** → 新 **9.3%**。
  - 空き 18〜32 の探索消費：旧 0.710秒 → 新 0.895秒（終盤段完了 36/90手 → 43/90手、うち完全読み 22手 → 27手）。
- **空き 20（`end120.obf` 全 40 局面・cold TT・1スレッド）**:
  - 中盤 12手 83%：29.7 ms / 1.05 石損
  - 中盤 16手 83%：112.8 ms / 0.55 石損
  - 終盤 85%：71.4 ms / 0.05 石損
  - 終盤 95% / 99% / 完全読み：125.2 ms / 163.5 ms / 232.2 ms（いずれも 0.00 石損）

## 残る課題

- GTP 15秒・60秒は標本数が小さく、未使用時間削減（60秒で 9.04s → 1.74s）に対して石差改善が未確定。
- 中盤最終深さから最初の終盤 MPC（85%）へ遷移する際のコスト予測、および終盤 MPC 段間の成長率の精緻化。
- 将来の完全読み事前推定のハードウェア・スレッド数への動的追随、およびブック併用時の評価。
