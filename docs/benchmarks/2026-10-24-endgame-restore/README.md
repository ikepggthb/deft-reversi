# 元実装を参照した終盤探索の復元

## 最終結果

| 集合 | 元の通常API | 修正版 | 修正版/元 |
|---|---:|---:|---:|
| FFO 40〜44 | 1.801550秒 | 1.811034秒 | 1.005倍 |
| FFO 1〜19 | 0.057705秒 | 0.044585秒 | 0.773倍 |

FFO 40〜44は合計ではほぼ同等。元の実装より高速という結論ではない。局面ごとには以下の差があり、遅い局面が残っている。1〜19は短時間のため、時間の揺れにも注意する。全24局面・全5周でスコア一致。合計は各周の合計時間の中央値で、局面別中央値の和とは少し異なる。

|---|---:|---:|---:|---:|
| 40 | 0.099150 | 0.114099 | 1.151倍 | 38 |
| 41 | 0.228234 | 0.234976 | 1.030倍 | 0 |

作業前のリライト版は以前の通常API比較で5.284167秒だった。今回の1.811034秒は約65.7%短縮。ただし前後を同じ測定内で交互実行した数字ではなく、探索仕様の復元と処理コスト削減を合わせた改善である。新旧比較そのものは、最終測定内で毎周交互実行している。

FFO 20〜39、45以降は今回測定していない。この結果からFFO全体や別モデルでの高速化は主張しない。

## 比較方針

旧版の通常の探索経路を基準に固定する。旧版は `../deft-reversi-feature` の `f4192a0`、`Solver::from_file(eval-v4.bin)` で評価重みとモデル付属MPC設定を読み込み、`solve(board, 60)` を実行する。準備探索と選択性の段階移行を含み、最後はMPCなしの完全読み。

新版は `SearchMode::Exact`。比較ツールが同じ旧モデルの `mpc_config().eval_search.params` / `final_search.params` から校正値を渡す。最終段階はMPCなし。以前の `solve_final` 単独との比較を採用条件には使わない。

条件: Intel Core Ultra 7 265K、CPU 1固定、1スレッド、native release、fat LTO、codegen-units=1、panic=unwind、メインTT 256 MiB。旧版にはPV専用表、新版には各ワーカー約384 KiBまでの局所表があるため、総メモリが同一という意味ではない。

各局面は旧版Solverとスレッドを作り直して共有・スレッド内TTを初期化し、新版も共有・局所TTを消去。各周で新旧の実行順を逆転して5周測定。モデル読込・Solver生成・表の消去は計時外。探索中の準備探索、浅い手順付け、局所表の遅延確保は計時内。辺の確定石表は両者ともプロセス内で一度だけ初期化され、初回に遅延初期化する。

最終測定はテスト・ビルドと同時に実行していない。途中の試行は原因切り分けの記録で、一部はテスト・ビルドと時間が重なるため、細かな差の判定には使わない。

## 元へ戻した処理

| 項目 | 復元した内容 |
|---|---|
| 反復深化 | 目標と同じ偶奇、2手刻み、可能なら5/6手から開始 |
| 終盤前の準備 | 残りマス数−8、2〜24手に制限 |
| 選択性 | 校正値がある場合、85%の準備から残りマス数に応じて段階移行し、最後にMPCなし |
| 手順付け | 元の中盤・終盤の浅い探索深さ、評価窓、重み、相手の隅の合法手への加重 |
| 置換表 | 候補2手、通常窓での上限によるbetaの絞り込み、NWSでの子局面の表によるカット・スキップ |
| 確定石 | 辺の全パターン表、NWSで実行を選ぶ残りマス数・alphaの閾値、相手側のみの計算 |
| 残り13マス以下 | 局所TT、子の表を合法手生成より先に照会、相手の合法手が極端に少ない手の先行探索 |
| 残り4マス以下 | 元の2/3/4マス専用処理、手順付け、パス処理を移植。停止・ノード予算は新版に接続 |
| アスピレーション | 浅い準備探索では全窓、元の初期窓幅、失敗側の拡張、終盤の偶数境界 |

校正値の参照は全ルールの線形走査から、探索方式・深さ・空き数による直接参照へ変更した。

## 維持した設計と残る差

盤面の検証付きAPI、評価特徴量の差分更新、モデルの不変共有、Context所有の局所表、停止・ノード上限、明示的なパス・中断結果は維持する。局所表はスレッドローカルへ戻さない。

元実装の完全な一対一移植ではない。levelからの自動モード選択、ルート候補ごとの境界保持と安定化反復、PV専用TTからの読み筋復元、通常窓でのすべてのTTカット・alphaの絞り込み・ETCは未移植。新版の通常窓では実際に検索した読み筋を保つため、今回のTT復元範囲を制限した。

選択的な準備探索の境界は段階ごとにタグを分け、共有TT・局所TTとも完全読みのカットに流用しない。段階切り替え前に全ワーカーを回収する。中断時に最後に完了したのが選択的な終盤探索なら `mode=SelectiveEndgame` / `selective=true` を返し、確定解とは表示しない。

## 検証

native releaseでストレスを含む全42テスト成功。通常/native構成でエンジンの全ターゲットClippy成功。比較ツールもClippy成功（参照先には既存の未使用関数・命名の警告あり）。

既存の総当たり照合、探索窓の上下限、PV、キャッシュ再利用、停止、予算、並列テストに加え、不正確な校正値を意図的に与えても最終完全読みへ境界が混入しないことと、準備探索直後に予算で停止してもExactを名乗らないことを検証した。

## 再現コマンド

```sh
RUSTFLAGS=-Ctarget-cpu=native cargo build --offline --release --manifest-path tools/engine-compare/Cargo.toml
taskset -c 1 tools/engine-compare/target/release/deft-engine-compare ../deft-reversi-feature/data/eval/eval-v4.bin /tmp/deft-pattern.dpr2 deft_reversi_engine_v2/tests/fixtures/ffo40-44.obf level:60 5 1
```

DPR2は `tools/convert_pattern_v2.py` で同じeval-v4.binから生成する。比較ツールはモデル付属MPCから直接パラメータを取得するため、別の校正値を指定していない。係数が非有限・傾きが非正・偏差が負・浅い深さが不正な領域にはルールを登録しない（以前の変換ツールと同じ制限）。
