# WASM SIMD 計測（2026-10-30）

Web向けエンジンを `wasm32-unknown-unknown` のリリース設定でビルドし、`simd128` の有無を比較した。Node.js 24.19.0、AMD EPYC 9V74、wasm-bindgen 0.2.129。`wasm-opt` は使用していないため、配信ビルドでの効果を保証する測定ではない。

FFO 40〜44 の5局面を各々 depth 10、32 MiB の置換表で順に探索し、エンジン生成とモデル読み込みを除いた合計時間を測った。各周で新しいエンジンを使い、2種類の実行順を交互にして8周した。最善手・スコア・ノード数は全周一致した。

| ビルド | 合計時間 ms（8周） | 中央値 |
|---|---|---:|
| SIMD 無効 | 267.0, 253.8, 251.3, 239.4, 245.0, 249.9, 247.3, 240.2 | 248.6 ms |
| SIMD 有効 | 152.2, 141.7, 150.6, 149.8, 145.4, 146.8, 144.9, 146.3 | 146.6 ms |

この測定では探索時間が約41%短縮した。局面・ブラウザ・CPUにより効果は異なり、棋力や全端末での速度を保証するものではない。SIMDを使うビルドは対応ブラウザが必要。

再測定は評価モデルを `python3 deft-reversi-web/scripts/build-model.py` で生成し、比較するそれぞれの `.wasm` に `wasm-bindgen --target nodejs` を適用したうえで、リポジトリのルートから次を実行する。

```sh
node tools/bench/wasm_compare.cjs /path/to/before/deft_reversi_wasm_engine.js /path/to/after/deft_reversi_wasm_engine.js
```

比較対象のRustバージョン、最適化設定、モデルを揃える。現行設定でSIMDを一時的に無効化して比較する場合は、別の `CARGO_TARGET_DIR` を使い、`CARGO_ENCODED_RUSTFLAGS` に `-C` と `target-feature=-simd128` をASCII 0x1fで区切って渡す。
