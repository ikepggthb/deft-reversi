2026-10-27 ソース・構造レビュー後の修正

対象は `refactor/engine-layout` の `f617941` からの変更。今回の「すべて修正」は直前のコード・ディレクトリレビューで挙げた問題を対象とする。過去の性能調査にある実験候補を一括で有効にするものではない。

**修正内容**

- MPCの確認探索を、本探索より浅い深さに制限する。非終盤は4〜60、終盤は12〜60の実際に使う表領域を検証する。API設定、JSON・bincode読込とも拒否し、不正な設定によって既存設定を変更しない。使わない領域の値と符号付き回帰誤差の互換性は維持する。
- 局所TTの `P ^ rotate_left(O, 32)` を先に作る混合を廃止する。この式では32マス離れた色交換が相殺される。各色を別の64ビット定数で乗算してからxorし、上位11ビットで2048スロットを選ぶ。完全な盤面・選択率の照合、上下限、候補手、再帰へ渡す不変スナップショットは維持する。衝突がなくなるという意味ではなく、構造的な相殺を除く修正である。
- `search/endgame/` を設け、入口・局所TT・7〜13マスの手順付け・5〜6マス・4マス以下を分離する。TTのエントリ型を非公開にし、EngineとContextは不透明なキャッシュを所有する。層の外側は固定長配列、各層の領域は必要時にだけ確保する。四分割パリティの領域・升番号を共通定義にする。探索中の動的ディスパッチや候補ごとのヒープ確保は追加しない。
- 現行比較ツールを `tools/bench/` に集める。旧クレートの場所、Edaxの評価データを引数化し、外部チェックアウト名への固定依存を廃止する。旧版比較は独立プロジェクトを生成し、初回に作ったlockfileを以降 `--locked` で利用する。変更前後の比較は実行ごとに結果を保存する。過去の測定スクリプトは記録として残す。
- ルートの `Cargo.lock` を管理対象とし、測定に使ったRust 1.99.1、rustfmt、Clippyを固定する。READMEの古い配置・現在値として記載されていた過去の時間を更新する。
- 固定した新しいClippyの指摘に従い、最下位1ビットの抽出を同じ意味の `isolate_lowest_one()` に、モデルの2バイト単位の読込を `as_chunks::<2>()` に置き換える。ノード予算のatomic APIは同じ動作の改名先 `try_update` を使う。

**テスト中に見つけた不安定な判定**

最終再検証の1回で、既存の並列ストレステストの `result.stats.splits > 0` が失敗した。各探索のスコア・完了状態は正しかった。共有ワーカーへのofferは前段のmailbox解放と競合して失敗でき、TT再利用でも分割が省略され得るため、毎回の分割はAPIの保証ではない。全500探索のスコアと完了状態を毎回検証する条件は残し、スレッド数ごとの反復全体で分割・helper実行があったことを要求するよう修正した。失敗を再試行で隠すために探索を変更していない。

**性能確認の分離**

変更前・構造変更だけの中間版・最初に試した2乗算版を別バイナリとして保存して比較した。構造だけの中間版にもMPC設定の検証と固定長の外側層を含むが、旧混合式を保つ。最初に試した2乗算版には新混合式に加え、意味を変えない上記のClippy対応を含む。そのため2乗算版と構造変更版の実時間差の全てをハッシュ演算の費用と断定しない。ノード数の変化と、同じノード数での時間差を分けて読む。

AMD EPYC 9V74仮想環境、CPU 0固定、1スレッド、主TT 256 MiB、main由来の変換モデルと明示的な `--legacy-main-mpc`、FFO40〜49の10局面を使用する。各局面は新しいプロセス・空TTで、Exact完了・深さ・スコアを照合する。6周で各局面を6通りの全実行順に均等配置する。測定中にビルド・テストは行わない。

| 構造変更のみ | 22.597963秒 | 1.000767 |

**回転量だけを変更する実装**

32ビット回転では、色交換マスクDに対し `D ^ rotate(D,32) == 0` になるマスクが多数ある。奇数の31ビット回転は64升を1つの巡回にするため、この式が0になるのはDが0または全64ビット1の場合だけ。同じ空き升配置で石の色を変える場合、空き升が1つでもあればDが全64ビット1になることはない。したがって、今回の局所TTが扱う空き6〜13の同じ空き升配置について、上位11ビットへ縮める前の色交換の相殺を除ける。

追加の試作では、この方法で回転を32から31へ変更した。乗算は元と同じ1回で、回転・xor・乗算の演算数を増やさない。異なる空き升配置間の衝突や、2048スロットへ縮める際の衝突は当然残る。完全な盤面照合も引き続き必要である。


この試作を変更前と6周・120実行で比較した結果は `odd/results.tsv` と `odd/results.json`。全スコアが一致した。変更前の10局面合計中央値は22.049882秒、試作は22.248243秒。周内の時間比中央値は1.010136（約1.01%増）で、試作が速かったのは2/6周だった。演算数が少ないことと実時間の優位は一致しなかった。ノード数は815,729,401で、変更前より約0.0160%少ない。

回転量31のアイデア全体が悪いとは判断しない。今回の実装では優位を確認できなかったため保留し、変更前との時間差が小さかった2乗算版を採用した。TTの分布・命令配置・仮想環境の変動を完全に分離できていないため、約1%差の原因を特定したとは主張しない。両比較の絶対時間を実験間で直接比べず、それぞれ同じ周の変更前との比を使う。保留版のソースは `odd-source.patch` と `odd-source-sha256.json` に残す。
