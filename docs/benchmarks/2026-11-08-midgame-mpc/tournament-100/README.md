# 6候補・100開局の総当たり

68・77・95・98・99・100%の6候補を総当たりで比較する。15組×100開局×先後交換2局＝3,000局。各候補は他の5候補と合計1,000局打つ。85%は今回の6候補には含めない。

## 条件

- 中盤は空き19以上、`Depth(60)`、100 ms／手、深さ1から1手ずつ反復深化。モデル・校正規則・確認探索の深さは共通で、選択段階だけを変える。
- 空き18以下は共通の `Endgame/Full`、25 ms／手。完全読み未完了の場合は最後の完了反復の手を打つ。境界より前に終盤モードへ切り替えない。
- 対局開始時と各エンジンの最初の空き18以下の探索前にTTを消去。反復間・同じ中盤設定の手番間は再利用。選択確率が変わる際のエンジン内部のTT消去も前回と同じ。
- Core i3-14100、1スレッド、TT 64 MiB、CPU 2に固定。1局ずつ順に実行し、ponderなし。測定中はビルドや別の重い計測を行わない。
- バイナリとモデルは前回の600局と同じ。ハッシュは `manifest.json` に記録。
- XOT原本の行をseed 3でシャッフルし、過去の予備測定4開局と600局の50開局を除き、対称形も含め重複しない100開局を選んで `xot-100.txt` に保存した。その100行を対戦ランナーでseed 3の順番に並べ、全15組で共通に使う。
- 開局ごとに15組の実行順を回し、先後ペアで先に打つ色も回す。

## 実行

```sh
python3 tools/bench/mpc_match.py \
  --out docs/benchmarks/2026-11-08-midgame-mpc/tournament-100 \
  --round-robin --candidates 68,77,95,98,99,100 --openings 100 --seed 3 \
  --xot docs/benchmarks/2026-11-08-midgame-mpc/tournament-100/xot-100.txt \
  --budgets 100 --endgame-empties 18 --endgame-ms 25 --cpu 2 \
  > docs/benchmarks/2026-11-08-midgame-mpc/tournament-100/run.log 2>&1
python3 tools/bench/mpc_report.py docs/benchmarks/2026-11-08-midgame-mpc/tournament-100
```

各手のログ（`logs/`）と `run.log` は git で管理せず、手元の `local/bench-runs/docs-raw/2026-11-08-midgame-mpc/tournament-100/` にある。

同じコマンドで保存済みの対局を除いて再開できる。設定・バイナリ・モデル・ランナーのハッシュが変わった場合は再開を拒否する。

得点率は勝ち1・引き分け0.5。組ごとは先後ペアを単位とする2,000回のbootstrap、総合成績は1つの開局における他5候補・先後10局を1組として4,000回のbootstrapで95%区間を求める。多重比較の調整は行わない。最高得点率だけで改善を確定せず、組ごとの結果と区間も見る。

## 結果

3,000局を完了。15組それぞれ200局、100開局すべてで先後のペアがそろい、重複IDなしを確認した。各候補は他の5候補と1,000局ずつ打った。途中の再開では保存済みの対局を除いて継続した。対局単位の外側時間の合計は10,897.17秒（3時間1分37秒）、1局平均3.632秒。中断中の時間と測定後の集計時間は含まない。

総合得点率は95%が58.40%で最高、77%が57.55%で続いた。両者の優劣は未確定。95%対77%の直接対戦は50.5%対49.5%で、95%側の先後ペア単位の95%区間は45.75〜55.25%。共通の100開局を単位に総合得点率の差をbootstrapで調べても、95%−77%は+0.85ポイント、95%区間は−3.15〜+4.70ポイントだった。後者はseed 1・10,000回で、詳細は `top-paired-comparison.json` に保存した。

85%は今回の総当たりには含まれないため、この測定で85%に対する改善は判断しない。次に絞るなら95%・77%と基準85%が候補になる。今回の結果だけでエンジンの選択確率の採用変更は行っていない。

### 検証

- 対象102,000着手で境界・確率・割当時間の検証を通過。完了反復なしの代替手・ワーカー失敗なし。
- MPCありの85,000着手すべてで、最後の完了反復にもMPCの確認探索があった。100%の17,000着手ではMPCの確認探索・カットが0。
- 共通終盤は53,951着手のうち53,699着手（99.53%）で完全読みを完了。252着手は上限内に完全読みが終わらなかった。終盤25 ms上限を含む条件での成績である。
- 探索内部の最大時間は中盤101.874 ms、終盤25.835 ms。中盤の外側時間の最大は138.678 ms。
- 総当たりの組み合わせ・引き分けと両側の集計・再開時のスキップを短い動作確認で検証済み。Pythonのテスト8件も成功。
