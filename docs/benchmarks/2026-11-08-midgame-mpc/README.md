# 中盤MPCの選択確率：実験計画と予備対戦

XOT以降、空き19マス以上で使うMPCの選択確率を、同じ1手の時間で比較する。最初の予備対戦は測定条件の確認が目的で、強さの採用判断には使わない。

> 2026-11-15 追記：ここで使った `tools/bench/mpc_match.py`・`mpc_report.py`・`mpc_detailed_report.py`・`mpc_sigmas.py` と実験用GTPのオプション（`--mid-sigma` など）は 2026-11-14 に削除した。当時のコードは各測定フォルダの `source.diff` にある。任意の確率は「85%段の中盤の倍率を置き換える」方法で実現していた。今のエンジンの段は 83/85/95/98/99/100% で、83%はモデルの校正が持つ倍率（ここで採用した 1.2691755）を使う。68%・77%は選べない。

## 固定する条件

- モデル：`local/release/model-v3-pen/deft-eval-v3-pen.dpr2`。回帰係数、確認探索深さ、校正倍率は共通。選択段階だけを変える。
- XOTは8手、空き52で開始。空き52〜19の34着手が比較対象（パス等を除く）。対象は着手前のルートの空き数で判定する。探索内部では終盤モードに切り替えない。
- 空き19以上：`Goal::Depth(60)`、指定の選択確率、固定時間／手。目標深さは空き数で制限されるが、時間指定の反復は深さ1から1手ずつなので開始深さの偶奇差はない。
- 空き18以下：`Goal::Endgame` / `Full`、25 ms／手。準備探索の85%と選択的な終盤段階は共通。完全読みが終わらなければ最後の完了反復の手を使う。読み切るまで待たない。
- 各対局の開始時と、各エンジンの最初の空き18以下の探索前にTTを消去。対象区間内は通常どおりTTを再利用する。
- 1スレッド・TT 64 MiB・CPU 2、2エンジンを同じCPUに固定し1局ずつ実行。ponderなし。測定中にビルドや別の計測は行わない。
- すべての候補に同じ開局、先後を交換して2局。開局ごとに候補順と先に打つ色を回す。

## 手順

1. 予備測定：基準85%に対し68・95・99・100%。4開局×先後2局×4候補×25/100 msの2条件＝64局。100%はMPCなしの対照。MPCの実行、反復の完了、時間のばらつき、終盤の費用を確認する。
2. 本測定の時間を決める：対象区間でMPCが実際に動き、そのMPCが使われた反復が完了していること、最初の反復が完了しない手がないことを確認する。必要なら200 msなどを追加する。
3. 粗い比較：まず100 ms／手で、基準85%と残り6段階を各50開局・100局、計600局比較する。予備測定の速度なら約37分。必要に応じ各200開局・400局へ増やす。25 ms条件は短時間での傾向確認に使う。少数の開局での順位だけで僅差の候補を落とさない。主指標は勝ち1・引き分け0.5の得点率、信頼区間は開局の先後ペア単位で集計する。
4. 上位候補の直接対戦、未使用開局での最終確認。最有力候補と基準を2,000開局・4,000局を目安に比較し、別の1手時間と、強めた共通終盤設定でも順位を確認する。

本測定と最終確認の開局は事前に分け、同一局面・対称形による重複も確認する。予備測定の4開局は最終確認には使わない。差が不明確なら改善未確認として扱う。

## 記録するもの

- 実行ファイル・モデル・XOTのSHA256、コミットと未コミット差分、ランナーのソース、開局と設定。
- 各手の空き数・要求モード・確率・割当時間・実時間（探索内部／TT消去等を含む外側）・停止理由・読み切り。
- 完了反復ごとの深さ・確率・累積経過時間・ノード数・MPC試行数・実際の確認探索数・カット数。
- 最後の完了反復でMPCの確認探索が実行された手数。`probcut_tries` は静的事前判定より前に増えるため、それだけではMPC実行の指標にしない。
- 時間の中央値・95パーセンタイル・最大、完了深さ、終盤の読み切り率、得点率・石差・総所要時間。

## 実行方法

基点は `c186ad5` に未コミットの変更を加えた状態。機械は Intel Core i3-14100（4コア8スレッド）。詳細とハッシュは `pilot/manifest.json`、ソース差分は `pilot/source.diff` に保存する。

```sh
RUSTFLAGS='-Ctarget-cpu=native' CARGO_TARGET_DIR=target-native \
  cargo build --locked --release -p deft_reversi_engine --example gtp
python3 tools/bench/mpc_match.py \
  --out docs/benchmarks/2026-11-08-midgame-mpc/pilot \
  --openings 4 --budgets 25,100 --candidates 68,95,99,100 --baseline 85 \
  --endgame-empties 18 --endgame-ms 25 --cpu 2
```

## 予備対戦の結果

1手あたりの時間・完了深さの最小／最大／平均／中央値は [pilot/move-statistics.md](pilot/move-statistics.md)、数値データは [pilot/move-statistics.tsv](pilot/move-statistics.tsv) にある。既存64局のログから再集計し、85%は全対戦相手との基準側の着手を合算している。

64局を完了。対局単位の実時間の合計は156.53秒（起動・終了を含む、最終集計を除く）。25 ms条件は1局平均1.23秒、100 ms条件は3.55〜3.71秒だった。

主指標は得点率＝（勝ち＋引き分け×0.5）／局数。以下は各8局しかなく、強さの順位や採用の根拠にはしない。

| 候補 | 25 ms：勝/分/負 | 得点率 | 平均完了深さ | 100 ms：勝/分/負 | 得点率 | 平均完了深さ |
|---|---:|---:|---:|---:|---:|---:|
| 68% | 3/2/3 | 50.0% | 16.32 | 5/1/2 | 68.8% | 20.03 |
| 95% | 3/1/4 | 43.8% | 13.37 | 1/5/2 | 43.8% | 15.71 |
| 99% | 5/1/2 | 68.8% | 12.00 | 1/2/5 | 25.0% | 13.88 |
| 100% | 2/0/6 | 25.0% | 9.41 | 2/0/6 | 25.0% | 10.98 |

対戦相手の85%の平均完了深さは、組み合わせによって25 msで14.46〜14.96、100 msで17.53〜18.00。候補によって対局の局面が異なるので、深さは同一局面での速度比較ではない。99%の得点率が時間条件で大きく動いており、現状では候補を落とさない。

### 調査条件の確認

- 対象区間は2,176着手。すべてで要求した中盤探索・確率・時間が適用され、終盤モードへの早い切り替えはなかった。反復未完了の代替手、ワーカー失敗もなかった。
- MPCありの1,904着手すべてで、最後に完了した反復にもMPCの確認探索があった。100%の272着手では確認探索・カットとも0だった。25 msでもMPCを比較できる深さまで到達している。
- 探索内部の時間：25 ms指定の95パーセンタイル25.0196 ms、最大25.6782 ms。100 ms指定は95パーセンタイル100.0198 ms、最大101.0062 ms。
- 外側の時間（TT消去等を含む）の最大は、25 ms条件で38.09 ms、100 ms条件で112.70 ms。初回や選択確率の変更に伴うTT再確保は探索内部の期限より前に行われるため、その費用も別に記録した。割当時間が同じでも、すべての着手の外側の時間が一致するわけではない。
- 共通終盤は1,152着手のうち1,147着手（99.6%）が完全読みを完了。探索内部の95パーセンタイル8.49 ms、最大25.005 ms、総探索時間1.414秒だった。初回のTT消去等を含む外側の最大は69.65 ms。今回の開局では終盤が対局時間を圧迫していない。

### 追加で分かった注意点

MPCありの中盤探索が、空き数と同じ目標深さまで到達して時間を余らせる手があった。これは中盤モードのままの終局深さ到達であり、MPCありでは完全読みの保証はない。

| 条件 | 68% | 85%（全組み合わせ合計） | 95% | 99% | 100% |
|---|---:|---:|---:|---:|---:|
| 25 ms：目標到達／対象着手 | 7/136 | 10/544 | 1/136 | 0/136 | 0/136 |
| 100 ms：目標到達／対象着手 | 21/136 | 47/544 | 5/136 | 2/136 | 0/136 |

100 ms・68%では空き19〜25で発生した。使わなかった時間は後の手へ繰り越さない。指定時間は各手の上限であり、実使用時間を強制的に一致させる実験ではない。本測定では対象全体の成績に加え、空き数の帯別と、時間切れ／目標到達別の深さ・使用時間も見る。

計測のため完了反復ごとにカウンタ取得とJSONの組み立てを行う。コールバックの費用も時間制限に含まれるが、無計測時との費用の差は未測定である。最終候補では記録を軽くした対戦でも確認する。校正規則は深い探索へ外挿されるため、表示の「確率」を対局の正確さとは解釈しない。

### 次に進める条件

100 ms／手を主条件、25 ms／手を短時間条件とする。終盤開始18・25 ms上限は予備対戦では十分軽かったため維持する。主条件を6候補×50開局に増やし、77%・98%も加えて比較した（下記）。独立した開局での最終確認は未実施。

## 100 ms／手・600局の粗い比較

2026-11-08に次の条件で開始。予備対戦と同じバイナリ・モデル、1スレッド、TT 64 MiB、CPU 2。XOTはseed 2で50開局を選んだ。対称形を含め50局面すべて異なり、予備対戦4局面との重複もない。各候補は85%と先後を交換して100局ずつ打つ。その他の条件と境界でのTT消去は予備対戦と同じ。

```sh
python3 tools/bench/mpc_match.py \
  --out docs/benchmarks/2026-11-08-midgame-mpc/main-100ms \
  --openings 50 --seed 2 --budgets 100 --candidates 68,77,95,98,99,100 \
  --baseline 85 --endgame-empties 18 --endgame-ms 25 --cpu 2 \
  > docs/benchmarks/2026-11-08-midgame-mpc/main-100ms/run.log 2>&1
```

600局を完了した。[結果と判断](main-100ms/README.md)に得点率・開局の先後ペア単位の信頼区間、1手の時間・完了深さ、目標到達率、境界とMPCの検証結果をまとめた。対局時間の合計は35分58秒。最高は68%の51.0%（95%区間42.0〜59.0%）で、85%より強いとはまだ確認できない。100%（MPCなし）は22.0%だった。

対局結果は `main-100ms/games.tsv`、各手の記録（`logs/`）と実行ログ（`run.log`）は git で管理せず、手元の `local/bench-runs/docs-raw/2026-11-08-midgame-mpc/main-100ms/` にある。設定とハッシュは `main-100ms/manifest.json`。最終確認用の対戦はこの600局に含めない。

「コマンドの終了までCodexが待てるか」という質問を終盤探索の変更依頼と誤解し、[時間制限なしで完全に解く補助検証](endgame-unlimited/README.md)を行った。意図の訂正後、この設定変更は取り消し、終盤25 ms上限に戻した。補助検証のデータは履歴として保持する。上の600局の条件・結果は変わらない。

## 6候補・100開局・3,000局の総当たり

[総当たりの結果](tournament-100/README.md)を追加した。68・77・95・98・99・100%の15組を、過去の測定と重複しない100開局で先後交換し、3,000局を完了。中盤100 ms・終盤25 ms、バイナリ・モデル・CPU等は前回と同じ。各候補は他5候補に対して1,000局ずつ打った。

最高得点率は95%の58.40%、次点77%の57.55%。直接対戦は95%側50.5%、総合得点率の差も+0.85ポイント（開局単位の95%区間−3.15〜+4.70ポイント）で、両者の優劣は未確定。85%は今回の総当たりには含めていない。対局時間の合計は3時間1分37秒だった。

## 77〜95%の再比較

[77・81・85・89・92・95%の総当たり](tournament-77-95/README.md)を完了した。今回は85%を含む6候補、過去の対戦と校正用の空き52の局面を除く新しい100開局、先後交換の3,000局。中盤100 ms／手・終盤25 ms／手などの条件は同じ。

新しい確率の倍率は現行モデルと一致する校正の41,000局面・445,000組の誤差の分位点から求め、元の6段階の倍率の再現も確認した。中盤の実験倍率は終盤への切り替え前に元へ戻す。対局後の全件検証と集計も成功し、`tournament-77-95/completion.json` と [結果](tournament-77-95/results.md) を保存済み。

最高得点率は81%の52.35%、次点85%の52.20%。差は0.15ポイント（共通の開局単位の95%区間−4.25〜+4.45ポイント）で、81%が85%より強いとはまだ確認できない。直接対戦も81%側53.75%（95%区間48.25〜59.00%）だった。対局時間の合計は2時間58分56秒。

元データは [pilot/games.tsv](pilot/games.tsv)、集計は [pilot/summary.json](pilot/summary.json)、各手の記録（`logs/`）は git で管理せず、手元の `local/bench-runs/docs-raw/2026-11-08-midgame-mpc/pilot/` にある。再現用の実行ファイル・モデルの識別は [pilot/manifest.json](pilot/manifest.json)、測定時の差分（新規ランナーを含む）は [pilot/source.diff](pilot/source.diff) を参照する。測定後、ランナーの保存方式をソースの複製から差分への収録に変更したため、現在のランナーのハッシュは測定時と異なる。探索処理・対局・集計の変更ではない。
