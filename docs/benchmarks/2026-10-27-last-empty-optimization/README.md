**段階的な実装**

- range: PEXT結果をu8に限定してから配列添字へ変換する。抽出maskは8ビット以下なので値は変わらない。コンパイラへ範囲を伝え、get_uncheckedを増やさずに表引きの範囲検査を除く。
- aligned: EdaxのBMI2実装を参考に、縦・斜線3本の抽出位置を盤面のrankに揃える。短い斜線には各rankからダミーの1ビットを補い、抽出前に実際の4軸のunionでゼロにする。ダミーはunionの外から選び、各maskが正確に8ビットになることをconst評価でassertする。横用と縦・斜線共通用の2つのcounter行を使う。従来のmask＋位置の表3072バイトを、3mask＋unionの2048バイトにする。
- once: 安定石表のLazyLockを関数入口で1度だけ参照し、4辺の表引きへ同じ参照を使う。表の内容、初期化処理、安定石の定義は変えない。
- inline: 最終1マスに通常のinline属性を付けた試作。nativeでは呼出しが残ったため、意図した呼出し除去は実現しなかった。
- always（比較名core）: inline(always)で最終1マスを2マスカーネルへ展開する。呼出しは消えるが、2マス側のコードは大きくなる。サイズと速度を別々に確認する。
- legal-cut（比較名legal）: coreに加え、石数だけの基準値がalphaを超える場合はAVX2で合法性だけを調べる。合法なら最小1枚反転分を足した下限を返し、反転数の完全な計算を省く。Egaroucidの同種のカットを参考にした試作。通常の正確値として扱わず、NWSの下限として使う。AVX2非対応ビルドは従来の反転数計算を使う。

1マスで手があるときの基準値は2*自石数-62であり、合法ならスコアは基準値+2以上になる。この基準値がalphaより大きい場合だけ、legal-cutは基準値+2を返す。パス・両者着手不能時の計算は維持する。着手不能判定では、8方向のrayに自石があることと、直近の石が相手であることを確認する。残り1空きのため、両者の間に空きはない。

主TT・局所TTの構造、選択率タグ、MPC係数、評価モデル、ノード上限、中断伝播は変更しない。range〜coreは探索の規則と返す値を維持する。legalは正しい下限を早く返すため、探索ノード数が変わる可能性がある。

**機械語と小規模診断**

assembly-manifest.jsonと各asm.txtに対象バイナリのSHA-256、関数サイズ、命令列を保存した。比較前の独立した最終1マス関数は612バイトで、パス分岐を含めPEXT後の255との比較が9箇所ある。rangeではこれが消え398バイト、alignedでは376バイトになった。squareの範囲検査まで除いたという意味ではない。

onceでは安定石表の初期化状態の読出しが4箇所から1箇所へ減り、null_window_upperは1482バイトから964バイトになった。alwaysでは最終1マスの独立シンボルがなくなり、2マスカーネルは2897バイトから4038バイトへ増えた。命令数・サイズの減少だけで高速化とは判定しない。

*-diagnostic.tsvは各段階の1周だけの診断で、採否の最終根拠にはしない。rangeはbase、alignedはrange、onceはaligned、legal-cutはalwaysとの比較。legal-cutだけFFO40〜49全体、その他は40〜44。すべての診断でスコアは一致した。legal-cut以外は各局面のノード数も一致した。

inline-ffo.*はonceと通常inline属性の版をFFO40〜44で5周比較した結果。周内比の中央値で約2.31%増、5周すべて遅かった。ただし実際のインライン化を実現していないため、この結果を「呼出し除去のアイデアが悪い」とは扱わない。always-ffo.*はonceとalwaysの5周比較で、4周で短縮、周内比中央値で約1.20%短縮だった。合計時間中央値同士の比では約3.52%短縮に見えるが、主に周内比を使う。

**検証**

反転数は全64升×128盤面について通常のflip計算と照合し、パス側の!playerで空き升ビットが立った場合も一致することを確認する。最終1マスのNWSは全64升×128盤面で、通常のBoardの着手・パス・終局処理から正解値を作り、alphaの境界・基準値の前後・正解値の前後で上下限契約を照合する。合法性の早期カットで正確値と一致しない場合も、返した上下限が正解を挟むことを検査する。

合法性カット試作は、EgaroucidのSIMD盤面を末端まで維持する構造全体を移植したものではない。現deftのスカラー盤面からSIMDへ変換し、着手不能後の反転数計算にはPEXTを使う。Egaroucidはパス時にも、合法性判定で作った相手石のrayをmovemaskで抽出し、相手の反転数へ再利用する。この試作はそのrayを使い捨て、相手側は改めてPEXTを行う。単体のアイデアと、その前後のデータの持ち方・再利用まで同じとは言えない。遅かった場合も、変換費用・追加分岐・再利用不足・コード配置・下限の違いのどれが支配的かは、この比較だけでは分離できない。

今回、MPCの静的ゲート・閾値事前計算・評価状態の再構築削減・5〜6マスの安定石カットは変更していない。これらは前のソース調査に残る候補で、特に5〜6マスの安定石判定は、呼出し費用とカットによる探索量削減を併せて確認する必要がある。Edax/Egaroucidとの新しい直接性能比較も行っていない。
