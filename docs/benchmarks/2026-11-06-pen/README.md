# パターン埋め込みネット（PEN）（2026-11-06）

今の線形のパターン評価に、小さい非線形の項（PEN）を足した。PEN の Deft は、同じデータで学習し直した線形の Deft に、同じ持ち時間で **+45 Elo**、同じレベル（12）で **+95 Elo** だった。Edax 4.5.5 には、レベル1・5・12 で **+140・+101・+88 Elo**（前回の線形の Deft は +51・+36・−24）、Egaroucid 7.8.1 には **+59・+87・+33 Elo**（前回は −17・−17・−67）だった。

設計の考え方は [docs/design/2026-11-06-nnue.md](../../design/2026-11-06-nnue.md) の7章にある。旧版（`feature-new-engine`）の NNUE は精度が高かった（MAE 約4.5）。しかし評価1回が今のパターン評価の約40倍遅かった。PEN は、精度の大部分を保ったまま、読むメモリを少なくすることを狙った。評価1回で、線形の表と埋め込みの表を44回ずつ（計88回、各1キャッシュライン）読む。

## PEN の中身

- 評価値は「線形の項 ＋ PEN の項」である。線形の項は今までのパターン評価と同じ形（パターンの重み・合法手数の差・バイアス）だが、重みは PEN と一緒に学習し直したもので、Release のモデルの値ではない。
- パターンの状態ごとに、線形の重み（i16）のほかに、**8個の i8（8バイト）**を持つ。
- 11パターンそれぞれで4つの向きの8個を足し、0〜127 に clamp する（88個）。ここに、自分と相手の合法手数（各 `min(4 m, 127)`）を足して90個にする。
- 段階ごとの MLP（90 → 32 → 1）に通す。隠れ層は i8 の重みで、0〜127 に clamp する。出力は 1/128 石の単位で、線形の和に足してから丸める。
- 隠れ層は AVX2 の `maddubs` で、入力4つずつを32個の出力に一度に掛ける（NNUE と同じ形）。AVX2 がないときは同じ結果のスカラー版を使う。
- パターンの番号は、今の `EvalState` の差分更新をそのまま使う。accumulator のスタックはいらない。
- モデルファイルは DPR2 版3。重みの後に `PEN1` と60段階の PEN を置き、その後に MPC の校正を置ける。

コードはエンジンの `src/evaluation/pen.rs` と、学習ツールの `src/pen.rs` である。学習ツールは、エンジンの整数計算を小数でなぞる。エンジンで読んだ値と学習ツールの値がずれないことを、テストで確かめている（局面ごとの差は1.5石以内、平均0.4石未満。差の主な原因は、整数の石数に丸めること）。

## データ

[Egaroucid の学習データ](https://www.egaroucid.nyanyan.dev/ja/technology/train-data/)（v0002：Egaroucid 7.8.0 と Edax 4.5.5 のレベル11での対局、5200万局）を取得した。`deft-reversi-train convert` で、[reversi-dataset-gen](https://github.com/ikepggthb/reversi-dataset-gen)（rdg）の `.rd` 形式にした。

- ランダムに打った手より前の局面は使わない。13.73億局面になった。
- 値は、終局の石差（黒 − 白、空きマスは数えない）を手番側から見たもの。
- train / valid / test は、rdg と同じく、局面を正規化したハッシュで分けた（98% / 1% / 1%。train 13.46億、valid と test は各1,373万）。
- 同じ局面が何度出ても、すべて残した。
- データは再配布できないので、リポジトリには入れていない。

以前のデータ（`egaroucid_rd_data_set`）とは分け方が違う。今の Release のモデルは以前の分け方で学習したので、新しい test の局面が学習に含まれている可能性がある。そのため、Release のモデルとは誤差を直接比べられない。

## 学習

線形と PEN を、同じデータ・同じ設定で学習した（[full.sh](full.sh)）。

- 全データ（1段階あたり約2,600万局面）× 8エポック。線形の重みは AdaGrad（lr 0.3）。
- PEN の埋め込みは AdaGrad（`--pen-lr 0.03`）、MLP は 256局面ごとに Adam（`--pen-dense-lr 0.0003`）。
- 学習時間は、このマシン（i3-14100）で PEN が約4時間（4並列）、線形が約3.6時間（2並列）。
- 学習率は、石数40の段階だけで3通りを試して決めた（400万局面 × 3エポック。[results/pilot-*.log](results)）。

| 試し（石数40） | valid の誤差 |
|---|---|
| 線形 | 5.046 |
| PEN（`--pen-lr 0.01`、`--pen-dense-lr 0.001`） | 4.591 |
| PEN（0.003、0.001） | 4.716 |
| PEN（0.03、0.0003） | **4.588** |

## 速さ

中盤150局面（[mid150.obf](../2026-11-03-midgame-speed/mid150.obf)）を深さ10・1スレッド・CPU 固定で読んだ。2回測って同じだった。

| | ノード数 | 時間 | ノード/秒 |
|---|---|---|---|
| 線形 | 6,457万 | 3.2 s | 20.2 M |
| PEN | 6,446万 | 6.0 s | 10.7 M |

- 評価1回あたり約 +43 ns で、同じ深さの探索は約1.9倍の時間になる。
- 最初の実装（MLP を自動のベクトル化に任せたもの）は約5.3倍だった。プロファイルで MLP が87%を占めていたので、AVX2 の `maddubs` で書き直した。探索の結果は、書き直す前と完全に同じである。

## MPC

線形・PEN それぞれに、`deft-reversi-train mpc` で MPC を合わせ直した（1空き数あたり250局面。[mpc.sh](mpc.sh)）。結果は [mpc-pen/](mpc-pen) と [mpc-lin/](mpc-lin) にある（局面の一覧は、データ由来なので入れていない）。

PEN では、浅い探索の値から深い探索の値を予想したときの誤差の幅（σ）が、多くの所で小さくなった。

| | 線形 | PEN |
|---|---|---|
| 中盤 空き30・深さ14 | 3.88 | 3.54 |
| 中盤 空き40・深さ14 | 3.06 | 2.63 |
| 中盤 空き50・深さ14 | 2.18 | 1.99 |
| 完全読み 空き20 | 3.58 | 2.84 |
| 完全読み 空き24 | 3.80 | 2.89 |

浅い中盤（深さ6、空き20〜30）では、PEN のほうが少し大きい。

- どのエンジンも1スレッド、先読みなし。
- 相手を Deft にするときは、`match.py deft ...` で、`OPP_MODEL` のモデルを読ませる（今回足した）。
- 数字は、PEN の Deft から見た値。

## 線形の項なしの PEN

線形の重みを使わず、PEN の MLP だけで評価値を表すモデルも試した（`train --pen --pen-no-linear`）。線形の表を読まずに済めば、評価1回の表引きは88回から44回に減る。

石数40の段階で、全データ（約2,800万局面）で学習した valid の誤差：

| | 1エポック | 2 | 3 | 4 | 8 |
|---|---|---|---|---|---|
| 線形だけ | | | | 4.903 | 4.897 |
| **PEN（線形の項あり）** | 4.363 | 4.263 | 4.226 | **4.200** | 4.169 |
| PEN（線形の項なし） | 4.690 | 4.622 | 4.597 | 4.558 | |

- 線形の項なしは、線形だけより 0.34石よいが、線形の項ありより 0.36石悪い。PEN の改善（0.70石）の半分しか取れない。
- 線形の項なしの学習率は、400万局面での試しで選んだ（`--pen-lr 0.03 --pen-dense-lr 0.003`。ほかに 0.1・0.001、0.3・0.003 を試した。[results/pilot2-*.log](results)。全データは `pilot2-f40-only.log`）。
- 線形の項は、状態ごとに自由な値を1つずつ持つ（1段階あたり約30万）。線形の項なしでは、その分も、パターンごとに8個へ要約し0〜127 に clamp した値から、32ユニットの MLP で作り直す必要がある。この要約と clamp で情報が落ちると考えられる（推測）。
- 速さの得（表引き44回分）に対して精度の損が大きいので、線形の項は残す。

## 完全読み（FFO 40〜59）

PEN でも、完全読みは遅くならなかった（合計 275.9 s。線形 276.4 s、Edax 310.9 s、Egaroucid 288.3 s）。ノード数は約10%減った。詳しくは [2026-11-06-ffo-pen](../2026-11-06-ffo-pen/README.md) にある。

## モデル

| ファイル | 大きさ | sha256 |
|---|---|---|
| PEN ＋ MPC（`mpc-pen/model.dpr2`） | 179 MB | `289e32b7…727ae83` |
| 線形 ＋ MPC（`mpc-lin/model.dpr2`） | 36 MB | `38ad361d…b069c1` |

## まだやっていないこと

- **モデルが大きい。** PEN の埋め込みを60段階それぞれに持つため、36 MB から 179 MB になった。数段階ずつまとめれば小さくできる。
- **MPC の測定が少ない。** 1空き数あたり250局面で、今の Release は1,000局面である。
- 浅い中盤で PEN の σ が少し大きい理由は、まだ調べていない。

## 再現

```sh
T=target-native/release/deft-reversi-train   # RUSTFLAGS="-Ctarget-cpu=native" で作る
$T convert --transcripts transcripts --out egaroucid-rd
$T train --data egaroucid-rd --work full-pen --out full-pen.dpr2 --epochs 8 --lr 0.3 \
  --pen --pen-lr 0.03 --pen-dense-lr 0.0003 --threads 4
$T train --data egaroucid-rd --work full-lin --out full-lin.dpr2 --epochs 8 --lr 0.3 --threads 2
$T eval -m full-lin.dpr2 -m full-pen.dpr2 --data egaroucid-rd --split test --stones 12..63
$T mpc -m full-pen.dpr2 --data egaroucid-rd --out mpc-pen --positions 250 -t 4

cd docs/benchmarks/2026-11-03-engine-match
DEFT_MODEL=mpc-pen/model.dpr2 OPP_MODEL=mpc-lin/model.dpr2 XOT=xot-openingslarge.txt \
  python3 match.py deft time1 250 time1.tsv 1
DEFT_MODEL=mpc-pen/model.dpr2 XOT=xot-openingslarge.txt python3 match.py edax level12 250 edax12.tsv 1
```
