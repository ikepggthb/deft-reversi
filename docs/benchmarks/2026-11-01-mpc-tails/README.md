# MPC の裾の重さの修正

ProbCut は、浅い探索から深い探索の値を予測し、予測の誤差が「deviation の t 倍」を超えそうなら枝を刈る。選択率の段（68%・77%・85%・95%・98%・99%）ごとの t は、これまで正規分布の値（1.0・1.2・1.44・1.96・2.326・2.576）に固定していた。しかし実際の誤差は正規分布より裾が重い。そのため、低い段では想定より刈らず、高い段では想定より多く読み違えていた。99% の段では、想定の約2倍の誤差を見逃していた。

そこで、段ごとの t を校正で測り、エンジンに渡せるようにした。

## 変更

- **エンジン**（`tuning` feature）
  - `ProbCutSigmas { midgame: [f64; 6], exact: [f64; 6] }` を足した。段ごとの t を、中盤の規則と完全読みの規則で別々に持つ。
  - `Engine::set_probcut_calibration(rules, sigmas)` で規則と一緒に渡す。
  - 既定は `ProbCutSigmas::NORMAL`（今までの値）。`set_probcut_rules`・`set_legacy_main_mpc`・モデルファイルの MPC はこれを使うので、今までの探索の動きは変わらない。
  - 刈るときは、反復の段（TT の品質の欄と同じ値）と、規則が完全読みかどうかで t を選ぶ。
  - `write_analysis_settings` には、t が既定と違うときだけ書き足す。既存の設定の識別情報は変わらない。
- **`deft-reversi-train mpc`**
  - すべての組の |深い値 − 予測| / deviation を並べ、各段の確率の分位点を t とする。中盤と完全読みで別々に求める。
  - `rules.json` は `{"sigmas": {...}, "rules": [...]}` の形になった。
  - `tails.tsv` には、空きマス数の帯ごとに、正規分布の t と測った t をそれぞれ超えた割合を書く。
  - 測った局面を、ジョブごとに `positions.tsv` に書き足すようにした。止めても同じコマンドで続きから測る。今回の測定で、強制終了から再開しても重複・欠けがないことを確かめた。
- テスト
  - エンジン：t が刈る距離を決めること、既定値なら設定の出力が変わらないこと、不正な t（非有限・減少）を拒むこと。
  - 学習器：分位点の計算と、`positions.tsv` の読み書き（書きかけの最後の行を飛ばす）。

## 測定

```sh
deft-reversi-train mpc -m e8.dpr2 --data egaroucid_rd_data_set --out mpc-1000 \
  --positions 1000 --empties 12..=52 --exact-empties 12..=24 --max-depth 14 -t 8
```

- モデルは lr 0.3・8エポック（`runs/v2-pattern-lr0.3/e8.dpr2`）。
- valid 分割から、空き12〜52マスの各空きマス数で1,000局面、計41,000局面を選んだ。深さ0〜14を枝刈りなしで探索し、空き12〜24は完全読みもした。
- 組は458,000組で、うち完全読みは13,000組。
- i3-14100（4コア8スレッド）・8スレッドで8時間19分。
- 規則の当てはめ方は前回と同じ。中盤は1次の回帰式、終盤は空きマス数ごとの表。式そのものの見直しは次の段階で行う。
- 結果は [rules.json](rules.json)・[cells.tsv](cells.tsv)・[tails.tsv](tails.tsv)。`positions.tsv`（3.7 MB）は `runs/v2-pattern-lr0.3/mpc-1000/` に置いた。

## 測った t

| 段 | 68% | 77% | 85% | 95% | 98% | 99% |
|---|---:|---:|---:|---:|---:|---:|
| 正規分布 | 1.000 | 1.200 | 1.440 | 1.960 | 2.326 | 2.576 |
| 中盤 | 0.884 | 1.084 | 1.330 | 1.947 | 2.510 | 3.003 |
| 完全読み | 0.918 | 1.124 | 1.367 | 2.013 | 2.549 | 2.977 |

誤差が t を超えた割合（想定はそれぞれ 0.32・0.23・0.15・0.05・0.02・0.01）：

| | 68% | 77% | 85% | 95% | 98% | 99% |
|---|---:|---:|---:|---:|---:|---:|
| 中盤、正規分布の t | 0.265 | 0.189 | 0.123 | 0.049 | 0.027 | 0.018 |
| 完全読み、正規分布の t | 0.282 | 0.202 | 0.132 | 0.054 | 0.031 | 0.019 |

- 低い段では誤差が t を超えにくく、刈る量が想定より少なかった。98%・99% では、超える割合が想定の1.3〜1.9倍だった。
- 空きマス数の帯（12〜24・25〜36・37〜52）ごとに分けても、超える割合はほぼ同じだった（`tails.tsv`）。帯ごとに t を持つ必要はない。

## 探索での比較

規則は同じ1,000局面の校正を使い、t だけを替えて比べた。

- **測った t**：`rules.json`

道具は [tools/](tools/)。`MODEL@rules.json[:normal]` の形でモデルを渡す。`solve` には選択的な終盤探索（`end85` など）を足した。

### 選択的な終盤探索の値は、完全読みとどれだけずれるか

valid 分割から、校正に使っていない局面を空き20・22・24マスで300局面ずつ選んだ（[accuracy900.obf](accuracy900.obf)）。それぞれを段ごとの選択的な終盤探索と完全読みで読み、根の値を比べた。1スレッド・TT 64 MiB で、[accuracy.sh](accuracy.sh) で実行し、[analyze_accuracy.py](analyze_accuracy.py) で集計した（[accuracy-summary.tsv](accuracy-summary.tsv)）。

| 段 | 値がずれた割合（正規分布 → 測った t） | 平均の誤差（石） | ノード数の比（測った t / 正規分布） |
|---|---:|---:|---:|
| 77% | 41.2% → 44.7% | 1.00 → 1.10 | 0.886 |
| 85% | 29.6% → 32.7% | 0.70 → 0.77 | 0.920 |
| 95% | 13.3% → 12.0% | 0.34 → 0.30 | 1.041 |
| 98% | 7.3% → 5.2% | 0.18 → 0.12 | 1.141 |

- 低い段はより多く刈るので、速くなり、値のずれが増える。高い段は刈りすぎが減るので、ずれが減り、遅くなる。
- どちらも、各段を名前どおりの確率に合わせた結果である。
- ここでの「ずれた割合」は根の値の不一致で、1回の刈りの失敗の確率ではない。そのため段の名前の値（例えば 98% なら 2%）とは一致しない。

## わかったこと

- 正規分布の t では、各段が名前どおりの確率で刈っていなかった。低い段は慎重すぎ、98%・99% は読み違いが想定の1.3〜1.9倍あった。測った t にすると、当てはめに使わない局面でも、各段がほぼ想定どおりの割合で刈る。
- 測った t にしても、強さは変わらなかった（レベル11・14）。完全読みの速さもほとんど変わらなかった（120局面で幾何平均 −0.3%、FFO −5%）。
- 固定レベルの速さは、どの段を使うかで変わる。98% の段を使うレベル11は8% 遅く、85% の段が多いレベル14は6% 速い。
- 「98%」が本当に 98% の確率で刈るようになったので、レベル表がどの段を使うかは、改めて速さと強さで選び直せる。例えば、レベル11の空き22〜24マスで 95% を使えば、今までの 98% と同じくらいの読み違いで、ノード数を減らせるはず。これはまだ試していない。

## Edax・Egaroucid との比較

Edax v4.6（`src/search.c` の `selectivity_table`、`src/midgame.c` の `search_probcut`）と、Egaroucid for Console 7.8.1（`src/engine/multi_probcut.hpp` の `SELECTIVITY_MPCT`、`src/engine/level.hpp` の `SELECTIVITY_PERCENTAGE`、`src/tools/probcut/`）のソースを読んだ。どちらも、誤差の実際の分布から t を測ってはいない。

| 段の表示 → t | Edax 4.6 | Egaroucid 7.8.1 | Deft の実測（中盤） |
|---|---|---|---|
| 低い段 | 73% → 1.1 | 74% → 1.13 | 77% → 1.08 |
| | 87% → 1.5 | 88% → 1.55 | 85% → 1.33 |
| | 95% → 2.0 | 93% → 1.81 | 95% → 1.95 |
| 高い段 | 98% → **2.6** | 98% → 2.32 | 98% → **2.51** |
| | 99% → **3.3** | 99% → 2.57 | 99% → **3.00** |
| | | 99.9% → 3.29 | |

正規分布での t と確率の組は、1.1 → 72.9%、1.5 → 86.6%、2.0 → 95.4%、2.32 → 98.0%、2.57 → 99.0%、2.6 → 99.1%、3.29・3.3 → 99.9%。

- **Egaroucid**
  - 表示の確率と t は、すべて正規分布の値と一致する。誤差を正規分布と仮定していて、裾の重さは考えていない。修正前の Deft と同じ考え方である。
  - σ は、測った誤差の標準偏差（`statistics.stdev`）に曲面を当てはめて作る。データの足りない所には、目安の点を手で足す。分布の形は見ていない。
- **Edax**
  - 低い3段の t は、正規分布の値である。
  - 高い2段は、表示が 98%・99% なのに、t は 2.6・3.3 と大きい。正規分布なら 99.1%・99.9% に当たる値である。
  - これは、Deft で測った「本当に 98%・99% になる t」（2.51・3.00）に近い。結果として、裾の重さを見込んだ値になっている。ただし、理由はソースにもコメントにも書かれていない。実測で決めたのか、対局で調整したのかは分からない。
- どちらのエンジンも、レベル表でどの段を使うかは、速さと強さで調整している。そのため、表示の確率がずれていても、段の選び方で補えている。ずれが直接影響するのは、表示される確率の意味と、段を選び直すときの見当である。
- Egaroucid の 99.9% の段（t 3.29）は、表示より大幅に多く読み違えている可能性がある。Deft の測定では、t 3.0 を超える割合が 1.0%、t 4.0 でも 0.31% あり、99.9% には t が 4 よりかなり大きい必要がある。ただし、これは Deft の評価関数で測った値からの推測で、Egaroucid では測っていない。

## 結論

- 測った t を採用し、校正の一部として渡すことにする（`set_probcut_calibration`）。段の名前と実際の確率が一致し、強さと完全読みの速さは変わらない。
- 既定値は正規分布のままにした。旧 main の MPC・モデルファイルの MPC を使う場合の動きは変わらない。
- 次の段階：
  1. 同じ測定データで、中盤・終盤の式（G から導く式など）を比べる。t は式に合わせて測り直す。
  2. レベル表の段の選び方を、速さと強さで選び直す。
