# 探索の値を PEN に合わせ直す（2026-11-06）

[PEN](../2026-11-06-pen/README.md) では、評価1回が線形の約1.9倍重く、MPC の予想の誤差（σ）も小さくなった。評価関数に合わせて決めていた探索の値を、PEN のモデルで測り直した。

## 結果

次の3つを変えた。

| 値 | 前 | 後 |
|---|---|---|
| TT を使わない中盤のゼロ窓探索の深さ（`SIMPLE_SEARCH_DEPTH`） | 5 | **4** |
| ProbCut の事前判定の余裕：完全読みの上側（`PROBCUT_EXACT_UPPER_MARGIN`） | 4石 | **2石** |
| ProbCut の事前判定の余裕：下側（`PROBCUT_LOWER_MARGIN`） | 2石 | **4石** |

PEN のモデルで、中盤（レベル21）が約7%、FFO 40〜59 が約3%速くなった。

| | レベル21 | レベル24 と同じ手 | レベル18 | FFO 40〜59 |
|---|---|---|---|---|
| 前（3回） | 91.0〜91.4 s | 83.3% | 27.7〜28.2 s | 278.2〜280.1 s |
| **後**（組み込んだ定数で測定） | **85.2 s** | 82.7% | 28.4 s | **269.2 s** |

- レベル24 と同じ手を選ぶ割合は、150局面のうち1局面違うだけである（83.3% → 82.7%）。選ぶ手の値とレベル24 の値の差の平均も、1.65 のまま変わらない。
- レベル18 は、どの設定でもほぼ同じだった。

**線形のモデルでは**、中盤は変わらず（レベル21 52.5 → 52.4 s）、FFO 40〜59 が約2%遅くなった（276.4 → 282.5 s）。今後は PEN のモデルを使うので、PEN に合わせた値にした。

## 測り方

- 局面：中盤は [mid150.obf](../2026-11-03-midgame-speed/mid150.obf)（空き32・40・48 を各50局面）、終盤は FFO 40〜59（[ffo40-59.obf](ffo40-59.obf)）。
- モデル：`mpc-pen/model.dpr2`（PEN、MPC は250局面で校正）。
- `examples/solve` を1スレッド、CPU 2 に固定、TT 256 MiB で、1つずつ順に動かした（[bench.sh](bench.sh)、集計は [summarize.py](summarize.py)）。
- 中盤の手の質は、同じモデルのレベル24 の結果（[results/ref-l24.tsv](results/ref-l24.tsv)）と比べた。
- 値を変えるために、一時的に環境変数で定数を置き換えるパッチを当てた（`DEFT_SIMPLE`、`DEFT_ORDERED`、`DEFT_MID_MARGIN`、`DEFT_EXACT_MARGIN`、`DEFT_LOW_MARGIN`、`DEFT_END_ORDER`）。パッチはコミットしていない。
- 結果は [tune.log](tune.log) と [results/](results) にある。

## わかったこと

- **TT を使い始める深さは、PEN では浅いほうがよい。** 残り4手から TT を引くと、ノード数が約9%減った（1,035M → 944M）。評価が重いので、TT で省ける評価の分が、TT を引く手間を上回ったと考えられる（推測）。
- **下側の事前判定の余裕は、広げたほうがよい。** 余裕を広げると、浅い探索を試す回数は増えるが、刈れる枝も増えて、FFO のノード数が約2%減った。PEN では静的評価の予想が当たりやすいので、余裕を広げても無駄な浅い探索が少ないと考えられる（推測）。
- **完全読みの上側の余裕は、狭めたほうがよい。** 浅い探索を試す回数を減らしても、刈れる枝はあまり減らなかった。
- 手を並べない深さ（3）と、1手読みで並べ始める空きマス数（20）は、今の値が一番よかった。

## 見送ったこと：評価そのものを速くする試み

中盤150局面を深さ10で読んだ時間（PEN、前の値）：

| 試したこと | 結果 |
|---|---|
| 隠れ層を AVX-VNNI の `vpdpbusd` で計算 | 6.01 → 6.04 s（変化なし）。コンパイラが、もとの2命令を `vpdpwssd` にまとめていた |
| 埋め込みの行の先読み（prefetch） | 6.04 → 6.2〜6.5 s（遅くなった）。L3 を外れる読み込みは1ノードあたり約0.1回で、表はもともとキャッシュに載っていた |
| 遅延評価（PEN の出力の範囲を足しても窓の外なら、PEN を計算しない） | モデルの重みから求めた PEN の出力の範囲が、石数40で −57〜+58石と広く、窓の外と言える場面がほとんどない。結果を変えずに使えるものにはならないので、実装しなかった |
