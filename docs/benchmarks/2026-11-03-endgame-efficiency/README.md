# 完全読みの探索効率：Edax・Egaroucid との差の調査（2026-11-03）

[空きの多い完全読みの調査](../2026-11-03-endgame-large-empties/README.md)の続きである。FFO の数問ではなく、ランダムな局面を空きマス数ごとに解いて、Deft と Edax 4.5.5・Egaroucid 7.8.1 の差がどこにあるかを調べた。

- エンジン：c433a80
- モデル：`mpc-formula/model.dpr2`
- 条件：1スレッド、TT 256 MiB
- コードの変更：なし。試した変更は、診断用のビルドだけで行った。

## 結論

1. **Edax には、どの空きマス数でも勝っている**（時間で 1〜2割速い）。
2. **Egaroucid との差は、空き16までは無く、空き20〜26で 13〜28%、空き28で 12%**（時間）である。FFO 57・58 の 1.6倍は、その2問に固有のものだった。
3. **空き13以下の探索は、Deft の方が速い。** 空き13の300局面で、Egaroucid の 0.8倍の時間だった。
4. **時間の約80%は、空き13以下の探索である**（perf）。空き14以上のノードの処理（並べ替え・置換表・評価）は、合わせて1割台にすぎない。速くするには、空き14以上でノードを減らすしかない。
5. **空き14〜19の並べ替えは、すでによく当たっている。** カットしたノードのうち、1手目でカットした割合は 94〜96% だった。
6. **並べ替えを深くしても、Egaroucid との差は縮まらなかった。** 試した形は次のとおり。
   - 空き14〜18から、子から1手読む
   - 空き24〜30で、子から2〜3手読む
   - Edax と同じ深さ（空き30で子から6手）
   - 並べ替えの探索を、中盤探索（TT あり）にする
   
   空き28〜30だけ子から2手にすると、FFO 50〜58 で −1.3% だったが、誤差と区別がつかないので入れていない。

評価関数は Egaroucid より弱いが、その差を並べ替えの深さで補うことはできなかった。残る差の原因の候補は、空き14〜20での置換表・ETC・確定石による枝刈りの違いである（まだ調べていない）。

### 測り方

- **空き24〜30**（`engines.py` → [solves.tsv](solves.tsv)、集計は `summarize.py`）
  - 1局面ごとに新しいプロセスで解いた。CPU 2 に固定し、エンジンの順番は局面ごとに回した。
- **空き13〜20**（`batch.py` → [small.tsv](small.tsv)）
  - 1局面が短いので、ファイルごとに1つのプロセスで解いた（CPU 6）。
  - このとき CPU 2 で別の測定を同時に走らせていたので、時間は参考値である。ノード数は影響を受けない。
- すべての局面で、3つのエンジンの答えが一致した。

- ノードの数え方はエンジンごとに違うので、エンジン間の比較では時間を主に見る。

## 2. Deft の中での切り分け

### 空きマス数ごとのノード数と、1手目でカットする割合

[diag-counters.patch](diag-counters.patch) の診断用カウンタで数えた。結果は [diag-results.txt](diag-results.txt) にある。

- **1手目でカットした割合**：空き20の100局面で、空き14〜19のゼロ窓の完全読みのノードを数えた（置換表・ETC・確定石で刈られたノードは除く）。カットしたノードのうち、1手目でカットした割合は 94.2〜96.5% だった。
- **カットしないノード**：偶数の空き（14・16・18）では、約半分のノードが、全部の手を読む必要がある（どの手でもカットしない）ノードだった。この部分は、並べ替えをよくしても減らない。

## 3. 並べ替えを深くする試み

### 子から1手読む範囲（空き16・20の局面）

[ordering-from/](ordering-from) にある（`pos-EE-FROM.tsv`、`FROM=99` は1手読まない）。

| 1手読む範囲 | 空き16の200局面 | 空き20の100局面 |
|---|---|---|
| 空き20以上（今） | 67.9M | 663.0M |
| 空き18以上 | 67.9M | 661.7M |
| 空き16以上 | 67.9M | 658.0M |
| 空き14以上 | 67.5M | 649.0M（時間は +1%） |

### 空き24〜30でさらに深く

[deep-ordering/](deep-ordering) にある（`FROM-TO-dD` は、空き FROM〜TO の並べ替えの深さを D にしたもの。D=3 は子から2手読む）。

| 設定 | 空き24の30局面 | 空き26の30局面 | FFO 50〜58 |
|---|---|---|---|
| 今 | 58.0 s | 241.8 s | 280.9 s |
| 空き24〜30 を子から2手 | 57.4 s | 242.3 s | 311.2 s |
| 空き26〜30 を子から2手 | 57.2 s | 241.5 s | 282.0 s |
| 空き28〜30 を子から2手 | 57.4 s | 241.5 s | 277.2 s |
| 空き24〜30 を子から3手 | 57.3 s | 242.4 s | 318.5 s |
| 空き26〜30 を子から3手 | 57.2 s | 242.4 s | 279.7 s |

空き24・26の局面では、ほとんど差が出ない。根は窓の広い探索で、この変更が効くのは根より下のゼロ窓のノードだけだからである。

### Edax と同じ深さ、並べ替えの探索を中盤探索にする

FFO 53・57・58 で試した（ノード数）。

Edax の深さは、子から (空き − 15)/3 手（空き27以上は +1）である。cap はその上限を表す。

| 設定 | 57 | 53 | 58 |
|---|---|---|---|
| 今 | 1.40G | 1.16G | 1.17G |
| Edax の深さ（上限なし） | 1.47G | 1.87G | 4.55G |
| Edax の深さ（cap 2） | 1.58G | 1.48G | 2.38G |
| Edax の深さ（cap 4） | 1.47G | 1.61G | 2.87G |
| 並べ替えの探索を中盤探索にする（深さは今と同じ） | 1.42G | 1.32G | 1.18G |
| 中盤探索にして、Edax の深さ（cap 3） | 1.43G | 1.59G | 1.49G |

- Deft の並べ替えの探索は、TT のない素の αβ である。深くすると、並べ替えそのものが重くなる。
- 中盤探索（TT あり）にしても、深くするほどノード数は増えた。浅い探索の結果が主 TT の深い結果を追い出している可能性もある。
