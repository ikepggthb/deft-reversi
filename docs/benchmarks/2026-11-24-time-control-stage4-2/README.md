# 持ち時間制：段階4-2 作る予測を決める（価値の信号は今のログで作れるか／その2：探索の副産物と2番目の手との差）

> develop/v2 には `tools/time-control/` を入れていない。ここに出てくるツールは `research/time-predict`（commit 9238780）または `ccr-a29b8244-tag4vo` にある。

時間管理の予測を精度よくする作業（[ロードマップ](../../design/2026-11-20-time-control-roadmap.md)）の段階4-2。段階4-1（[記録](../2026-11-24-time-control-stage4-1/README.md)）で、伸びしろは時間の予測ではなく「次の反復で手が良くなるか」（価値、ロードマップの B1）の判断にあると分かった。ここでは、(1) 今のログにある情報で、その判断をどこまで当てられるかを調べ、(2) その精度の信号で止めると何石減るかをシミュレーターで見た。

**シミュレーションの結果で、対局での石差ではない。** データはどちらも調整用の開局（200〜299 の通常の対局、300〜449 の延長モード）。

## 結論

- **作る予測は価値（B1）に絞る。** 時間の予測（A1〜A4）は正解にしても 0.2 石以下、予約（A6）と配分（C3）は変えても得にならない（段階4-1）。価値の正解は −0.11〜−0.47 石。
- **ただし、今のログの情報だけでは、今の不安定度とほとんど変わらない信号しか作れない。** 反復の種類・最善手の変化・評価値・探索の量・盤面の30ほどの特徴量でロジスティック回帰を作り、開局で分けた交差検証で測ると、AUC は 0.80（遷移ごとに 0.70〜0.76）。今の不安定度と同じ外れる率で比べると、当たる率は 0.04〜0.09 上がるだけ（中盤 0.31 → 0.35、ENTRY 0.33 → 0.42、ステージ 0.51 → 0.58、EXACT 0.48 → 0.54）。
- **その差は 1局・片方あたり 0.004〜0.029 石。** 同じ作りの信号どうし（外れ方が独立な0/1の信号）で比べると、区間はほぼ0をまたがないが、大きさは対局で区別できない程度。
- **大きく減らすには、当たる率 0.75・外れる率 0.1 くらいの信号が要る**（今の不安定度の精度の信号より −0.06〜−0.18 石）。当たる率 0.5・外れる率 0.15 では −0.01〜−0.06 石。今のログにない情報が要る。
- **訂正：段階4-1その3の「当たる率 0.5・外れる率 0.15 で −0.04〜−0.16 石」は、今の時計との差。** そのうち 2秒の約 0.10 石は、信号の精度ではなく信号の作り（外れ方が独立）から来ていた。今の不安定度と同じ精度の0/1の信号でも、2秒では今の時計より −0.10 石（ほかの条件は0をまたぐ）。精度の効果は、同じ作りの信号どうしで比べた上の値で読む。
- **今の不安定度を0/1にするだけ（`instbin`）では変わらない**（±0.03 石以内、向きはそろわない）。

## 考察

- 「次の反復で手が良くなるか」を今のログから当てる力は、ほぼ「最善手が変わったか」で尽きている。今の不安定度はその情報をすでに使っているので、作り直しても伸びない。
- 大きく伸ばすには、手が入れ替わりそうかを直接示す情報が要る。候補は、ルートの上位2手の評価値の差（2番目の手がどれだけ迫っているか）、1手目以外に使ったノードの割合、反復の途中で最善手の評価が窓を外れた回数。どれもエンジンの中で数えられるはずだが（確かめていない）、今の `Progress` にはない（公開 API への追加になる）。`Progress::moves`（`all_moves`）は最後の反復の後だけで、反復ごとには出ない。
- 段階4-1その3で今の時計との差として出した値のうち、2秒の約 0.10 石は信号の作りによるもの。理由は確かめていないが、「外れ方が独立な信号」は同じ精度でも今の不安定度と時間の使い方が違う（今の不安定度は最善手が変わった後の数反復に続けて出る）ためと考えられる。2秒ではそれが得になるが、規則としてわざと散らす理由は見つかっていない。

## 残った課題

1. **新しい情報で価値を当てられるかを確かめる（段階4-2の続き）。** 調整用の局面の一部（中盤の遷移で数千組）で、反復ごとのルート上位2手の差などを probe で測り、当たる率 0.75・外れる率 0.1 に近づくかを見る。近づくなら、それを `Progress` に足す（追加のみ）。
2. 近づかないなら、時計の作り直し（段階5）で得られるのは 1局・片方あたり数百分の1石の大きさで、対局で確かめられない。その場合は、今の時計のまま、その2の最初の反復の扱いなど別の所を見る。

# その2：探索の副産物と、2番目の手との差（2026-11-24）

その1の残った課題1。ログにない情報で「次の反復で手が良くなるか」が当たるようになるかを、測定用のプログラム（probe）で調べた。比べた情報は2種類：

- **ただで取れる情報（探索の副産物）**：探索を変えずに数えるだけのもの。ルートで最初に調べた手（前の反復の最善手）以外に使ったノードの割合、最初の手より良いとわかって読み直したルートの手の数（fail-high）、aspiration window を広げた回数。エンジンに数える処理を足し、`Progress::root`（`RootStats`）で反復ごとに出すようにした（公開 API への追加。探索は変えていない）。
- **2番目の手との正確な差**：同じ反復を、ルートの全部の手を全幅で読み直して（`all_moves`）求める。対局で毎回求めると探索が遅くなるので、ここでは「もし分かったら」の比較のためだけに測る。

**シミュレーションと測定の結果で、対局での石差ではない。**

## 結論（その2）

- **ただで取れる情報は、ほとんど足しにならない。** ログの情報に足しても AUC は +0.01〜0.02、今の不安定度と同じ外れる率での当たる率は変わらない（±0.03）。
- **2番目の手との正確な差は効くが、目標には届かない。** 足すと AUC は +0.05〜0.08（0.80〜0.84。ログの情報だけからは +0.07〜0.09）、当たる率は 0.59〜0.64（外れる率約 0.19）。当たる率 0.75・外れる率 0.1 には遠い。
- **差が分かっても、石では 1局・片方あたり −0.02〜−0.09。** 対局データの率に、差を足したときの当たる率の上がり分を乗せてシミュレーションすると、今の不安定度と同じ精度の信号より −0.022（4スレッド）〜−0.086（2秒）石（補い方4通りすべてで区間が0をまたがない）。これは差を求める費用を入れる前の値。
- **差を求める費用のほうが大きいと見込まれる。** 時間を 10% 減らすと 1局・片方あたり約 0.07〜0.11 石悪くなる（段階3-2の条件ごとの損失からの大まかな目安）ので、上の得は時間の 2〜8% ぶんにしかならない。一方、今の探索ですでにノードの 29〜40% は最初の手以外に使われており、差を確かめるにはこれらの手をより厳しい窓で読み直す必要がある。全部の手を全幅で読む方法（今回の測定）は、試し流しで本探索の約3倍の時間がかかった。安い方法（差が δ 以内の手があるかだけを調べる）の費用は測っていないが、数%に収まるとは考えにくい。
- **したがって、価値の信号のために探索の情報を足すことは勧めない。** 今の時計の判断（不安定度）を作り直して得られるのは、今ある情報では 1局・片方あたり 0.03 石以下。

- 最初の手以外に使ったノードの割合は、「2番目の手が迫っている」ことを表すと期待したが、ほとんど情報がなかった。手が入れ替わるかどうかは、そこに使ったノードの量より、評価値の差そのもので決まっている。
