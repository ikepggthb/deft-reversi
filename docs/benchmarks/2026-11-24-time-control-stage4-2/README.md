# 持ち時間制：段階4-2 作る予測を決める（価値の信号は今のログで作れるか）

時間管理の予測を精度よくする作業（[ロードマップ](../../design/2026-11-20-time-control-roadmap.md)）の段階4-2。段階4-1（[記録](../2026-11-24-time-control-stage4-1/README.md)）で、伸びしろは時間の予測ではなく「次の反復で手が良くなるか」（価値、ロードマップの B1）の判断にあると分かった。ここでは、(1) 今のログにある情報で、その判断をどこまで当てられるかを調べ、(2) その精度の信号で止めると何石減るかをシミュレーターで見た。

**シミュレーションの結果で、対局での石差ではない。** データはどちらも調整用の開局（200〜299 の通常の対局、300〜449 の延長モード）。

## 結論

- **作る予測は価値（B1）に絞る。** 時間の予測（A1〜A4）は正解にしても 0.2 石以下、予約（A6）と配分（C3）は変えても得にならない（段階4-1）。価値の正解は −0.11〜−0.47 石。
- **ただし、今のログの情報だけでは、今の不安定度とほとんど変わらない信号しか作れない。** 反復の種類・最善手の変化・評価値・探索の量・盤面の30ほどの特徴量でロジスティック回帰を作り、開局で分けた交差検証で測ると、AUC は 0.80（遷移ごとに 0.70〜0.76）。今の不安定度と同じ外れる率で比べると、当たる率は 0.04〜0.09 上がるだけ（中盤 0.31 → 0.35、ENTRY 0.33 → 0.42、ステージ 0.51 → 0.58、EXACT 0.48 → 0.54）。
- **その差は 1局・片方あたり 0.004〜0.029 石。** 同じ作りの信号どうし（外れ方が独立な0/1の信号）で比べると、区間はほぼ0をまたがないが、大きさは対局で区別できない程度。
- **大きく減らすには、当たる率 0.75・外れる率 0.1 くらいの信号が要る**（今の不安定度の精度の信号より −0.06〜−0.18 石）。当たる率 0.5・外れる率 0.15 では −0.01〜−0.06 石。今のログにない情報が要る。
- **訂正：段階4-1その3の「当たる率 0.5・外れる率 0.15 で −0.04〜−0.16 石」は、今の時計との差。** そのうち 2秒の約 0.10 石は、信号の精度ではなく信号の作り（外れ方が独立）から来ていた。今の不安定度と同じ精度の0/1の信号でも、2秒では今の時計より −0.10 石（ほかの条件は0をまたぐ）。精度の効果は、同じ作りの信号どうしで比べた上の値で読む。
- **今の不安定度を0/1にするだけ（`instbin`）では変わらない**（±0.03 石以内、向きはそろわない）。

## 方法

### (1) ログから当てられるか（`tools/time-control/value_signal.py`）

| 項目 | 内容 |
|---|---|
| 行 | 段階3-2の参照で損失が分かる手番の、続けて終わった反復の組 (k, k+1)。109,683組（通常の対局5条件と、延長モードの延長した手番）。中盤→終盤の最初のステージの組（ENTRY）、ステージ間、EXACT、中盤どうし。中盤に戻る組は除く |
| ラベル | k+1 の手の損失が k の手の損失より小さい（手が良くなる）。全体の 7.2%（中盤 6.6%、ENTRY 22.2%、ステージ 3.5%、EXACT 1.1%） |
| 特徴量 | 反復 k が終わった時点で時計に分かるもの。遷移の種類／最善手が変わったか・変わった回数・最後に変わってからの反復数・不安定度／評価値・その変化・読み筋の長さ／空き数・深さ・ステージ・何回目の反復か・時間・ノード数・時間の比・置換表から始めたか・予測時間と経過時間の比／合法手の数・領域・奇数領域・スレッド数／遷移と主な項の積。段階的に足した6通り |
| モデル | L2 付きロジスティック回帰（numpy、ニュートン法） |
| 評価 | 開局で5つに分けた交差検証（1つの開局の対局は同じ組に入る）。AUC と、外れる率（良くならない組で信号が出る率、FPR）を決めたときの当たる率（良くなる組で信号が出る率、TPR）。遷移ごとに基準の率が大きく違うので、遷移ごとにも出す |

### (2) その精度で止めると何石減るか（`sim.py signal`）

段階4-1その3の `vinst` と同じ。今の止め方の不安定度を0/1の信号に差し替え、信号は「次の反復で手が良くなる」ときに確率 TPR、良くならないときに確率 FPR で出す。TPR と FPR は遷移ごとに (1) の値を入れる。

| 信号 | 中盤 | ENTRY | ステージ | EXACT |
|---|---|---|---|---|
| legacy-rates（今の不安定度 ≥ 0.5 と同じ率） | 0.306 / 0.132 | 0.332 / 0.175 | 0.508 / 0.210 | 0.481 / 0.201 |
| model-at-legacy-fpr（モデルを同じ FPR で） | 0.349 / 0.132 | 0.419 / 0.175 | 0.580 / 0.210 | 0.541 / 0.201 |
| model-at-0.15（モデルを FPR 0.15 で） | 0.388 / 0.15 | 0.360 / 0.15 | 0.479 / 0.15 | 0.459 / 0.15 |
| target | 0.5 / 0.15 | 0.5 / 0.15 | 0.5 / 0.15 | 0.5 / 0.15 |
| 0.75/0.1 | 0.75 / 0.1 | 0.75 / 0.1 | 0.75 / 0.1 | 0.75 / 0.1 |
| truth | 1 / 0 | 1 / 0 | 1 / 0 | 1 / 0 |

`instbin C`：今の不安定度を、C 以上なら1、そうでなければ0にする（今の時計でそのまま使える規則）。

差は「変種 − legacy-rates」（`signal-vs-rates-*.txt`、時間をそろえた `=t` どうし）と「変種 − 今の時計」（`signal-*.txt`）。補い方4通り（h1、flat、d22、h2）、世界8通り、開局を単位にしたブートストラップの95%区間。

```
tools/time-control/value_signal.py table local/time-control/stage3/run-v4 local/time-control/stage3/refer-v4 > pairs.tsv   # 109,683組、2秒
tools/time-control/value_signal.py fit pairs.tsv > fit.txt                                                                  # 13秒
export SIM_SIGNALS="legacy-rates:mid=0.306/0.132,entry=0.332/0.175,stage=0.508/0.210,exact=0.481/0.201;model-at-legacy-fpr:mid=0.349/0.132,entry=0.419/0.175,stage=0.580/0.210,exact=0.541/0.201;model-at-0.15:mid=0.388/0.15,entry=0.360/0.15,stage=0.479/0.15,exact=0.459/0.15;target:mid=0.5/0.15,entry=0.5/0.15,stage=0.5/0.15,exact=0.5/0.15;0.75/0.1:mid=0.75/0.1,entry=0.75/0.1,stage=0.75/0.1,exact=0.75/0.1;truth:mid=1/0,entry=1/0,stage=1/0,exact=1/0"
tools/time-control/sim.py signal local/time-control/stage3/run-v4 local/time-control/stage3/refer-v4 8 1 > signal-h1.txt
SIM_BASE="vinst legacy-rates =t" tools/time-control/sim.py signal ... 8 1 > signal-vs-rates-h1.txt
#   flat：SIM_DEPTH_BUCKETS=0、d22：SIM_MID_POOL_DEPTH=22、h2：最後の引数 2
```

1回の `signal` は約3分（1コア）。

## 考察

- 「次の反復で手が良くなるか」を今のログから当てる力は、ほぼ「最善手が変わったか」で尽きている。今の不安定度はその情報をすでに使っているので、作り直しても伸びない。
- 大きく伸ばすには、手が入れ替わりそうかを直接示す情報が要る。候補は、ルートの上位2手の評価値の差（2番目の手がどれだけ迫っているか）、1手目以外に使ったノードの割合、反復の途中で最善手の評価が窓を外れた回数。どれもエンジンの中で数えられるはずだが（確かめていない）、今の `Progress` にはない（公開 API への追加になる）。`Progress::moves`（`all_moves`）は最後の反復の後だけで、反復ごとには出ない。
- 段階4-1その3で今の時計との差として出した値のうち、2秒の約 0.10 石は信号の作りによるもの。理由は確かめていないが、「外れ方が独立な信号」は同じ精度でも今の不安定度と時間の使い方が違う（今の不安定度は最善手が変わった後の数反復に続けて出る）ためと考えられる。2秒ではそれが得になるが、規則としてわざと散らす理由は見つかっていない。

## 残った課題

1. **新しい情報で価値を当てられるかを確かめる（段階4-2の続き）。** 調整用の局面の一部（中盤の遷移で数千組）で、反復ごとのルート上位2手の差などを probe で測り、当たる率 0.75・外れる率 0.1 に近づくかを見る。近づくなら、それを `Progress` に足す（追加のみ）。
2. 近づかないなら、時計の作り直し（段階5）で得られるのは 1局・片方あたり数百分の1石の大きさで、対局で確かめられない。その場合は、今の時計のまま、その2の最初の反復の扱いなど別の所を見る。
