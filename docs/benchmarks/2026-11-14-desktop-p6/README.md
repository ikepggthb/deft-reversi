# デスクトップ版の性能測定（P6、2026-11-14）

`docs/desktop-plan.md` §11 の目標に対する、deft-reversi-desktop の測定結果。

## 条件

- Windows 11 Home、論理CPU 20。表示は 240 Hz。
- release ビルド（`cargo build --release -p deft_reversi_desktop`）。モデルは `deft-eval-v2-pattern-lr0.3.dpr2`。
- エンジンは 8 スレッド、TT 128 MiB（アプリの既定）。
- 計測ログは `DEFT_DESKTOP_TRACE=1` のときだけ標準エラーに出る。内容は、反転アニメーション1回ごとのフレーム間隔と、着手探索1回ごとのノード数・時間。
- 手順は [tools/measure.ps1](tools/measure.ps1)。エンジン単体の比較は [tools/headless_nps.rs](tools/headless_nps.rs)（`deft-reversi-engine/examples/` に置くと動く）。

## 結果

| 指標 | 目標 | 結果 | 判定 |
|---|---|---|---|
| 起動（盤面の表示） | コールド1 s、ウォーム500 ms以内 | 初回フレーム 106〜127 ms（5回） | 達成 |
| AI準備完了 | 記録のみ | 110〜132 ms（モデル読込 19〜25 ms、`Engine::new` 27〜28 ms） | — |
| 描画（反転アニメーション中） | p95 16.7 ms以内 | 1回あたり約36〜47フレーム。p95 4.3〜4.8 ms、最大 5.2 ms（240 Hz） | 達成 |
| 待機CPU | 1コア換算1%未満 | 起動4秒後から10秒間で 0.00〜0.16%。最初の1回だけ 2.19% | 概ね達成（下記） |
| メモリ | 内訳を記録 | 作業セット 219 MiB（大半はTT 128 MiBとモデル） | — |
| 探索への影響 | 悪化が中央値5%以内 | GUIのAI同士（Lv 20、1局60手）は 116〜119 M nodes/s。エンジン単体で着手の間に同じ250 msの休みを入れると 112〜115 M nodes/s | 悪化なし（下記） |
| 入力応答・停止 | p95 50 ms / 100 ms | 未測定 | — |

### 待機CPU

最初の測定では 2.5〜4.5% あった。効果音の出力ストリームを起動時に開いたままにしており、無音を合成し続けていたのが原因。鳴らすときに開き、最後の音から3秒で閉じるようにした。その後の3回では、2回が 0.2% 未満だった。残る1回の 2.19% は、起動直後（4〜14秒）の測定区間に起動処理の残りが含まれた可能性がある。

### 探索への影響

エンジン単体で着手を休みなく続けると 128〜140 M nodes/s。着手の間に 250 ms 休むと 112〜115 M nodes/s に下がる（各3回）。CPUが一度休むと、次の探索の立ち上がりで遅くなるためと考えられる。GUIのAI同士は、着手の間に 250 ms の表示用の間を置いている。同じ条件のエンジン単体と比べると、GUIは同等かやや速い。GUIの描画・イベント処理による探索の悪化は見られない。

人間対AIでも、人間が考えている間はCPUが休むので、同じ影響を受ける。これを避けるには、待機中もワーカースレッドを起こしておく必要がある。ただし、それは待機CPUの目標と両立しない。
