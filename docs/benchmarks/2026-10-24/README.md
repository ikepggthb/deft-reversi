# リライト検証・性能測定（2026-10-24）

> 初回実装時点の測定履歴です。旧版比較は低水準APIとの比較であり、通常利用時の性能の根拠にはできません。[通常APIでの再測定](../2026-10-24-public-solve/README.md)と[終盤探索の復元](../2026-10-24-endgame-restore/README.md)を参照してください。

## 検証

- 通常テスト: 38件成功、ストレス1件は明示実行。
- native release: ストレスを含む全39件成功。
- Clippy: 通常・nativeの両構成で `--all-targets -- -D warnings` が成功。
- 実際のv4パターンモデルをDPR2に変換し、比較局面すべてで評価値・探索スコアが旧版と一致。
- 並列測定の全5周・1/2/4/8/20スレッドで完全読みスコアが一致。
- 固定局面の生成スクリプトを再実行し、保存内容が再現することを確認。

## 単一スレッドの新旧比較

各集合の合計探索時間を5回測り、中央値で比較した。倍率は旧版時間÷新版時間。1より大きいほど新版が速い。

| 対象 | 旧版 | 新版 | 倍率 |
|---|---:|---:|---:|
| 中盤24局面・深さ8 | 0.214363秒 | 0.145497秒 | 1.473倍 |
| FFO 1–19・完全読み | 0.216390秒 | 0.058010秒 | 3.730倍 |
| FFO 40–44・完全読み | 8.295109秒 | 9.180300秒 | 0.904倍 |

中盤と小さな終盤集合では明確な改善を確認した。**重いFFO 40–44では新版が約11%遅く、すべての局面で高速化したわけではない。**
特にFFO 43の単一スレッド性能が残る課題。完成済みの機能と、追加の性能調整が必要な部分を区別する。

## 新版の並列性能

同じFFO 40–44を各スレッド数で5周測定した。各周の順番は往復させ、比較する測定は同時に走らせていない。
倍率は新版の単一スレッド時間÷各時間。

| スレッド数 | 中央値 | 単一スレッド比 |
|---:|---:|---:|
| 1 | 9.206839秒 | 1.000倍 |
| 2 | 4.752575秒 | 1.937倍 |
| 4 | 2.781151秒 | 3.310倍 |
| 8 | 1.859530秒 | 4.951倍 |
| 20 | 1.593855秒 | 5.776倍 |

CPU割当はPコアを先に使い、20スレッドではEコアも含める。具体的なCPU番号は `parallel.json` に記録した。
ハンドオフ数とjoin時間も `parallel.tsv` に保存した。join時間には子孫の仕事を手伝った時間も含み、純粋なアイドル時間ではない。

## 条件と注意

- CPU: Intel Core Ultra 7 265K。単一スレッド比較は新旧ともCPU 1に固定。
- Rust: `RUSTFLAGS=-Ctarget-cpu=native`、release、fat LTO、codegen-units=1、panic=unwind。
- メインTT: 256 MiB。旧版には実装固有のPV用表もある。
- 評価: 同一の学習済みパターン重み、整数石単位、MPCなし。旧版の `solve_eval` / `solve_final` と新版の反復深化ドライバを比較。
- 初期化とモデル読込は探索時間に含めない。
- 旧版は毎局面で新しいSolverとスレッドを作り、グローバルTTとスレッド内TTを初期化。新版も比較ツールでは局面ごとにTTを初期化。
- 並列測定では各実行を新しいプロセスにし、その実行内の局面間ではTTを再利用。新旧比較と並列表の単一スレッド時間は別測定。
- 最初の試行で旧版の `clear_tt()` を空表化と誤認した結果は破棄した。ここに掲載するデータは修正後の測定のみ。
- CPUや局面集合が変われば結果は変わる。ノード数の数え方は旧版と異なるためNPSだけで比較しない。

## 再現

`deft_reversi_engine_v2/README.md` にビルド・変換・実行方法を記載した。
`tools/bench_rewrite_parallel.py` はCPU割当・スコア一致を検証し、生データとハッシュを保存する。
`environment.json` に参照コミット、モデル・バイナリ・局面・ソースのハッシュ、Rustのバージョン、検証件数を保存した。

生データは同じディレクトリの `*.tsv`、各集合の最小・最大・各周の値は `*-statistics.json`。

## Remoteの停止について

表示された `failed to load workspace requirements: not a directory` は探索コマンドの失敗ではなかった。
Git worktreeの元リポジトリの `.codex` が空の通常ファイルになっており、設定ファイルの参照でENOTDIRが発生していた。
そのファイルを `.codex.empty-file.backup` に退避し、同名ディレクトリを作成。設定パスが正常に不存在を返すことを確認した。
Remote UIでの次ターンの成否は、このファイル構造の確認とは別に扱う。参照先のRustソースには変更していない。
