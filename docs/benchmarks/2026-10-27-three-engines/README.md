2026-10-27 現deft・Edax・Egaroucidの1コア終盤比較

対象は現在のdeft作業ツリー（refactor/engine-layout、基点8ab1682、直近の合法手共有・評価状態更新の改善を含む）、Edax 786421f355219ade872ce7285c1cab1eaf67836a、Egaroucid 2a65c87860be999373088ad833aa00b0844883b6。Egaroucidは通常のSIMD版と、今回追加ビルドしたAVX-512版を両方測定する。

**測定条件**

- AMD EPYC 9V74仮想環境、CPU 0固定、1スレッド、時間・ノード数の上限なし。
- FFO40〜49の10局面、20〜26空き。各局面を新プロセス・空TTで実行する。
- 主TTは全構成8,388,608項目。deftは主TT 256 MiB＋PV 16 MiB、Edaxは-h 23で主TT約192 MiB＋PV約12 MiB＋shallow約12 MiB、Egaroucidは-hash 23で主TT約192 MiB。局所表や管理領域、静的な予約領域は別であり、総メモリ使用量が同じという条件ではない。
- deftはexact＋旧main MPC、Edax・Egaroucidはlevel 60。EdaxとEgaroucidのbookを明示的に無効化する。最終結果は深さが空き升数まで到達し、非選択的な完全読みを完了することを検査する。
- deftはmainの実evalを変換したDPR2モデル、Edax・Egaroucidはそれぞれ付属する実評価データを使用する。評価器とMPC設定はエンジンごとに異なり、同一評価関数の探索カーネルだけを比較する試験ではない。
- 各エンジンが報告する探索時間を比較する。モデル読込・プロセス起動・主TT確保は計時外で、準備・反復探索を含む。deftの安定石表は初回探索中にLazyLockで初期化され、Edax/Egaroucidの対応表は起動時に初期化される。これを純粋な定常カーネル速度と同一視しない。
- プロセス全体の経過時間もprocess_wall_secondsに保存するが、上記探索時間と混ぜて集計しない。
- 性能測定中はビルド・テスト・他の探索を並行実行しない。

EdaxとEgaroucidの主表は24バイト/項目、deftは32バイト/項目であり、設定の違いを隠して「全て256 MiB」とは表現しない。Edaxの-hはMiB指定ではない。EgaroucidのHash_nodeはBoard 16バイト＋Hash_data 7バイト＋Spinlock 1バイトで24バイト。両バイナリのtransposition_tableシンボルは0x30000078バイトで、既定の2^25項目の静的予約と管理領域に対応する。23指定時の有効範囲は約192 MiBで、静的予約全体を使う指定ではない。

4構成の実行順はWilliams designの4通りを使い、各局面について8周する。各構成が各順番を2回占め、直前に走る構成の組合せも均等になる。局面ごとにも順番をずらす。各実行の直後にTSVと標準出力・標準エラーのJSONLを書き出す。

**ビルド・データ**

deftはRust 1.99.1、release、fat LTO、codegen-units=1、-C target-cpu=native、既定feature。バイナリは直前の全61テストと反復比較を通過した37c7921866885a22a7e8b407e253d3d85a4f54ea7977a9ca2ca8417fbbcc0ae8を固定した。

Edaxと通常SIMD版Egaroucidは既存のnativeビルドを使用した。前のビルド記録はEdaxがGCC 14.2で-Ofast -flto -march=native、EgaroucidがG++ 14.2で-O3 -flto -march=native -DHAS_AMD_PROCESSOR。AVX-512版は同じソースとG++ 14.2で次のように追加ビルドした。

```sh
g++ -std=c++20 -O3 -flto -march=native -DHAS_AMD_PROCESSOR \
  -DHAS_AVX512 -pthread src/Egaroucid_for_Console.cpp \
  -o bin/Egaroucid_for_Console_AVX512.out
```

Egaroucidの表示バージョンはソースのEGAROUCID_ENGINE_VERSIONによる7.8。CMakeListsのprojectバージョンとは異なるため、比較の識別にはコミットとバイナリハッシュを使う。AVX-512版も20空きの事前確認でスコア38・20@100%を返し、このCPUで動作することを確認した。

setup.jsonに実行ファイルのハッシュ、environment.jsonにコミット・コンパイラ・CPU・評価ファイルのハッシュを保存する。測定用には実行ファイルを/tmpへコピーして固定し、Egaroucidの評価データへのリンクをその横に配置した。探索ソースは今回変更していない。

**Egaroucidのハッシュ表データを固定する理由**

付属するresources/hashにはhash25〜27だけがあり、hash23がない。通常は起動時にhash_init_rand(23)へフォールバックし、時刻由来の乱数で主TTのハッシュ関数が実行ごとに変わる。

今回はmake_egar_hash.cppで、Egaroucid自身のhash_init_rand(23)に固定シード0x20261027を与えて一度生成した。エンジンのハッシュ生成アルゴリズムは変更していない。通常SIMD版とAVX-512版は同じファイルを全実行で使用する。付属の学習済みhash23を入手したという意味ではなく、標準フォールバックを固定した条件である。

生成ファイルは2,097,152バイト、SHA-256は0a44b764e10b250229d25a007cda5a16857733b92d8566b65d95243739b7d323。元のチェックアウトのresources/hashは変更せず、測定用コピーのresources/hash/hash23.eghsへ配置した。前の測定は時刻乱数のフォールバックだったため、前の時間との差をそのままコード改善の効果とは扱えない。

```sh
g++ -std=c++20 -O3 -march=native -DHAS_AMD_PROCESSOR \
  -I /path/to/Egaroucid/src make_egar_hash.cpp -o /tmp/make-egar-hash
/tmp/make-egar-hash /path/to/benchmark/resources/hash/hash23.eghs
```

**正解と測定スクリプト**

ffo40-49.obfは共通の入力局面、ffo40-49-answers.obfはEdaxの付属問題集から得た正解の出典である。正解値は順に38、0、6、-12、-14、6、-8、4、28、16。全エンジンに渡すファイルは局面と手番だけで、正解値を探索へ渡さない。

compare.pyはdeftのExact/Completed、Edaxの非選択的な最終深さ、Egaroucidの最終深さ@100%を検査し、全結果を正解値と照合する。失敗・未完了の実行を時間だけの結果として混ぜない。ノード数も保存するが、エンジン間でノードの数え方が違うため、その比やNPSを単純に優劣の根拠にしない。同じエンジンのノード数が反復間で安定するかは別途検査する。

```sh
python3 compare.py --root /tmp/deft-three-engines-20261027 \
  --model /tmp/deft-eval-main.dpr2 --positions ffo40-49.obf \
  --answers ffo40-49-answers.obf --out run --rounds 8 --cpu 0
```

root以下にはdeft/engine、edax/engine、egar_simd/engine、egar_avx512/engineと必要なresourcesを置く。Edaxの評価ファイルはスクリプト内の絶対パスで指定しているため、別環境で再現する場合は合わせて変更する。smoke/は本測定に含めない事前確認の出力である。

**測定結果**

全320実行で、正解スコア・最善手・空き升数までの完全読みが一致した。同じエンジン・同じ局面のノード数は全反復で一定だった。Egaroucidの2ビルドも各局面のノード数が一致している。条件・配置・データのハッシュは測定後も変わっていない。

各周の10局面の探索時間を合計し、その8周の中央値を取った結果：

| エンジン | 10局面合計の中央値 | 最小〜最大 |
|---|---:|---:|
| Edax | 19.400000秒 | 19.066000〜19.788000秒 |
| Egaroucid AVX-512 | 21.187500秒 | 20.566000〜22.149000秒 |
| 現deft | 21.838293秒 | 21.184755〜22.810141秒 |
| Egaroucid SIMD | 22.101500秒 | 21.122000〜22.679000秒 |

時間比については、合計時間の中央値同士の比と、各周でdeft/相手を計算してから取った中央値を併記する。この2つは異なる統計量で、同じ値にはならない。

| 相手 | 合計時間中央値同士のdeft/相手 | 周内deft/相手比中央値 | deftが短縮した周 | deftが速い局面数（局面別中央値） |
|---|---:|---:|---:|---:|
| Edax | 1.125685（+12.57%） | 1.138225（+13.82%） | 0 / 8 | 1 / 10 |
| Egaroucid SIMD | 0.988091（-1.19%） | 0.977105（-2.29%） | 5 / 8 | 2 / 10 |
| Egaroucid AVX-512 | 1.030716（+3.07%） | 1.035586（+3.56%） | 1 / 8 | 2 / 10 |

周内比中央値では、deftの所要時間はEdaxより約13.82%長く、Egaroucid AVX-512版より約3.56%長い。通常SIMD版よりは約2.29%短いが、短縮した周は5/8であり、僅差で変動もある。合計中央値同士の比では、それぞれ約12.57%増、3.07%増、1.19%短縮になる。都合のよい統計量だけを選んで「Egaroucidを追い越した」とは結論しない。

**解釈と記録**

CPU・局面集合・TT設定・ハッシュ関数・評価データを固定した、現在の環境での結果である。全てのリバーシ終盤や別CPUでの順位を保証しない。特にEgaroucidは固定したフォールバックhash23を使用し、標準のhash25設定や別シードとは検索量が変わり得る。学習済みhash23に対する比較でもない。

run/results.tsvは全生データ、run/process-output.jsonlは全コマンドと各プロセスの標準出力・標準エラー、run/summary.jsonは周別時間・中央値・時間比・ハッシュを保存する。validation.jsonはスコア・最善手・実行順・ノード数とファイルの最終照合結果である。

参考としてプロセス全体の経過時間も保存した。その10局面合計の中央値は、現deft 23.610秒、Edax 21.273秒、Egaroucid SIMD 31.897秒、Egaroucid AVX-512 31.064秒。これは起動・モデル読込・TT初期化・標準出力等を含む別指標であり、探索時間の表へ加算・混用しない。

今回、探索ソースの変更やエンジンの追加最適化は行っていない。deft-worktree.patchは測定時のHEADに対する既存の作業ツリー差分（新規のend_ordering.rsを含む）を凍結したもので、今回新しく最適化した差分ではない。deft-source-sha256.jsonと合わせ、測定した未コミットのソースを識別できる。比較前HEADからの適用と再構築の一致を確認した。

最終確認では全320コマンドのCPU 0固定、全標準エラーが空であること、TSVと出力ログの実行順一致も検査した。スクリプトの構文検査、JSON読込検査、git diff --checkにも成功した。


現在の比較ツールは [tools/bench](../../../tools/bench/README.md) に移した。Edaxの評価ファイルは `--edax-eval` で指定できる。このディレクトリのスクリプトと結果は、上記測定時の記録として保持する。
