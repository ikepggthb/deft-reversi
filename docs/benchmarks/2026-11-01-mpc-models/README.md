# MPC の統計モデルの再検討

[式の比較](../2026-11-01-mpc-formulas/README.md)では、σ の関数形だけを比べた。Edax・Egaroucid の MPC は、関数形だけでなく、平均（傾き・切片）の扱いも Deft と違う。そこで MPC の誤差モデルを次の4つの部品に分け、それぞれを入れ替えて比べた。

1. 平均の補正
2. σ が標準偏差か RMS か
3. σ の関数形
4. 閾値 t の決め方

本番の探索と MPC のパラメータは変えていない。

文中の根拠には、次の印を付ける。

- **［ソース］**：ソースコードで確かめた事実
- **［論文］**：原論文に書かれていること
- **［明言］**：開発者が理由として書いていること
- **［推論］**：数学的な推論
- **［実測］**：このデータでの測定結果

## 1. 原論文と Edax・Egaroucid の調査

### 原論文（Buro 1997, *Experiments with Multi-ProbCut and a New High-Quality Evaluation Function for Othello*）

[PDF](https://skatgame.net/mburo/ps/improve.pdf)

- ［論文］モデルは v_h = a·v_d + b + e である。e は「平均0・分散 σ² の正規分布に従う誤差」とされる。
  - a・b・σ は、石数・高さ h（2〜13）・確認の深さ d ごとに、深さ13までの枝刈りなしの探索の値から線形回帰で求める（9節）。
  - 刈る条件は v_d ≥ (Φ⁻¹(p)·σ + β − b)/a である。図7の実装でも、bound = round((t·σ + β − b)/a) と、a・b を使っている。
- ［論文］ProbCut の論文（Buro 1995）で決定係数 0.96 以上が報告されていることを、線形モデルが適している根拠に挙げている。
  - 正規分布かどうかを確かめた記述はない。
  - MPC の再帰（浅い探索も MPC 付きになる）による推定のずれは「無視する」と明記している。
- ［論文］t は対局で決めた。36石以上で 1.4、それより前で 1.0 である。確認の深さも、局面集の総探索時間が最小になるように選んだ（9節、表2）。

### Edax 4.6

- ［ソース］`eval.c` の `eval_sigma()` は、σ = a·u² + b·u + c、u = A·空き + B·深さ + C·浅い深さ である。係数はすべてのモデルで共通の定数（eval.c 734行）である。
- ［明言］`eval_sigma` のコメントには、次の2点が書かれている。
  - 統計的な調査で、αβ の精度は主に深さと手数で決まると分かったこと
  - 表の代わりに関数を使うと、内挿・外挿がしやすいこと
- ［ソース］`search_probcut()`（midgame.c 187行〜）の上側の刈りは β + t·σ、下側は α − t·σ で、傾き・切片は使わない。
  - t は 1.1・1.5・2.0・2.6・3.3 で、表示は 73・87・95・98・99% である（search.c 97行）。
  - 浅い深さは 2·⌊0.25·深さ⌋ + 偶奇で、深さのほぼ半分になる。
  - 評価関数の値（深さ0）による事前の判定がある。深さ0と浅い深さの σ の平均を使う。
  - 完全読みも、深さ = 空きマス数として同じ関数を使う。
- ［ソース］係数をどう当てはめたか、σ が残差の標準偏差か RMS かを示すスクリプトは、リポジトリにない。二次式を選んだ実験的な根拠も見当たらない。

### Egaroucid 7.8.1

- ［ソース］`multi_probcut.hpp` の `probcut_sigma()` は、u = a·石数/64 + b·浅い深さ/60 + c·深い深さ/60 の三次式である。
  - 刈る条件は β + ⌈t·σ⌉ で、傾き・切片は使わない。
  - t の表には「standard normal distribution table, two-sided test」とコメントがある（74〜99.9%）。
  - 浅い深さは、中盤で深さ/2、終盤で深さ/3（いずれも偶奇を合わせる）。
  - 評価関数の値による事前の判定（error_0 = error_search − 4）がある。
  - 完全読みでは、α・β を奇数にそろえる。
- ［ソース］データを作る `get_data_probcut_mid/end` は、次のとおりである。
  - 初期局面から乱数で打った局面を使い、1万回まわす。
  - 浅い深さも毎回乱数で選び、「深い値 − 浅い値」を記録する。
- ［ソース］当てはめの `tools/probcut/model_sigma_mid.py` と `model_sigma_end.py` は、次のとおりである。
  - `mean = 0.0` と置き、√(Σ誤差²/n)、つまり**平均を引かない RMS** を、組ごとに求める。`statistics.stdev` の行はコメントアウトされている。
  - 平均の曲面も当てはめる処理があるが、`popt_mean = [0 …]` で無効にしてある。
  - 中盤には、浅い深さ0・深い深さ30の所に `z = 3 + 12·(石数−4)/60` という人工の点を足している。
  - 当てはめは scipy の `curve_fit` である。
  - [README](https://github.com/Nyanyan/Egaroucid/tree/main/src/tools/probcut) には「データは十分な量得ることができないので、適宜ガイドとなる点を打つ」とある。
- ［明言］平均を補正しない理由と、三次式を選んだ理由は、見つからなかった。[技術解説のページ](https://www.egaroucid.nyanyan.dev/ja/technology/explanation/)の Multi-ProbCut の節は「今後丁寧に追記予定（2024/06/10）」のままである。

### まとめ

| 問い | 答え |
|---|---|
| 統計モデルの根拠 | 原論文は、線形回帰と正規分布の誤差（決定係数 0.96 が根拠）。Edax は「精度は深さと手数で決まる」「関数は内挿・外挿しやすい」とコメントしている。Egaroucid には説明がない |
| 二次式・三次式を選んだ実験的な根拠 | 両者とも見つからない。Egaroucid は、データ不足を人工の点で補っている |
| 推定しているもの | Egaroucid は、平均を引かない「深い値 − 浅い値」の RMS（ソースで確認）。Edax は不明。原論文と Deft は、回帰の残差の標準偏差 |
| 平均の補正を省く理由 | どちらも説明していない。Egaroucid は、平均の当てはめを書いたうえで無効にしている |

## 2. 部品の分解と、それぞれが成り立つ条件

刈る条件は、どの方式も「v ≥ ⌈(β − b + t·σ)/a⌉ なら上側で刈る」の形に書ける。部品は次のとおり。

| 部品 | 比べたもの |
|---|---|
| 平均 | **none**（a = 1, b = 0。Edax・Egaroucid と同じ）、**parity**（a = 1、b は「完全読みか × 浅い深さの偶奇」ごとの平均）、**shared**（a・b を特徴の1次式で表す）、**cell**（組ごとの直線。今の A） |
| σ | 選んだ平均からの残差の RMS。平均が none なら「深い値 − 浅い値」の RMS で、これが今回の **F**（none / *）に当たる。平均がある場合は残差の標準偏差と同じものになる |
| σ の関数形 | **table**（A の方法）、**quad**（Edax 型）、**cubic**（Egaroucid 型）、**loglin**（D）、**G**（E） |
| t | **normal**（正規分布の値）、**abs**（|z| の分位点。今のエンジン）、**side**（z の上側と下側を別々の分位点にする）、**fc**（エンジンと同じ整数の計算で、訓練データの誤った刈りの率が (1−p)/2 になる t を、上下別々に求める） |

### ［推論］平均を補正しない方式が成り立つ条件

平均のずれを δ = E[深い値 − 浅い値] とすると、RMS² = σ² + δ² である。

- 平均を補正しない方式は、ずれを幅に混ぜて対称に扱う。δ が組によらず小さいなら、損はほとんどない。
- δ が組ごとに違う場合（例えば浅い深さの偶奇で符号が変わる場合）は、事情が違う。δ < 0 の組では、上側の刈り（深い値が予想より低いと誤り）が危険になり、下側は慎重すぎになる。δ > 0 の組では逆になる。t を全体で1つ決めても、この片寄りは直らない。
- 平均を補正する方式は、δ を測れる範囲では幅を σ まで狭められる。ただし、測っていない所で δ が変わると、補正がそのまま偏りになる。平均を補正しない方式の偏りは真の δ そのものだが、補正する方式の偏りは「δ の変化量」になる。

## 3. 実験

### 条件

```sh
cd docs/benchmarks/2026-11-01-mpc-models
R=~/dev/deft-reversi-feature/runs/v2-pattern-lr0.3
python3 compare_models.py $R/mpc-1000/positions.tsv $R/mpc-exact25-28/positions.tsv > models.txt
python3 paired.py        $R/mpc-1000/positions.tsv $R/mpc-exact25-28/positions.tsv > paired.txt
```

- **データ**：1,000局面の測定（valid 分割、空き12〜52、深さ0〜14、空き12〜24の完全読み）と、空き25〜28の完全読み各120局面。モデルは lr 0.3・8エポック。
- **分け方**
  - 局面の盤面のハッシュで、訓練と確認を半分ずつに分けた。同じ盤面（序盤の重複が22組あった）は、必ず同じ側に入る。
  - 空き25〜28の480局面と同じ盤面は、訓練から外した（245局面）。これらの局面の中盤の値は、1,000局面のデータに含まれているためである。
- **同じ対局どうしの相関**
  - データセットは、1つの対局から各石数に1局面ずつ記録している。そのため、同じ組（空きマス数）の中に同じ対局の局面は入らない。
  - 異なる空きマス数の間では、valid 分割の約29万局から各1,000局面を選んでいるので、1局面あたり同じ対局の局面は平均約0.14個である。
  - 対局は盤面からは特定できないので、この相関は残っている。ただし、相関するのは別の組の局面どうしなので、組ごとの当てはめへの影響は小さいと考える。
- **エンジンと同じ整数の計算での確認**
  - 誤った刈り：上側は β = 深い値 + 1、下側は α = 深い値 − 1 で刈ってしまう割合。一番際どい窓での誤りである。
  - 効率：正しい刈り（β = 深い値 − k、α = 深い値 + k、k = 1〜8）が起こる割合の平均。
- 誤った刈りの率をそろえて（t: fc）、効率を比べるのが主な比較である。差の標準誤差は、局面単位で求めた（paired.txt）。

- **中盤**：平均の補正も σ の関数形も、効率をほとんど変えない（差は 0.6% 以下）。
  - 中盤で比べる深さの組（例えば深さ10と浅い深さ2）は、偶奇が同じである。浅い値と深い値に同じ向きの偏りがあり、差を取ると打ち消し合う。全体の δ は −0.4 しかない。
- **完全読み**：平均を補正しないと、効率が 85% で 4%、98% で 17% 落ちる。

  - 補正した A では、0.071〜0.079 にそろう（models.txt の偶奇別の表）。
- 偶奇のずれだけを補正する parity では、効率の差の 3〜5 割しか取り戻せない。残りは傾き（完全読みで a = 1.01〜1.05）による。点差の大きい局面ほど、a·v が v から離れるためである。

### 3.4 誤差の分布

確認用の局面で、z = 残差 / σ。

| | 歪度 | 尖度 | P(z > 2) | P(z < −2) | P(z < −3) |
|---|---:|---:|---:|---:|---:|
| 中盤、浅い深さが偶数 | −0.35 | 15.5 | 0.024 | 0.020 | 0.004 |
| 中盤、浅い深さが奇数 | −0.59 | 12.5 | 0.018 | 0.026 | 0.007 |
| 完全読み、偶数 | +0.06 | 5.1 | 0.027 | 0.025 | 0.005 |
| 完全読み、奇数 | −0.17 | 4.0 | 0.019 | 0.030 | 0.008 |
| 完全読み 25〜28 | +0.35 | 4.2 | 0.033 | 0.010 | 0.000 |

（平均は A、正規分布なら尖度 3、P(|z| > 2) = 0.023 ずつ）

- 中盤の誤差は、裾が非常に重い（尖度 12〜15）。
- 下側に片寄っている。深い値が予想より大きく下がることが多く、上側の刈りが危険になりやすい。この片寄りは、浅い深さが奇数の組で強い。
- 全体で上下別々に t を決めると、中盤 85% で上 1.34・下 1.33 と、ほぼ対称になる。片寄りは偶奇の組ごとに違うので、全体の上下の t では直らない。

### 3.5 t の決め方

A（cell / table）で、t の決め方ごとに、誤った刈りの率を比べた（上側 / 下側。想定は 85% で 0.075、98% で 0.010）。

| t | 中盤 85% | 中盤 98% | 完全読み 85% | 完全読み 98% |
|---|---|---|---|---|
| normal（修正前） | 0.041 / 0.038 | 0.0099 / 0.0087 | 0.048 / 0.046 | 0.012 / 0.009 |
| abs（今） | 0.049 / 0.046 | 0.0077 / 0.0066 | 0.052 / 0.052 | 0.008 / 0.007 |
| fc | 0.079 / 0.078 | 0.0109 / 0.0104 | 0.074 / 0.075 | 0.012 / 0.009 |

- ［推論・実測］エンジンは、刈る境目を ⌈…⌉ で整数にする。さらに「一番際どい窓（β = 深い値 + 1）での誤り」は、z < −t よりも約1石きびしい条件である。
  - そのため、z の分位点で決めた t（abs）では、85% の段の実際の誤りが名前の 0.075 ではなく 0.05 になる。同じ誤りの率で比べると、刈る量が少ない側にずれている。
- どの t にするかは、段の名前をどう定義するかの問題でもある。段をどう使うかはレベル表で調整するので、ここでの差が直接棋力に効くわけではない。
- 完全読みの値は、いつも偶数である（空きは勝った側に足す）。Egaroucid は、完全読みで α・β を奇数にそろえている（［ソース］）。Deft はこの粒度を規則に入れていない。

## 4. 判断

### Q1. 線形回帰による平均の補正は必要か

**完全読みでは必要、中盤ではほとんど要らない。**

- 中盤では、F（平均の補正なし + RMS）で十分である。誤りの率をそろえた効率の損は 0.6%。
- 完全読み（空き12〜24）では、F にすると効率が 85% で 4%、98% で 17% 落ちる。誤った刈りは、浅い深さの偶奇によって、片側だけ約1.4倍になる。原因は、完全読みの値に対する浅い値の偏りが、偶奇で符号を変えることである（−1.6 と +0.55）。
- 偶奇のずれだけを補正しても、効率の損は半分ほどしか戻らない。傾きも効いている。

### Q2. A が外挿で安定しているのは、モデルが優れているからか

**使い回しが、今回のデータの性質に合っていたからである。**

- 空き18〜24では、完全読みの σ と切片がほぼ一定である（[式の比較](../2026-11-01-mpc-formulas/README.md#考察なぜこうなったか)の考察5）。だから最後の値の使い回しが1〜4マス先で正確だった。
- 一定でなくなる所では外れる。
  - 空き25〜28では切片が変わり、+0.9 の偏りが出た。
  - 空き29以上では浅い深さが7・8になる。それでも A は、浅い深さ5・6の σ を使い回す。
- 式で外挿する方式（shared の平均、quad・G の σ）は、それよりも大きく外れた。今回のデータで最も外さないのは「測って使い回す」A だが、それは測った所の近くでしか正しくない。

### Q3. Edax・Egaroucid の関数近似を採用する理由はあるか

**今のデータでは、ない。**

- 測った範囲では、関数形による差はほとんどない。中盤では効率の差が 0.1% 以下である。完全読みでも 2% 以下で、例外は 98% の段の quad（Edax 型）の −7% だけである。
- 測っていない範囲では、二次式・三次式は慎重すぎ（空き25〜28で効率が 15% 低い）、G は刈りすぎだった。
- Edax の「関数なら外挿しやすい」という理由は、計算の手間としては正しい。しかし、外挿した値が正しいことは、このデータでは裏付けられなかった。
- Egaroucid が人工の点を足しているのは、関数の外挿を自分で制御するためで、データの根拠ではない。
- 採用する価値があるのは、関数形ではなく、Egaroucid の「乱数で選ぶ浅い深さ」のような、データの集め方の考え方である。Deft の測定も、深さ0〜14のすべての組を持っているので、同じことができる。

### Q4. A を続けるなら、どこを優先して直すか

1. **完全読みの空き25以上の規則**（切片と σ）。測った範囲の外で、偏り（+0.9）と下側の誤りの増加（0.090、想定 0.075）が確かめられた。浅い深さが7・8になる空き29以上は、まだ測っていない（5節の1）。
2. **t の定義**。いまの |z| の分位点では、エンジンの整数の計算で、実際の誤りが名前の約 2/3 になる。誤った刈りの率を直接合わせる fc にするか、今の定義のまま段の使い方で調整するかを決める。
3. **σ の関数形**は後回しでよい。測った範囲では差がない。外挿は、測る範囲を延ばすほうが確実である。

### Q5. 棋力を大きく上げるには、統計モデルと実行条件のどちらを優先するか

**実行条件を優先する。**

- 統計モデルを替えた効果は、誤りの率をそろえた効率で、中盤 0.6% 以下、完全読み 4〜17% だった。しかも、完全読みの改善は今の A ですでに取れている。
- 一方、これまでの実測では、実行条件の差のほうが大きい。
  - 準備の段の確率を変えると、完全読みのノード数が −4%〜+18% 変わった（[MPC 校正](../2026-10-31-mpc-calibration/README.md#準備の段階の-mpc-の確率)）。
  - t を変えただけで、固定レベルの時間がレベル11で +8%、レベル14で −6% 変わった（[裾の重さ](../2026-11-01-mpc-tails/README.md#自己対戦)）。
  - 表 3.5 でも、t の決め方だけで、中盤 85% の段の効率が 0.475（abs）から 0.571（fc）に動く。ただし、誤った刈りの率も 0.048 から 0.079 に上がる。
- 原論文も、t と確認の深さは対局と探索時間で決めている。
- 浅い深さの選び方（Deft は参照実装の表、Edax・Egaroucid は深さの約半分）と、評価値による事前の判定（Edax・Egaroucid にはあって、Deft にはない）は、まだ比べていない。
