# 探索中の計算再利用の試行

今回の変更前は、局所TT候補手保存までを実装した作業ソースを `/tmp/deft-reuse-before` にコピーしたもの。旧main評価モデルのDPR2変換版、旧main MPC、1スレッド、主TT 256 MiB、CPU 0固定、native release、Rust 1.99.1、AMD EPYC 9V74仮想環境で比較した。各局面は新プロセス・空のTT、前後の実行順を周ごとに逆転して5周。モデル読込と初期化は計時外、測定中のテスト・ビルド並行実行はなし。

## 再利用版（未採用）

`trial.patch` は変更前に対する次の試行差分。

- 保存済み局所TT候補 `tt_move` と今回の最善手の変数を分離。
- 候補に子の合法手を保持し、評価関数・浅い手順付け探索・再帰先で再利用。
- 合法手が一つなら手順付け評価を省略。
- 手順付けに使った評価特徴量を、最初に探索する候補の本探索で再利用。全候補に176バイトの状態を保存する方式は取っていない。

| 対象 | 変更前 | 再利用版 | 時間変化 |
|---|---:|---:|---:|
| 中盤24局面・深さ8 | 0.199232秒 | 0.207562秒 | +4.18% |
| FFO 40〜49 | 24.948270秒 | 24.983536秒 | +0.14% |

各周の局面合計の中央値。すべてCompleted、すべての前後スコアが一致した。ただし独立した正解計算ではない。中盤の悪化と終盤の改善不明確のため、合法手・特徴量の再利用版は本体に採用しなかった。計算回数が減っても、状態保持・候補データの増加などを含む実時間の改善は確認できていない。バイナリ配置や仮想CPUの変動の寄与は分離していない。

`deft-reuse-v2-*` がこの版の全測定。`deft-reuse-midgame.*` と `deft-reuse-ffo.*` は、手順付けの戻り値に評価状態を含めていた初回試行で、最終版の結果とは別。すべてのJSONにモデル・局面・バイナリのSHA-256を保存。

## 本体へ残した変更

局所TTの保存済み候補を列挙中の低mobility探索で上書きしないよう、`tt_move` を固定して保持する修正と、汎用探索で唯一手の手順付け評価を省く変更を残した。候補手を全候補の評価前に探索する変更とは別である。

| 採用版の確認 | 変更前 | 採用版 | 時間変化 |
|---|---:|---:|---:|
| 中盤24局面・深さ8 | 0.208423秒 | 0.204899秒 | -1.69% |
| FFO 40〜44 | 3.583219秒 | 3.597048秒 | +0.39% |

各5周、全実行Completed、スコアは前後一致。短時間の測定で変動もあり、これを終盤全般の高速化とは主張しない。`deft-reuse-final-*` に全データを保存。採用版でnative releaseの全52テスト（ストレス含む）、書式検査、差分検査が成功。唯一手のテストでは、探索値を保ちつつ手順付け評価が呼ばれないことを確認した。既存のAtomicU64::fetch_update非推奨警告は残る。
