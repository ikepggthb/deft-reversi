2026-10-27 評価と手順付けの合法手共有、14→13マスの評価状態更新

基準はrefactor/engine-layout、基点8ab1682の作業ツリーで、直前までのTT・5〜6マスカーネル・最終1マス最適化を含む。比較前バイナリのSHA-256はd75409b3fd8300f0688e0e9f336808c48f6c0db87c660431ac93a3c1a064dc55。[直前のソース調査](../2026-10-27-post-leaf-source-review/README.md)のうち、探索規則・評価値を変えずに削れる処理を対象にした。

**変更した処理**

通常評価はモデルのmobility項のために両者の合法手を計算する。以前の手順付けはその評価後、同じ子の現手番の合法手を再計算していた。endgame_orderingとmidgame_orderingの静的評価に相当する経路で、この合法手を共有する。

比較用に2つの方法を実装した。

- provided: 手順付け側で合法手を計算して、評価関数へ渡す。
- returned: 評価関数から評価値と計算済み合法手を組で返し、手順付けが再利用する。通常の評価APIは組の評価値だけを取り出す。

いずれもmobilityの係数・両者の合法手数・特徴量・位相・符号付き丸め・スコア制限は維持する。相手側の合法手生成もモデルの値に必要なので削除しない。深い手順付け探索全体の合法手生成をすべて共有する変更ではなく、直接評価または深さ0のordering_searchに相当する経路が対象である。

以前のordering_search深さ0も1ノードとして数えていたため、その呼出しを省いた経路でもContext::enterを呼ぶ。評価回数、中断ポーリング、厳密なノード予算を維持する。ノードを数えなくして時間だけを改善する変更ではない。

もう一つの変更は、完全読み・既定feature・ゼロ窓の親14→子13での評価状態更新の省略である。子はBoardだけの局所探索へ入るため、更新したEvalStateを使わない。広い窓の13マスは通常評価を使うので更新する。siblingで最初のゼロ窓が失敗し広い窓で再探索する場合は、その時点で元の親の状態から正しい子の状態を作る。

MPC有効時と実験用endgame-pattern-ordering有効時の14→13では更新を維持する。選択率タグ・評価状態の利用条件・中断後に未完成のTT値を保存しない条件は変えない。

**段階的な試作と生成コード**

provided.patchは合法手を引数で渡す変更のみ。provided-boundary.patchはそれに14→13の更新省略を加えた版。returned-only.patchは組で返す変更のみ。returned-boundary.patchはそれに更新省略を加えた版である。すべて今回の比較前からの累積差分で、重ねて適用するものではない。最終比較にはbase、provided-boundary、returned-boundaryを使う。

assembly-manifest.jsonと各asm.txtにバイナリのSHA-256と生成コードを保存する。最初のprovided版は、合法手共有で計算を減らす一方、汎用nodeが10804→11433バイト、ordering_searchが1453→1645バイトになった。通常評価を呼ぶ側へ合法手生成が広がるため、手順付け単体の計算削減だけで採用を判断しない。

returned-only版ではordering_searchは1453バイトに収まったが、nodeは11497バイトとなり、すべての関数が縮むわけではなかった。評価関数は従来2547バイトに対し、provided版2407バイト、returned版2536バイト。コード量は時間そのものではなく、実行時間と分けて記録する。

**正しさの検証**

新しいテストは2つ追加した。

1. 静的な手順付け経路の訪問ノード数・評価回数、およびノード上限0での中断を確認する。
2. 14マスから13マスへ進み、ゼロ窓でカットできず広い窓で再探索する局面を2つ使う。非ゼロの特徴重み・mobility・位相biasを持つモデルで、従来どおり最初から正しい評価状態を渡す探索と比較し、スコア・手順・ノード数・評価回数の一致を確認する。広い窓で実際に評価が行われることも確認する。

provided-boundaryとreturned-boundaryはそれぞれ既定機能の全61テストに成功した。ignoredの中断・並列ストレステストも含み、test-threads=1で実行した。ログはprovided-boundary-tests.log、returned-boundary-tests.logに保存した。既存のAtomicU64::fetch_updateの非推奨警告は残る。

局所TTのハッシュ、6マスTTの有無、5〜6マスの安定石カット、14以上の整数NWS化、モデルの学習係数は今回変更していない。Edax/Egaroucidとの新しい直接性能比較も行わない。今回の結果を両者を追い越した証明として扱わない。

採用版のnativeでも、手順付けは評価関数が返した合法手を使っている。returned-boundary-node.asm.txtでは0x59490のevaluate_state_and_moves呼出し後、戻り値RDXをRBXへ移し、0x59526からその合法手をPOPCNTと隅マスクで評価する。静的評価のこの経路には、従来あった合法手生成の再実行がない。中盤手順付け側も0x5914fから0x5943cへ戻り値RDXを渡して使う。

最終コード差分はfinal.patchに保存した。モデル値・手順付け点・ノード数を保った今回の変更と、今後のハッシュ・安定石カット等による探索量の変更は分けて扱う。
