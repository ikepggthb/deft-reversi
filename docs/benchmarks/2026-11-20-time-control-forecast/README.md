# 持ち時間制：次の反復の種類による予測（2026-11-20）

`Forecast` が `Progress::next`（次に実行する反復の種類）を見て、次の反復の時間を予測するように変えた。この変更を `a21b8c9`（`feature/cli-v2`）と対局させて比べた。設計は `docs/design/2026-11-18-time-management.md` に書いてある。

## 結論

- **時間切れ**：全19条件・3,667局（調整用を含む）で、どちらのビルドも0件。
- **強さ**：最終評価の9条件はどれも ±0.15石以内だった。信頼区間が0をまたがないのは GTP 2秒・1スレッドの +0.10 [+0.01, +0.18] だけで、下限は0にほぼ接している。9条件を比べた中の1つなので、改善とは判断しない。悪化した条件もない。
- **終わらない反復に捨てた時間**：次が終盤の最初のステージか完全読みなのに、hard まで使って止まった手（「捨て」と呼ぶ）が減った。GTP 20秒・1スレッドでは、総使用時間に占める割合が 5.0% から 0.5% に下がった。
- **スレッド数による予約の補正**（`5339c14`、完全読みの見積もりを `threads^0.85` で割る）：FlipSight 6秒・4スレッドで −0.33 [−0.63, −0.03] と負けたので、取り消した（`28114b1`）。
- **倍率を対局中の中央値に下げる案**（第2案）：調整用の開局で差がなく、捨てが増えたので採用しなかった。

## 捨てた時間（`DEFT_GTP_LOG`、`ratios.py --waste`）

「遷移の前で止まった手」は、最後に完了した反復のあと、次が中盤 → 終盤の最初のステージ、中盤 → 完全読み、選択的ステージ → 完全読みのどれかだった手。そのうち hard の90%以上を使った手を「hard まで使った」と数え、使用時間から最後に完了した反復の時刻を引いたものを「捨てた時間」とした。旧のログには `next` がないので、同じ空き数・同じ最後の反復で新が予定していた次の反復を使った（レベル表が同じなので、計画は同じ）。

| 条件 | スレッド | hard まで使った手 旧 → 新 | 捨てた時間の割合 旧 → 新 |
|---|---:|---|---|
| GTP 2秒 | 1 | 94 / 358（26%）→ 27 / 442（6%） | 1.9% → 0.4% |
| GTP 20秒 | 1 | 99 / 285（35%）→ 12 / 341（4%） | 5.0% → 0.5% |
| GTP 60秒 | 1 | 90 / 212（42%）→ 12 / 234（5%） | 7.8% → 0.7% |
| GTP 2秒 | 4 | 30 / 219（14%）→ 3 / 319（1%） | 2.2% → 0.1% |
| GTP 20秒 | 4 | 53 / 143（37%）→ 4 / 176（2%） | 7.1% → 0.6% |

数え方の詳細は `waste.txt`。

## 遷移の倍率（`ratios.txt`）

各反復にかかった時間（前の反復が終わってからの時間）の、直前の反復に対する比。中央値は次のとおり。

| 遷移 | 空き数 | probe 1スレッド | probe 4スレッド | 対局中 |
|---|---|---:|---:|---:|
| 中盤 → 終盤の最初のステージ | 20〜23 | 6.1 | 4.8 | 3.7 |
| | 24〜27 | 5.1 | 4.3 | 3.1 |
| | 28〜31 | 5.9 | 5.4 | 7.6 |
| 選択的ステージ → 完全読み | 20〜23 | 3.4 | 2.6 | 1.2 |
| | 24〜27 | 4.8 | 4.5 | 1.9 |
| | 28〜31 | 6.2 以上 | 4.1〜13.7 | （8局面） |
| ステージ → ステージ | 20〜31 | 0.9〜1.2 | 0.9〜1.2 | 1.1〜1.5 |
| 中盤 d → d+2 | 20〜36 | 1.8 | 1.6〜1.8 | 1.6〜2.0 |

- probe は `tools/time-control/probe`。置換表を空にして `timed_levels(60, 30s)` で探索し、20〜34空きの局面で各反復の完了時刻を記録した。1スレッドは各空き数16局面、4スレッドは5局面。棋譜は `self-play -l 8 --random 8 --seed 11` の32局。
- 対局中の値は、評価対局の GTP ログ（新旧両方）から集計した。前の手番の置換表が残っているので、終盤の倍率は probe より小さい。
- スレッド数で中央値はあまり変わらない。
- 採用した倍率は probe の中央値に合わせた（`ENTRY = max(2, 5·1.06^(空き−24))`、`EXACT = max(1, 3·1.15^(空き−22))`、ステージ間 1.25）。対局中の値に合わせた第2案は、下の「不採用」に書いた。

## 不採用にした変更

### 第2案：対局中の倍率（調整用の開局 0〜99、E コア）

`ENTRY = max(2, 3.5·1.08^(空き−22))`、`EXACT = max(0.8, 1.6·1.2^(空き−22))`、ステージ間 1.1。第1案（採用版）との対局。

| 条件 | 局数 | 石差 [95%CI] | 使用時間 第2案 / 第1案 | 捨てた時間 第2案 / 第1案 |
|---|---:|---|---|---|
| GTP 2秒 | 200 | +0.07 [−0.13, +0.26] | 1.864 / 1.846 | 1.1% / 0.6% |
| FlipSight 6秒 | 200 | +0.01 [−0.12, +0.14] | 5.565 / 5.490 | — |
| GTP 20秒 | 120 | +0.00 [−0.13, +0.13] | 18.87 / 18.66 | 1.1% / 0.7% |

時間は多く使うが、終わらない反復も増え、強さに差は見えない。

### スレッド数による予約の補正（`5339c14`、開局 1200〜1299、4スレッド）

4スレッドでは、20〜30空きの完全読みが1スレッドの約3.3倍速かった（probe、45局面の幾何平均、`4^0.86` 相当）。そこで将来の完全読みの予約を `threads^0.85` で割り、中盤に時間を回した。`0c53a14` との対局。

| 条件 | 局数 | 石差 [95%CI] | 使用時間 補正あり / なし |
|---|---:|---|---|
| GTP 2秒 | 200 | +0.03 [−0.28, +0.34] | 1.781 / 1.664 |
| FlipSight 6秒 | 200 | −0.33 [−0.63, −0.03] | 5.312 / 5.037 |

時間を多く使っても強くならず、FlipSight 6秒では区間が0の下にある。取り消した。予約を減らすと、終局近くの手番に完全読みの時間が残らなくなるのかもしれない。

## 損失の表（予備、`losses.txt`）

`tools/time-control/probe/src/bin/truth` で、20〜28空きの各16局面について全合法手の正確な値を出した。probe（1スレッド）の各反復が選んだ手の損失（最善手の値 − 選んだ手の値）と、完了時刻の中央値を並べた。

- 最後の中盤反復の平均損失は 0〜0.88石。終盤の最初のステージ（85%）で 0〜0.25石に下がる。95%/98% ではすべての空き数で0だった。
- 98%/99% → 完全読みは、24〜28空きでは時間が2〜9秒増えるのに、損失は減らない（21空きの 0.12石だけ）。
- 局面が16個しかなく、完全読みが後の手番の時間を節約する効果も入っていない。配分を決める根拠にするには、局面を増やして一局全体で計算する必要がある。
