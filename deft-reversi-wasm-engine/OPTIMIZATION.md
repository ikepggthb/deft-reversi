# WASMエンジンが速くなった理由

2026-10-30の改善について、実装の狙いと実測結果を残す。性能の基準は **FFO 40〜49を終局まで完全に解いた10問の探索時間の合計**。単問の速度や中央値では判定しない。

## 前提

8×8の盤面は、手番側と相手側それぞれ64ビットの整数（bitboard）で表す。1ビットが1マスに対応し、ビット演算で着手可能な場所や反転する石を求める。終盤の完全読みでは同様の盤面操作を大量に繰り返すため、1回あたりの処理量を減らすと、探索する手順が同じでも合計時間が短くなりうる。

今回の測定では各問の最善手・評価値・探索ノード数が新旧で一致し、10問の合計は627,213,734ノードだった。探索順や探索量を減らしたことによる改善ではなく、同じ探索を行う際の処理時間の差として観測されている。ただし、各変更が何秒を占めるかや、実行環境が異なる場合の効果までは確定していない。

## 残り1マスの反転数を専用計算にした

実装: [`src/board/last.rs`](src/board/last.rs) の `doubled_flips`。

以前は残り1マスの場合も、汎用の反転処理で8方向に相手石を伸ばし、挟めるかを調べていた。残り1マスなら他の63マスはすべて埋まっているため、着手位置から各方向を見て最初の自分の石までの間は、すべて相手の石と分かる。

そこで各マス・各方向のビットマスクをあらかじめ生成し、ビット番号が増える方向では最下位の自石、減る方向では最上位の自石を検出して、その間の反転石をまとめて求めるようにした。自石がない方向は反転しない。汎用処理の方向ごとの繰り返し伝播を避けられることが狙いで、終盤の葉に近い頻出処理のコストを下げる。

## 残り数マスの反転処理も方向マスクを使う

実装: [`src/board/last.rs`](src/board/last.rs) の `near_full_flips` と [`src/search/endgame/last_four.rs`](src/search/endgame/last_four.rs) の `flip_at`。

残り4マス以下の探索でも、各方向の最初の「相手石以外」をビット演算で探す。そこが自石なら間の相手石を反転し、空きマスや盤端なら反転しない。残り1マス専用処理と異なり、途中の空きマスを考慮する必要がある。汎用の反転処理を毎回行う代わりに、終盤のこの探索で必要な計算を直接行う。

ChromeでFFO 40〜49を完全読みした交互測定では、直前の公開版が36.182秒・34.100秒、この変更後が34.174秒・32.146秒だった。実行順は旧→新→新→旧。測定は変動するので、他の端末でも同じ短縮率になるとは限らない。[測定条件・各問の結果](../docs/benchmarks/2026-10-30-wasm-endgame-rays/README.md)

## 合法手生成の手書きWASM SIMD

実装: [`src/board/moves.rs`](src/board/moves.rs) の `wasm_simd::get_moves`。WASMの `simd128` を有効にしたビルドで使用する。

盤面の64ビットを反転したものをもう一方のSIMDレーンに入れると、元の盤面の右シフトを反転盤面の左シフトとして扱える。これにより、同じシフト量を使うWASM SIMD命令で正逆方向を2レーン同時に計算できる。ビット反転には8ビット単位の参照とバイトの並べ替えを使い、最後に結果を戻して空きマスを抽出する。

この工夫は並列処理を意図したものだが、**FFO 40〜49ではSIMD化単独の明確な高速化は確認できていない**。終盤処理のみと、それにSIMD合法手生成を加えた版のChromeでの交互測定は、終盤のみ33.420秒→組み合わせ33.430秒→組み合わせ33.201秒→終盤のみ33.324秒だった。反転や並べ替えのコストもあるため、SIMD命令を使ったこと自体を高速化の証拠とはしない。[詳細と生データ](../docs/benchmarks/2026-10-30-wasm-manual-simd/README.md)

## 試して採用しなかった案

- 汎用の石反転を手書きSIMD化し、終盤だけ従来処理に戻すなど複数の形を試した。一部の終盤局面やFFO合計で改善が安定しなかったため採用しなかった。これらの計測だけでSIMD反転全般が遅いと結論づけることはできない。
- 残り1マスの横方向を参照表で求める案は、正しさは確認できたが、FFO合計で改善を確認できなかったため採用しなかった。

## 正しさと再測定

合法手生成は10万通りの重複しないランダム盤面で従来実装と比較した。残り1マスの反転数は256万ケース、残り数マスの反転処理は10万盤面の全空きマスについて汎用処理と比較した。これらに加え、FFO各問の最善手・評価値・ノード数も照合している。

測定はChrome Web Worker、1スレッド、主TT 32 MiB、各問の前にTT初期化、時間制限なしで実施した。CPU、ブラウザー、コンパイラ、負荷や実行順により時間は変動する。変更の採否は、同一条件で旧版と新版を交互に実行し、10問合計と正解を合わせて判断する。再現手順は[最初の測定記録](../docs/benchmarks/2026-10-30-wasm-manual-simd/README.md#再現)を参照。
