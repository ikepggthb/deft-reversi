deft-reversi NNUE 評価関数 図解

この資料は、現在の deft_reversi_engine の NNUE を、機械学習に慣れていない人にも追いやすいように説明するものです。 NNUE は「盤面から少数の特徴IDを作り、そのIDに対応する重みを足し、小さなニューラルネットで点数に変換する」評価関数です。

236,358入力特徴の総数。実際に立つ特徴は一部だけです。
256 x 2手番側と相手側、2本の accumulator を作ります。
32 + 32accumulator の後ろに小さな2層の dense network があります。
-64..64最終的な評価値は石差相当のスコアに丸めます。

1. 全体像

通常のニューラルネットでは、盤面64マスすべてを毎回行列計算に入れる設計がよくあります。 この NNUE は少し違います。盤面から「今ONになっている特徴ID」だけを取り出し、その特徴IDの重みだけを足します。 これにより、入力が236,358次元あっても、毎回すべてを計算する必要がありません。

2. 盤面から何を入力するか

入力は「画像」ではなく「特徴ID」

NNUE は盤面を64個の数値としてそのまま入れるのではなく、いくつかの観点で盤面を見ます。 それぞれの観点で「この特徴がON」となったIDだけを集めます。

特徴グループ次元意味
石プレーン128own石64 + opp石64。どのマスに自分/相手の石があるか。
合法手プレーン128own合法手64 + opp合法手64。どこに打てるか。
象限空き数684象限それぞれについて、空きマス数0..16をone-hot化。
パターン236,03442個のn-tuple pattern。各セルを 空=0 / own=1 / opp=2 として3進数化。

own の石として見る視点と、opp の石として見る視点を両方作ります。
相手の石も別の入力特徴になります。
合法手も64マスのone-hot特徴として入ります。
黄色部分のような形を42個見るのがn-tuple patternです。

3. one-hot と sparse input

one-hot は「たくさんの候補の中から、該当する場所だけ1にする」表し方です。 入力全体は236,358次元ありますが、1局面でONになる特徴はその一部だけです。 そのため、実装では長い配列を全部作らず、ONになったIDのリストだけを持ちます。

左上4x4の空きが12なら、17候補のうち「12」だけON。

01...12...16

パターン

たとえば8マス pattern は 3^8 = 6561 通り。 そのうち現在の並びに対応する1つだけONになります。

[空, own, opp, 空, own, ...] → 3進コード → pattern offset + code

4. 2つの視点を作る理由

オセロの評価では「自分から見た形」と「相手から見た形」の両方が重要です。 同じ盤面でも、黒視点では黒石がown、白石がoppです。白視点では逆になります。 この実装では手番側視点と相手側視点を作り、同じ重み表でそれぞれ accumulator を作ります。

5. accumulator は「重みの足し算」

最初の層は通常の dense layer ではありません。active feature id ごとに 256個の重み があり、それを bias に足します。 これが NNUE の FT accumulator です。

acc = input_bias for id in active_feature_ids: acc += input_weights[id] acc は 256 個の int32
機械学習の見方: これは「巨大なone-hot入力に対する線形層」と同じです。 ただし one-hot の0がほとんどなので、ONの列だけを足す実装にしています。

6. dense network は何層か

accumulator の後ろには、小さなニューラルネットがあります。 FTを含めて数えるなら、構造は FT + L2 + L3 + output です。 通常の全結合層として見ると、accumulator後は 512 → 32 → 32 → 1 です。

dense_raw = bias + sum(input[i] * weight[i]) dense_out = clamp(round(dense_raw / weight_scale), 0, 4095) score_raw = output_bias + sum(last[i] * output_weight[i]) score = clamp(round(score_raw / weight_scale), -64, 64)

7. 学習では何をしているか

学習は「今の重みで予測した評価値」と「教師データの評価値」の差を小さくする作業です。 このプロジェクトの trainer は、float の重みで計算し、最後に engine 用の i16 / i32 形式に丸めて保存します。

教師データを読む

RD dataset から own bitboard、opponent bitboard、教師スコアを読みます。

盤面を特徴IDに変換

推論と同じ NnueState::from_board を使い、手番側視点と相手側視点のactive feature idsを作ります。

予測して誤差を見る

forward で評価値を出し、教師スコアとの差を Huber loss で測ります。

Adam で重みを更新

誤差が小さくなる方向に、入力重み、bias、dense層、出力層の重みを更新します。

EngineFile に保存

学習後、EvaluatorData::Nnue として engine file に保存します。推論側はこのファイルを読んで同じネットワークを使います。

8. 現在実装されていることと未実装のこと

実装済み

  • 236,358次元のNNUE入力特徴定義
  • 手番側/相手側の2視点 accumulator
  • 512 → 32 → 32 → 1 の推論
  • int16重み、int32 bias、weight_scale=4096
  • NNUE trainer と EngineFile 出力

今後の最適化候補

  • 探索中の make/unmake による差分 accumulator 更新
  • SIMD によるacc加算とdense層高速化
  • 終盤ソルバとの境界での軽量make/unmake統合
  • 重みスケールや初期値の品質調整
